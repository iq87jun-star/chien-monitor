# sorare

Sorare の大会(In-Season)に向けて、節ごとに次の処理を行います。対象の大会は `config.json` の `targets` で決めます。

| 大会 | 既定 | メモ |
|---|---|---|
| J1 Rare | 有効 | 本命。現金の賞金は上位約 12%。プラスアルファ プランで買う(`buyPlan: "plus"`) |
| J1 Limited | 有効 | 安く遊べる練習用(5 枚で数ドル)。賞金はほぼカードの欠片 |
| Jupiler Limited(ベルギー) | 有効 | ヨーロッパの練習用(5 枚で $20 以内)。現金の賞金は上位 10 位まで |
| Jupiler Rare(ベルギー) | 有効 | 最低の賞金が $15。5 枚で $100 前後 |
| NBA Limited Champion | 有効 | 節は週 2 回。現金の賞金は上位 50 位まで(最低 $25)。5 枚で $30 前後 |
| NBA Rare Champion | 無効 | 現金の賞金は上位 60 位まで(最低 $25、参加 600〜700 チーム)。5 枚で $100 前後 |

大会を足す時は、`targets` に `name`(通知の名前)・`league`(リーグ名)・`competition`(リーグの slug)・`leaderboard`(大会の slug の後半)・`rarity` を書きます。予算などは大会ごとに上書きできます。
大会ごとに 1 通ずつ Discord に送り、1 つの大会でエラーが出てもほかの大会は続けます。

### NBA(`sport: "nba"`)

- 5 枚の位置の決まりはありません。代わりに、選手のランク(GOAT=5 〜 DNP=1 の星)の合計に上限があります(Champion は 16、Contender は 11)。上限は大会のルール(`rules.averageScores.max`)から読みます。
- 得点は「節の中で一番良い 1 試合 × カードのボーナス」です。予想は、直近 10 試合の平均に、節の中の試合数に応じた上振れ(ばらつき × 係数)を足します。今のケガで欠場(OUT)なら 0、出場未定(GTD)は 0.7 倍です。
- キャプテンはありません。
- 節は週 2 回(月〜木・金〜月ごろ)あり、締切の判定は大会ごとにします。
- `autoBuy: false` の大会は、購入候補をリンク付きで通知するだけで、自動購入はしません。

1. 次の節のラインナップ(GK・DF・MF・FW・エクストラ)を選ぶ
2. Discord に送る
3. 設定があれば、そのラインナップを Sorare に登録する
4. 手持ちで 5 枚そろわない時は、購入候補を 2 つのプランで送る
   - 最安プラン: 予算 `marketBudgetUsd` 以内
   - プラスアルファプラン: 予算 `plusBudgetUsd` 以内。最安プランより予想が高い時だけ送る
   - どちらも、カードごとに購入ページへのリンクを付ける
5. 手持ちのカードから売却の検討候補を送る
   - 条件は `config.json` の `sell` で決める(`maxAge` を超える年齢、スタメン率が `minStartRate` 未満、または買値から `gainPct`% 以上の値上がり)
   - 買値は、カードの所有履歴の最後の取引額(自分が買った時の価格)を使う。パックなどで価格が無いカードは、値上がりの判定をしない
   - 出品の目安(今の最安出品から `undercutPct`% 下げた額)と、カードのページへのリンクを付ける

## 残高の範囲で広げる

追加の入金はせず、ウォレットの残高(賞金・カードの売却で増える)の範囲で自動購入します。

- 残高は Sorare のウォレットから読み、購入するたびに減らして数えます。手数料のために `trade.reserveUsd`($2)は残します。
- 残高は `targets` の上から順に使います。安い大会を上に並べています(J1 Limited → Jupiler Limited → NBA Limited → J1 Rare → Jupiler Rare)。
- 足りないカードの合計が残高に収まらない大会は、その節は見送ります(5 枚そろわない買い方はしません)。通知は節ごとに 1 回です。
- `buyPlan: "auto"` の大会(J1 Rare)は、残高が足りればプラスアルファ、足りなければ最安で買います。
- 賞金やカードの売却で残高が増えると、見送っていた大会も次の節から自動で始まります。

## 結果からの学習(`src/learn.js`、記録は `state/learn.json`)

節が終わるたびに記録し、次の節の判断に使います。

- **入賞ライン**: 各大会で賞金(現金)が出る最後の順位と、その順位の点数を記録します。出ていない大会も記録します。目安は直近 5 節の中央値です。
- **届く見込み**: 通知に「入賞ライン 目安 ○点 / 予想 ○点(○%)」を出します。記録が 2 節以上あり、予想が目安の 8 割に届かない大会はカードを買わず、残高を届きそうな大会に回します(`learn.skipBelowReach`)。手持ちで組める大会は、そのまま登録します。
- **予想の補正(サッカー)**: 予想した上位 60 人の予想点を記録し、節が終わったら実際の点数と比べます。ポジションごとの「実際 ÷ 予想」の中央値で、次から予想を補正します。記録が少ないうちは 1 倍に近く、0.7〜1.3 倍に収めます。
- **売り時**: 手持ちカードの最安出品を毎回記録します。買値から上がった後に最高値から 10% 下がり始め、まだ買値から +10% 以上ある時に売ります(`learn.sellTiming`)。これまでの売却条件(年齢・スタメン率・+30%)にも、そのまま当てはめます。

記録は GitHub Actions のキャッシュに残すので、7 日以上どの実行もキャッシュを使わないと消えます(3 時間ごとに動くので、ふつうは消えません)。

## 節の結果の通知

節が終わって順位と賞金が確定すると(Sorare の節の状態が `closed`)、その後の最初の定期実行で、大会ごとの結果を Discord に 1 回だけ送ります。送る内容は、順位と参加チーム数、合計点、選手ごとの点数、賞金(カードを含む)です。サッカーと NBA で別々に送ります。送ったことは `state/done.json` に `result:節の slug` として記録します。

## 入れ替え(`config.json` の `swap`)

値上がりしたカードを売り、似た働きをする安い選手のカードに替えます。自動売買が有効な時は自動で行い、それ以外は「入れ替え予定」を通知します。

- 売る側: 買値から `gainPct`%(20)以上、今の最安出品が上がっていて、買ってから `trade.minHoldDays` 日を過ぎたカード。
- 代わり: 次の条件をすべて満たす選手です。
  - 手持ちに無い。
  - 同じポジションである。NBA は位置の決まりが無いので、代わりに星の数が売る側以下であること。
  - ケガ・出場停止が無い。
  - 移籍してから `newJoinDays` 日(30)以上たっている。
  - 予想点が売る側の `minProjRatio` 倍(0.9)以上。
  - 価格が売る側の最安出品の `maxPriceRatio` 倍(0.6)以下。
- 手元に残る額 = 売値 ×(1 − `feePct`%(5))− 代わりの価格。これが `minProfitUsd`($1)以上のものだけ、得の大きい順に選びます。
- 先に代わりを買い、買えた時だけ値上がりしたカードを出品します(出品はすぐ売れるとは限らないので、今節の 5 枚を欠かさないため)。代わりが買えなければ、入れ替えはしません。
- 1 枚の上限・週の上限・買値より安く売らない(`trade`)の決まりは、ここでも守ります。

ケガ・出場停止・移籍は、Sorare のデータ(`activeInjuries`・`activeSuspensions`・`memberships`)から読みます。予想点にも効かせていて、欠場・出場停止なら 0、出場が微妙(doubtful など)なら 0.7 倍です。

## 自動売買(`src/trade.js`)

購入候補の自動購入と、売却候補の自動出品ができます。**既定は試し運転**で、「購入予定・出品予定」を通知するだけです。
実際に売買するのは、Variable `SORARE_TRADE=true` と Secret `SORARE_PRIVATE_KEY`(Sorare のウォレットの秘密鍵)の両方がある時だけです。

安全策(`config.json` の `trade`):

| 設定 | 既定 | 内容 |
|---|---|---|
| `buyPlan` | `cheap` | 買うプラン(`cheap` = 最安、`plus` = プラスアルファ)。大会ごとに `targets` の `buyPlan` で上書きできる |
| `perCardMaxUsd` | 40 | 1 枚の上限。超えるカードは買わない |
| `weeklyMaxUsd` | 250 | 直近 7 日の購入額の上限(全大会の合計)。これまでの購入額は所有履歴から数える |
| `minHoldDays` | 14 | 買ってからこの日数は売らない |
| `neverBelowCost` | true | 買値より安くは出品しない |
| `currency` | `WEI` | 決済と出品の通貨。`WEI` = ETH ウォレット、`USD`・`EUR` = キャッシュウォレット(キャッシュウォレットはパスポートでの本人確認が必要) |

ほかに、次の場合も売買しません。

- 買う直前に価格を読み直し、提案の時より高くなっていたら買わない。
- 手持ちにある選手は買わない。
- 今節のラインナップに入れたカード、出品中のカードは出品しない。
- 出品した後に出品額を読み直し、想定と違ったら警告を送る(アプリで取り消してください)。
- 買ってそろった時は、同じ実行の中でラインナップを組んで登録する(`SORARE_SUBMIT` が `false` でない時)。

止めたい時は Variable `SORARE_TRADE` を消します。止めた後は、試し運転(通知だけ)に戻ります。

ETH ウォレットで売買する時の注意:

- 上限(`perCardMaxUsd`・`weeklyMaxUsd`)は USD のままです。ETH 建ての価格は、Sorare の換算レート(`config.exchangeRate`)で USD にして比べます。
- 出品額は USD の目安を ETH(wei)に換算して出します。Sorare の「受け取り方法」は Crypto only か Cash and Crypto にしておいてください。
- ETH ウォレットに ETH が無いと購入は失敗します(通知に理由が出ます)。
- 売り手が受け取る通貨を選べるので、ユーロや Solana(LAMPORT)でしか受け取らない出品は ETH では買えません。ログインしている時は、購入候補の価格とリンクを「`currency` で買える出品の中の最安」にします。
- `SORARE_PRIVATE_KEY` は、Sorare のウォレット設定から書き出した秘密鍵(0x + 64 桁の Ethereum の鍵)です。署名の前に、鍵から作ったアドレスが Sorare の承認の送り手(senderAddress)と一致するか確かめます。違う時は売買せず、通知に理由が出ます。

注意:

- 署名は Sorare の公式の例(github.com/sorare/api の examples)と同じ作り方です(`src/sign.js`)。ETH の支払いは Base(Ethereum の鍵、viem)、カードの受け渡しは Solana(Ethereum の鍵から SLIP-0010 で作る鍵、@solana/kit)で署名します。旧来の StarkEx・キャッシュウォレット(Mangopay)の承認が来た時は、署名せずに止まります。
- API への入力の形は、エラーメッセージで確かめただけです。実際の売買はアカウントでしか試せないので、最初の数回は試し運転の通知と、アプリの取引履歴を照らし合わせてください。
- 秘密鍵が漏れると、カードとウォレットの資産をすべて失う恐れがあります。GitHub の Secrets 以外には置かないでください。
- 自動売買が Sorare の利用規約に合っているかは、ご自身で確認してください。

## 動く場所

- GitHub Actions(`.github/workflows/sorare.yml`)だけで動きます。自宅 PC や VPS は使いません。
- リポジトリには書き込みません。
- ほかのブランチ(VPS が配備に使う `claude/prop-trading-new-methods-a8y3l1` や `claude/zaption-check-m776m7` など)、ほかのワークフローには触れません。
- 定期実行は 3 時間ごとです(GitHub の定期実行は数時間遅れることがあるため)。大会ごとに、節の開始(締切)が `runWithinHours`(12)時間以内になった最初の実行で処理します。その節に大会が無い時は、何もせず終わります。
- 済んだ大会は GitHub Actions のキャッシュ(`sorare/state/done.json`)に記録し、同じ節では 2 回目から何もしません(通知も 1 回)。手持ちで 5 枚そろわなかった時だけは済みにせず、締切前の次の実行でもう一度動きます(自動購入なら買い直し、アプリで買った後なら組んで登録)。手動実行(force)は記録に関係なく動きます。
- GitHub の定期実行は既定ブランチ(main)にある時だけ動きます。

## 選び方(`src/model.js`)

- 予想スコア = L15(直近15試合の平均スコア)× 出場の確実さ × 相手の補正
  - 出場の確実さは、直近10試合で60分以上出た割合から計算します。
  - 相手の補正は、守備の選手には相手チームの得点の少なさ、攻撃の選手には相手チームの失点の多さを使います。どちらも直近10試合の成績から出します。
- 同じクラブの選手は 2 人まで(`config.json` の `maxPerClub`)です。
- キャプテンは、予想スコアが一番高い選手にします。
- 予想にはボーナスを入れていません。目安で、結果を保証するものではありません。

ログインの有無で、選ぶ対象が変わります。

- **ログインあり**: 手持ちの `seasonYear` 年の、その大会のランク(`rarity`)のカードのうち、その大会のリーグの選手から選びます。
- **ログインなし**、または手持ちで 5 枚そろわない時: 市場の最安出品から、購入候補を 2 つのプランで提案します。

## 設定

Secrets(リポジトリの Settings → Secrets and variables → Actions):

| 名前 | 内容 |
|---|---|
| `SORARE_DISCORD_WEBHOOK` | 通知先の Discord ウェブフック URL |
| `SORARE_EMAIL` / `SORARE_PASSWORD` | Sorare のログイン情報 |
| `SORARE_OTP_SECRET` | 2段階認証の秘密鍵(base32)。認証アプリに登録した時の文字列で、2段階認証を使っていなければ不要 |
| `SORARE_API_KEY` | 任意。Sorare の API キーで、API の利用上限が上がる |
| `SORARE_PRIVATE_KEY` | 自動売買をする時だけ。Sorare のウォレットの秘密鍵 |

Variables:

- `SORARE_SUBMIT`: 既定(未設定)でラインナップを実際に登録します。`false` にすると提案の通知だけです。
- `SORARE_TRADE` を `true` にすると、自動購入・自動出品を実際に行います。未設定なら予定の通知だけです。

## 最初の確認手順

1. `SORARE_SUBMIT=false` にして、Actions の sorare を手動実行(force)します。Discord に届く提案と手持ちカードの人数が正しいか確認します。
2. 問題なければ `SORARE_SUBMIT` を消して手動実行し、アプリで登録されたラインナップを確認します。特に次の 2 点を見てください。
   - ポジションの並び
   - キャプテン

ラインナップ登録(`createOrUpdateSo5Lineup`)と手持ちカードの取得は、ログインしないと試せません。入力の形は API のエラーメッセージで確かめただけなので、最初の 1 回は必ずアプリで確認してください。

## 認証アプリを失くした時

Actions の sorare を手動実行する時に「otp」にチェックすると、`SORARE_OTP_SECRET` から今の 6 桁コードと次の 2 回分を作って Discord に送ります(ラインナップの処理は動きません)。
メッセージは約 2 分後に消えます。秘密鍵そのものは出さず、ログにもコードは出しません。
そのコードで Sorare にログインしたら、2 段階認証を設定し直して、新しい秘密鍵で `SORARE_OTP_SECRET` を上書きしてください。

## 手元での実行

```
cd sorare
npm ci
npm test
SORARE_FORCE=1 node run.js   # 未ログインの提案(全選手を取得するので10〜15分)
```

自動化ツールの利用が Sorare の利用規約に合っているかは、ご自身で確認してください。
