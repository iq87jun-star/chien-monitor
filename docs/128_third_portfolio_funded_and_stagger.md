## 1. 資金化後モード(案1) — どの口座が受かったら何に切り替えるか

### 発動ルール(事前固定)

| 順番 | 資金化した口座 | 適用 | 根拠 |
|---|---|---|---|
| **1口座目** | どれでも | **PD保守−6%**: `Chien_PortfolioD_AllInOne_PROP` + `pd_funded_conserv.set` | **Drive確定**が唯一これ: 年失格0.2% / 年率7.0% / $100k・分配95%・¥155で手取り≈¥86k/月(docs/76 §3) |
| **2口座目以降** | どれでも | **R4+G3生存 @0.68x**: `【資金化後】季節R4G3_生存068倍.mq5`(挿すだけ) or 本体+`seasonal_r4g3_funded_068.set` | docs/110 パネルA(Yahoo近似): 平均月利+1.13% / **年率+14.2% / Sharpe 2.21 / maxDD−2.9%** / 10.5年でガード非接触。ただし**R4はデモ未了**のため、R4G3チャレンジ版のデモ採点(docs/103)が分布内であることが前提条件 |
| 迷ったら | — | PD保守−6% | 確定値(Drive)>近似値(Yahoo)の原則 |

- 0.68xが「攻めていない」ように見えても上げない: 0.68x=**過去10.5年で日次−4%/月中−8%を
  一度も踏まない上限**(docs/110)。資金化口座の失格は掛金でなく**収入源の喪失**なので、
  期待手取り最大化ではなく生存最大化が正しい(docs/76 §3: 保守−6%の期待手取りは攻め設定と大差ない)。
- 利益ロック(+7/+7.5)は**資金化後OFF**(通過目標が存在しない)。出金はdocs/49の定石で手動。
  ガード(日次−4%/フロア−8%)と通知はそのまま。

### 切替手順(5分)

1. チャレンジ口座がPASS_LOCK(+7.5%全決済・docs/100)→ファーム審査→資金化口座の資格情報を受領
2. 資金化口座のチャートに上記EAをドロップ(または.set適用)
3. **`InpBaselineReset=true` で1回だけ基準残高を取り直す**(→falseへ戻す)。以後ガード/通知の基準が資金化後残高になる
4. 初日に確認: ロットが従来の約1/2〜1/3になっていること(0.68x/1.5x≈0.45)・利益ロックOFF表示
5. 月末: docs/103ハーネスで採点し、docs/98に転記(チャレンジ口座と同じ規律)

## 2. 時差複線ルール(案3) — 常にフェーズ違いの口座を並走させる

**目的**: 収入の平滑化。チャレンジ(掛金→回収まで中央3ヶ月)と資金化(毎月出金)の位相をずらし、
「全口座が同時に審査中で収入ゼロ」の期間を構造的に無くす(docs/77-78の複線化を規則化)。

### トリガー(事前固定・裁量を挟まない)

| トリガー | アクション |
|---|---|
| **T1**: 走行中チャレンジがPASS_LOCK | その週のうちに**次のチャレンジ口座を購入**(原資=通過で確定した返金/初回出金)。構成=R4+G3 @1.5x(`seasonal_r4_g3_median3.set`: 中央3ヶ月・通過95%・失格5〜8%, docs/111) |
| **T2**: チャレンジが失格 | **1週間の冷却後**に同構成で再purchase(倍率を上げるリベンジ変更は禁止)。失格がdocs/98の想定分布外なら購入前にレジーム監視(docs/102)を確認 |
| **T3**: FN枠($200k×2+$100k)満杯 | FTMO側で追加。FTMOも満杯なら購入せず待機(**業者を新規開拓しない** — Blueberry没収の教訓, docs/99) |
| **T4**: 資金化口座が2つ以上 | 新規チャレンジ購入を停止し、以後は資金化口座の運用に集中(口座数より生存年数が収入を決める, docs/57/78) |

## 3. 正直な開示(この構成で検証していないこと)

1. **R4G3生存モードの数字はYahoo日足近似**(PD保守だけがDrive確定)。だから1口座目はPD保守に固定した。
2. **時差複線の分散効果は機序的な主張であり統計値ではない**: 全口座が同じ5エッジに乗る以上、
   ドローダウン月は同時に来る(docs/52: 同時マイナス月15%が下限)。平滑化されるのは
   「フェーズの位相」(=審査中/出金中のミックス)であって「リターンの相関」ではない。
3. 0.68x/保守−6%の「ガード非接触」は過去分布の話。2024/8/5型を超えるショックでは
   日次ガードの執行ギャップで超過し得る(docs/110 ⚠と同じ)。
4. 本docはEAロジックを一切変更していない(既定値のみ)。従ってバックテスト再実行義務なし
   (docs/99 規律: バックテストを伴う変更のみゲート必須)。
