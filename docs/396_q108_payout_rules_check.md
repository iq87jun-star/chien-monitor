## 4. 判定
1. **Fintokei(パール・ルビー・トパーズ)と FN 2-Step(14074882・14166201)は MC の前提(月次・超過分のみ・静的床・80%)がそのまま成立。** 出金規則(毎月 1 日・基準残高 × 1.20 超過分の半分・docs/382)は変更しない。
2. **FTMO 2-Step 本口座(50k × 2・宝くじ)は手順が違う**: 「超過分の半分だけ出金」は請求画面にはなく、Reward 請求で全利益が分配される。同じ残高を保つには取り分をロールオーバーする(毎月 1 日に請求、取り分のうち「基準残高 × 1.20 + 超過分の半分 − 額面」をロール、残りを受け取る)。ロール後の床の基準(E2 か E3 か)で成否が決まるので **FTMO に確認してから**(§5)。確認までは現行どおり(請求せず緩衝を積む = 床は額面 −10% のまま、docs/202 の P0 と同じ)。
3. **FTMO 1-Step は MC(portfolio_sim)の床の扱いが誤り**(資金化後も静的)。規約はトレーリング + 出金で全リセット・ロール不可なので、最適方針は「保持 20%」ではなく「毎サイクル全額 Reward」(C/D)、倍率は資金化後 ×3.125 では 1 年失格 40%。**docs/382 §4 の『1-Step 資金化後は残し 20% を必ず守る』は撤回**(トレーリング床では保持は緩衝にならない)。資金化後の倍率は MC を直してから再決定(現在は評価中・EA9 の資金化後入力はまだ使っていないので運用への影響なし)。
4. FN Instant(11988011)は分配 70%(Tier 1〜2)と建値ロック床の 2 点で MC が楽観。口座が小さい(¥316 万)ので全体の月収への影響は小さいが、月次集計(monthly_scoring)の「期待」との差の原因になる。
5. FN 2-Step の On-Demand Performance Reward(+2% 成長・最良日 ≤ 40% で 90%)は Mon4/Hold のように利益が日に分散する構成なら満たしやすく、分配 +10pt(出金 +12.5%)。14074882 の次回請求で選べるか確認する価値がある(docs/370 §5 B の「分配アドオン」より安い可能性)。
6. なぜ偽陽性でないか: 規約は公式ヘルプの文言を直接引用し、計算は同じ乱数・同じ帳簿で床の式だけを変えた差分。1-Step の 9% → 40% は床の定義差そのもので、コスト感度・標本誤差の問題ではない。

- **FTMO への確認(1 通・ユーザー承認後に送る)**: ① 2-Step で Reward の一部だけを受け取り残りを同一口座に残せるか、② ロールオーバーした場合、次口座の Maximum Loss の基準は元の Initial Simulated Capital か、ロール分を含む新残高か。②が「元の額面」なら月次ロール運用(§4-2)に切替、「新残高」なら FTMO 2-Step は「請求しない → 緩衝が 20% を超えた月に超過分だけ…」ができないので、年 1〜2 回の全額請求 + 低倍率(Q86 の固定 ×3.3 相当)を再計算する。
- **FN サポートへの追加質問(11/6 のリマインドに 1 行追加)**: Stellar 2-Step の Performance Reward は全額のみか任意額か。On-Demand Performance Reward(90%)は既存の本口座 14074882 で請求時に選べるか。
