# 153.【事故記録+恒久対策】GER30サイズ10倍事故(2026-07-13)と v1.32 二重チェック

## 1. 事象(タイムライン・実測)

- 2026-07-13(月)、FN100k #14074882 で PD間引き版(デモ未了・ユーザー判断で当日投入)が稼働開始。
- 14UTC枠のE-Monで **GER30 buy 0.74/0.76ロット×2枚**(2インスタンス起動によるスロット重複も併発)。
  SL=24,918(203pt)→ **1枚あたりSL到達で約$1,710 = 設計値$182(perShot 0.182%)の約9.4倍**。
- 同日DAX下落で含み損 −$1,840(2枚計)。equityは一時101,960(日次−3%警告)。
  日次ガード(−4%)とSLにより下限は限定されていた(口座喪失リスクはなし)。
- NDX100(0.06)/SPX500(0.48)の同時刻レッグは**設計どおりのサイズ** → GER30固有。

## 2. 根本原因

`LotsFor()` が **SYMBOL_TRADE_TICK_VALUE(ブローカー申告値)を単独で信頼**していた。
FNサーバーのGER30はこの申告値が実損益(実測$11.4/pt/lot)と**約10倍乖離**しており、
ロットが10倍に算出された。EAのリスク計算式(perShot=週次÷ショット数)は正常動作を確認済み
(ログに perShot=0.182% が印字されている)。

## 3. 恒久対策(v1.32・実装済み)

`MoneyPerUnit()`: ①tick値経路(TICK_VALUE/TICK_SIZE)と ②損益計算エンジン経路
(`OrderCalcProfit` で1ロット×価格0.1%動かした損益)の**2経路で独立見積り、大きい方
(=ロットが小さくなる保守側)を採用**。乖離1.5倍超で `[SIZE SANITY]` 警告をログ。
適用: `Chien_PortfolioD_Prop3` v1.32 / ワンクリック版(#14074882用)。

## 5. 教訓(恒久規則に追加)

1. **ブローカー申告メタデータは検証対象**(価格データと同じ扱い)。サイズ計算は必ず2経路化。
2. デモ関門を飛ばす場合、初回スロットの**エントリーログのロット数を必ず即日確認**する
   (今回はユーザーの「サイズが大きくないか」という観察が検知手段だった)。
3. 複数チャートへの多重アタッチはスロット重複を生む(1チャート1EA、docs/53 §5の再確認)。
4. 発現しなかった月(7月の季節EA)は「バグがない」証明にならない — 横展開表(§4)で管理する。
