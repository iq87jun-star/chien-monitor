## 1. 検証の位置づけ

- **ペーパー検証**(実弾なし)。目的は docs/29 準用の「BT分布との整合確認」と運用規律の実地確認。
- 期間: **3ヶ月**(2026-08 / 09 / 10 の月次サイクル3回)。
- 検証中のロジック変更・裁量介入は禁止(docs/192 の凍結を維持)。介入した月は「逸脱」として記録。

## 2. 毎月の手順(所要 ~10分)

1. **毎月最初の3営業日以内**に edge24_signal ノートブックを「すべて実行」
2. 出力の「売り/買い」を記録(ペーパーなので発注はなし。IB紙口座を使う場合はそのまま発注)
3. 出力される「前月の実測(戦略/ベンチ/超過/累計超過)」を確認
4. ログは Drive の forex_ml/results/edge24_forward_log.json に自動保存(手作業なし)

## 3. 中止基準(事前定義)

| # | 条件 | 処置 |
|---|---|---|
| S1 | 累計超過 ≤ **−15%**(スクリプトが自動警告) | 検証中止。失敗として docs に記録 |
| S2 | 実行忘れ・逸脱が **2回** | 検証無効(規律不成立)。再スタートは新カード起票から |
| S3 | データ取得不能が1ヶ月以上継続 | 保留(期間延長)。ロジック変更はしない |

## 4. 3ヶ月後の合否判定(docs/29 準用・事前固定)

- **合格**: 3ヶ月の月次超過が BT分布(docs/193: 月次超過 μ≈+0.59%/σ≈9%/月次勝率54%)と
  矛盾しない(3ヶ月累計超過が BT分布の下側5%タイル以上)かつ 逸脱ゼロ。
- 合格後の扱い: 実弾移行の判断(サイズ設計=docs/193 §2 の警戒点: 暴落時−25%許容額から逆算。
  モメンタム・クラッシュ用の縮小規則の設計はこの時点で別途事前登録)。
- 不合格: 記録して終了。edge24 の再挑戦は新しい事前登録から。
