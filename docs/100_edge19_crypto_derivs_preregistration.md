## 1. 凍結ルール(実行前に全て固定・スキャンなし)

- **主資産**: BTCUSDT(判定対象)。**ETHUSDT は確認用**(方向一致のみ見る・ゲート外)。
- **執行モデル**: シグナルは日次 00:00 UTC 境界で確定(資金調達率=当日までに支払済の直近9回、
  DVOL=前日終値)→ **翌日の spot close-to-close リターン**を獲得。ルックアヘッドなし。
- **コスト(基本)**: ポジション変更時に片道 10bp(往復20bp, プロップCFDのBTCUSD実勢)。
  保有コスト基本 0%/年(FundedNextスワップフリー)。
- **仮説(N=4, 方向・閾値とも固定)**:

| ID | シグナル(3日=直近9回の平均資金調達率 F3d, DVOL=日次終値) | ポジション | 機構 |
|---|---|---|---|
| **H19a FUND-CONTRA-L** | F3d < 0 | 翌日 LONG | 負ファンディング=ショート過密/投げ売り後の需給リバウンド |
| **H19b FUND-CROWD-S** | F3d > +0.05%/8h(年率≈+55%) | 翌日 SHORT | ロング過密の巻き戻し(スクイーズ後のリバーサル) |
| **H19c VRP-L** | DVOL − RV30 > +10pt(RV30=30日実現ボラ年率%) | 翌日 LONG | 分散リスクプレミアムが厚い局面の保有対価 |
| **H19d IVSPIKE-L** | DVOL が5日前比 +15pt 以上上昇 | 翌日から5日 LONG | パニックIVスパイクの平均回帰(VIX類推の独立検定) |

- 閾値(0 / +0.05% / +10pt / +15pt・保有5日)は本doc固定値であり、**いかなるスキャン・
  グリッドも行わない**。変更した場合は本批次全体を無効とする。

## 2. 採点ゲート(docs/80 §5 標準・全て通過で STRONG-LEAD)

- **G-dir**: 基本コストで net 総リターン > 0
- **G-p**: **ドリフト保存プラセボ**順列p ≤ 0.05(同方向・ON日数保存のランダム配置, 2000draw)。
  Bonferroni(N=4)の正式ライン **α=0.0125** も併記し、超えたら格を1段下げる。
- **G-split**: データ期間を中央で2分割し両半で符号+(pre-2016が存在しないための代替・必須)
- **G-cost**: 2×コスト(往復40bp)で net > 0
- **G-hold**: 保有コスト15%/年(クリプトCFDスワップ相当)で net > 0
- **G-beta**: 超過 = net − (ON比率 × 同期間B&H) > 0(ベータの言い換え排除・E6/F2の再発防止)
- **G-dd**: レバ1のmaxDD ≥ −20%(プロップ配分はEA化時に別途校正)

**判定(事前固定)**: 全ゲート通過=**STRONG-LEAD** / G-p(α=0.05)含む過半通過=**LEAD** /
G-dir+p≤0.10のみ=参考 / 他=**REJECT**。
本批次は履歴が短い(funding 6.8年・DVOL 5.2年)ため、**全通過でもADOPTにはしない**。
昇格はE5と同じ「デモ前進検証+別ソース(Bybit/OKX)再現」のみ(docs/86 §4の規律)。

## 3. 合格した場合の扱い(事前固定)

- STRONG-LEAD → `Chien_Crypto_Derivs_EA.mq5`(**デモ専用ラベル**・BTCUSD・日次判定・
  Magic分離・日次−4%/フロア−8%ガード)+ docs/102 デプロイカード。シグナル値(資金調達率/DVOL)は
  EAでは**手動input更新 or WebRequest**とし、実装方式はEA設計時に決める。
- LEAD → EA化せず docs/98 のフォワード監視候補に記載のみ。
- REJECT → 正直に閉鎖。**同データでの閾値変更・再検定はしない**。
