# 386.【Q100・工学・セル 0】建て損ね検知の自動化 — 予定表を deploy_manifest + EA 既定入力から生成し、毎朝のダイジェストで前週/今週の建て損ねと**二重建て**を 1 行で報告。**初回照合で FN 14074882 が 10/19 以降、毎ショットを 2 本ずつ建てている(同量・7〜10 秒差)ことを検出 = 名目が設計の 2 倍**
> docs/322 Q100(order 18)。2026-10-29(平日夕の定例)。`research/forward/exec_schedule.py`(新規)・`research/forward/exec_gap.py`(2026-10 以降の予定本数を生成に置換、それ以前は手書き SCHEDULE を履歴として維持)。セル 0(工学)。累積セル 10,060 のまま。配備・manifest・EA は変更していない。

## 1. 仕組み
- 予定: `ops/config/deploy_manifest.json` の apply=true 口座 → ensure の .mq5 から既定入力(`InpMonLegs` / `InpMonHoursUTC` / `InpJpHolidayMondays` / `InpAuNzHolidayMondays` / `InpMonSkipDates` / `InpSessEnable` / `InpSessLegs` / `InpSessDaysUTC` / `InpSessSkipDates` / `InpRollRates` / `InpRollMinCarryPp`)を正規表現で読む。Mon FX レグ = 月曜 × ショット数(JPY レグは日本の祝日月曜、AUD/NZD レグは豪 NZ の祝日月曜で 0)、Mon 指数レグ = 月曜 × 1(NYSE 休場で 0)、Roll = 指定曜日 × 門を通るレグ(現行の金利表では USDJPY / GBPJPY / AUDJPY の 3 本)。Hold・GER40 ブレイク・v4 は予定本数なし。
- 実績: `ops_inbox/<口座>/positions.csv` + `open_positions.csv` の open_time(サーバ EET → UTC)と comment(`RF(I)Mon_<銘柄>_h<時>`・`RFRoll_`)。同じ(口座・族・銘柄・日・時刻タグ)の複数行は 1 本(分割約定)。
- 二重建ての疑い: 同じキーに **建て時刻が 2 秒以上離れた同量の行が 2 本以上**(分割約定は同秒・量が違う)。
- 出力 1 行: 「建て損ね なし(予定 N 本・実 N 本)」/「建て損ね: 口座 族 銘柄 日 予定 n 実 m; …」+「⚠二重建ての疑い: 口座 k ショット(例 …)」。既定の週 = 今週(月曜の朝は前週)。
- 制限: 予定表は**現在の** manifest を過去にも当てるので、EA を切り替えた週より前は偽の建て損ねが出る(例: 10/5 の 1-Step EURJPY/USDJPY は 10/12 に追加されたレグ)。

## 3. 判定: FN 14074882 の二重建て(2026-10-19 から)
- 10/5 までは各ショット 1 本(0.33 / 0.59 lot)。10/19・10/26 は全ショットが同量 2 本・7〜10 秒差・決済も同時刻。EA のログ(エージェントが読む chien 端末)には ENTRY が 1 本分しか無い → **別の端末(MQL5 VPS の停止漏れ、または自宅 PC 上の別 MT5)で同じ EA が動いている**可能性が最も高い(VPS 停止 10/17 直後の週から始まっている)。
- 影響: Mon3 の名目が設計 ×4 → 実質 ×8。Hold XAU は Magic 共有で 1 本のまま。14074882 は equity −7%(失格 −10%)で、月曜の悪い日が 2 倍で来る。
- 次の月曜 11/2 は日本の祝日(JPY レグ全停止)なので、次に影響が出るのは **11/9**。それまでに止める。
- 他口座: 9/28・8/17 の重複は移行日の単発(既知)。現在は 14074882 のみ。
