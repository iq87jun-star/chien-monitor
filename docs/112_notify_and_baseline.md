# 112. プッシュ通知(Even G2ミラー)と基準残高の自動永続化 — Seasonal v1.40 / R4G3_Prop v1.10

> ユーザー依頼「手決済の参考値・参考値到達・エントリーのタイミングでスマートグラスEven G2に通知」
> 「残高の自動反映」。両EA(Chien_Seasonal_Top_EA v1.40 / Chien_Seasonal_R4G3_Prop v1.10)に実装。

## 1. 通知の経路(カスタム開発なしの標準機能チェーン)

```
EA(SendNotification) → MT5モバイルアプリ(スマホ) → スマホの通知 → Even Realitiesアプリの
通知ミラーリング → Even G2 のディスプレイ
```

### セットアップ(1回だけ)
1. スマホに **MT5アプリ**を入れ、設定→チャット・メッセージで **MetaQuotes ID** を確認
2. PC側MT5: ツール→オプション→**通知タブ** → 「プッシュ通知を有効にする」+ MetaQuotes ID を入力 → 「テスト」
3. **Even Realitiesアプリ**: 通知(Notifications)設定で **MetaTrader 5 を許可リストに追加**
4. EA側は `InpNotifyEnable=true`(既定ON)。テスターでは自動無効。

## 2. 通知されるイベント(タイマー1回=1通に集約・250字で切詰め)

| イベント | 既定 | 内容 |
|---|---|---|
| **エントリー** | ON(`InpNotifyEntries`) | `IN <タグ> <銘柄> <ロット>`(G3 FOMCエントリー含む) |
| **手決済の参考値** | +6.0%(`InpNotifyRefPct`) | equityが参考値到達で1回通知(−0.5%離れたら再武装)。「ARM=+7%/LOCK=+7.5%が自動処理」の注意書き付き=**基本は手を出さずロックに任せる**設計 |
| **参考値を踏んだ(ARM)** | +7.0% | 新規停止の通知(手決済参考: +7.5%で自動全決済) |
| **PASS_LOCK** | +7.5% | 全決済・通過確定処理の通知 |
| 日次警告 | −3.0%(`InpNotifyDayWarnPct`) | ガード−4%の手前で1日1回 |
| DAILY_STOP / FLOOR | ガード発動時 | 即時送出 |

- 送出は即時(ガード系)+最大60秒遅延(エントリー系=次タイマーで集約送出)。
- SendNotification失敗時はエラーコードをログに出す(MetaQuotes ID未設定が典型)。

## 3. 基準残高の自動反映(`InpInitialBalance=0` が安全になった)

v1.30まで: 自動取得=「アタッチ時点の残高」→ フェーズ途中の再アタッチでガード/ロック基準がズレる問題
(docs/100 §1の注意)。v1.40で解決:

- 初回アタッチ時の残高を**端末グローバル変数**(口座番号×Magic基底キー)に記録し、
  **再アタッチ・端末再起動後も同じ基準を自動復元**(4週失効はEAが日次タッチで防止)。
- 優先順: `InpInitialBalance`明示入力 > 端末保存値 > 現残高(新規記録)。
- **新フェーズ開始時(P1→P2・新チャレンジ)だけ `InpBaselineReset=true` で一度挿し直す**
  (基準を今の残高で取り直してfalseに戻す)。これが唯一の手動操作。

## 4. 残存注意

- 通知はスマホ経由なのでスマホ圏外/電源断では届かない(EA自体のガードは通知と独立に動作)。
- Even側のミラーリング仕様(表示文字数・アプリ許可)は Even Realities アプリの版に依存=初回に
  テスト通知(オプション→通知→テスト)がG2に出ることを確認してから運用。
- 通知は情報提供であり、**手決済の推奨ではない**(参考値通知にも「ロックが自動処理」と明記)。
  手決済した場合は v1.20 の再建て機能と docs/98 の manual-adjusted 規律が適用される。

> 免責: SendNotificationはMetaQuotes社のプッシュ基盤に依存(稀な遅延/不達あり)。
> クリティカルな防御はEA内ガードが担い、通知はその写しである。

## 5.【追記 v1.50】利幅通知(スリーブ別・過去分布比較)

- `InpNotifyWidth`(既定ON): 各スリーブの**月内PnL(実現+含み)を素サイズ1xに換算**し、
  当該スリーブ×当該月の**過去10年分布**(2016-2025・EA内蔵テーブル)と比較して通知:
  - **p75超え**: 「上振れ認識・行動不要」(月1回・スリーブ別)
  - **過去最大超え**: 「⚪上振れ=docs/98の読み方」(月1回・スリーブ別)
- 1x換算 = 口座PnL% ÷ (シナリオ月別重み × 倍率)。重みはシナリオ別テーブルから自動解決。
- G3は対象外(イベント建玉・月次分布の概念が合わない)。
- ⚠ **これは手決済の推奨ではない**。通知文にも明記。過去分布はYahoo再構築の記述統計であり、
  上振れ月の途中カットは検証済みエッジ(時間・カレンダー決済)からの逸脱になる(本docの設計思想)。
  用途は「今月は出来すぎ」の認識と、月末採点(docs/103)の予告。

## 6.【追記】PortfolioD_Prop3 v1.20 への移植

Seasonal v1.40/1.50 の機能を `Chien_PortfolioD_Prop3` に移植(逐語・既定値同一):
- プッシュ通知: エントリー(v7/v4/E-Mon/E5)・参考値+6%・ARM+7%・PASS_LOCK+7.5%・日次−3%警告・
  DAILY_STOP/FLOOR。プレフィクスは `[PD]`(季節EAの `[季節EA]` と区別)。
- 基準残高の端末永続化(`ChienPD_base_<口座>_<Magic>`・日次タッチ・`InpBaselineReset`)。
- E5の手決済後同月内再建て(決済理由CLIENT/MOBILE/WEBのみ・タグ `E5RE_`)。
- **利幅通知は移植対象外**(PortfolioDは通年固定配分でスリーブ×月分布の意味が薄い。必要なら別途)。
