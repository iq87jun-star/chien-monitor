# 117.【事前登録】edge21: E-Mon(指数月曜LONG)の保有時間 — 現行24h vs 同日決済

> 動機: ユーザーのフォワード手決済観測(2026-06〜07、docs/98系)。月曜建玉の同日一括手決済の
> 反実仮想分析で、損益差のほぼ全てが**指数建玉(E-Mon)の翌日持ち越し分**から出ることを確認した。
> 円クロス(v7)の保有時間は10年検証済み(24h優位・docs/37/38)だが、**E-Monの保有時間は個別未検証**。
> ⚠ 本docは `research/edge21_emon_hold_10y.py` の**実行前**にコミットする(docs/72/104/114の流儀)。
> 結果は docs/118 に実出力JSONの転記のみで記載する。

## 1. 仮説と候補(これで固定・追加は再登録)

対象: E-Monスリーブ = NAS100/US500/GER40 月曜LONG(現行実装: 月曜o2o・往復3bps)。

| ID | 保有ルール | 実装(日足10年・主判定) |
|---|---|---|
| **H24(現行)** | 24時間(翌日オープンまで) | 月曜 open→火曜 open(= 現行スリーブ定義そのまま) |
| **HDC(同日決済)** | 当日セッション引けまで | 月曜 open→月曜 close(o2c) |

- 副確認(H1・直近約2年・Yahoo上限730日): 実際のエントリー時刻(9/14 UTC)で
  保有 {同日引け, 24h} を再現し、**日足判定と方向が一致するか**のみを見る(2年でエッジの主張はしない)。
- パラメータ最適化はしない(二値比較・フィットなし → プラセボ/LOYO不要。docs/38と同じ扱い)。

## 2. ファイナンス(夜越しコスト)感応 — 本検証の核心変数

指数CFDのロング夜越しは通常マイナス金利調整(金利+業者マーク)。同日決済はこれを構造的に
排除する(v9がスワップ耐性で生き残ったのと同型・docs/37 §0)。データ(Yahoo指数)には含まれないため
明示シナリオで両建て比較する:

- **F0**: 0bps/夜(価格変化のみ・楽観側=H24有利方向)
- **F2**: 2.6bps/夜(≈ 短期金利4.5%+業者2%を年252日で按分・現実側)
- **F4**: 4bps/夜(高コスト業者・保守側)

H24は月曜→火曜の1夜分を負担、HDCは0夜。**実測が最優先**: ユーザー口座の
`ChienSwapLog_<口座>.csv`(docs/100 §4)の指数スワップ実測が得られれば、その値のシナリオを追加する。

## 3. 手順(固定)

1. データ: 既存の固定窓 日足 2015-01-01〜2026-06-30(fetch_all済みCSV・SHA-256はdocs/114検証と同一)。
   H1は Yahoo 1h の 2024-07-09〜2026-07-07 固定窓(ES=F/NQ=F/^GDAXI・SHA記録)。
2. 系列: `parallel_vs_existing_compare.load_daily` を流用し、月曜の o2o(H24)/o2c(HDC)を
   3銘柄平均・往復3bpsで構築。2016-01〜2025-12の週次(月曜)系列で採点。2026H1は参考表示。
3. 指標: 合計net% / 年率 / 週次Sharpe(年率化) / maxDD / Calmar / 最悪週。
   docs/87式の倍率校正はこの週次系列に対し 最悪週−4%・最大DD−8% 逆算×0.8 で行い、
   **score = mult × 平均週次リターン** を主指標とする(docs/114 §2と同じ思想)。
4. 頑健性: IS:OOS 70:30 / 年次ジャックナイフ(差の符号が何年で反転するか) / コスト2倍。
5. H1副確認: 9/14 UTC建て×{同日引け, 24h}の2年成績の**符号・順位**が日足判定と整合するか。

## 4. 採否の決定規則(事前固定)

**HDC(同日決済)を採用**するのは以下のいずれかを満たす時のみ:

- **A(無条件採用)**: F0(コストなし)で score(HDC) ≥ 1.1 × score(H24) かつ net(HDC) ≥ 0.9 × net(H24)
  かつ コスト2倍で順位維持 かつ H1副確認が矛盾しない
- **B(業者コスト条件付き採用)**: Aは不成立だが、F2(現実的夜越しコスト)で
  net(HDC) > net(H24) かつ Calmar(HDC) ≥ Calmar(H24) → 「**夜越しコストが実測でF2級以上の
  業者に限り** HDC推奨」(v9のスワップ条件付き採用 docs/38 と同じ扱い)

- どちらも不成立なら**現行H24維持**(それも価値ある確認)。
- 採用時の実装: E-Monを持つEA(PortfolioD_Prop3/Seasonal系/Parallel系)に**入力パラメータで**
  反映(既定は現行値=既存動作不変)。同日決済は銘柄セッション引け基準のため
  `InpEMonHoldHours`の短縮ではなく専用ロジック(採用が決まってから設計)。デモ並走→次フェーズ適用。

## 5. 既知の限界(先に書く)

- Yahoo日足の指数o2cは現物指数のセッション(GER40=欧州時間)基準。CFDの24hセッションとは
  引け時刻がずれる(業者引値≠現物引値)。H1副確認とデモで補完。
- H1はYahoo上限で約2年のみ=レジーム1つ分。**主判定はあくまで10年日足**。
- 配当調整(現物指数は配当落ちを含む・CFDは配当調整で概ね中立)は未計上。o2oとo2cの
  差分には配当落ち日効果が僅かに乗る(月曜夜の配当落ちは稀・影響は小さい想定だが正直に記す)。
- 本検証はE-Monスリーブ単体。RG3ゲートとの相互作用は対象外(ゲートは建てる/建てないの判定で
  保有時間と直交)。採用してもポートフォリオ全体の再校正はdocs/87手順で別途。
