## 3. 研究系列との整合(Q104 の本来の問い)

- 研究の基準系列 `base.mon_cell`(deployed_book の Mon レッグ・MC・紙上フォワードの「Mon」族)は**祝日を除外していない**。EA は除外する。差は docs/303/304 の改良分(Mon4 で年 +0.3〜0.5%・祝日月曜は 7 ペア平均マイナス)で、方向は EA 側が有利。紙上フォワードでは `MonExHol` / `MonExJpTue` / `MonExAUNZ` の候補セル(docs/390 §2)がこの差を 6 か月累積で測っている。
- 実口座採点(docs/387 monthly_scoring)は実約定ベースなので、除外の効果は採点に入っている。分布照合(研究系列)側だけが除外なしで、採点月に除外日が多いほど実績が研究分布より良く出やすい(10 月は 10/5・10/12・10/26 の 3 回)。

## 4. 提案(変更する / しない)

| 項目 | 提案 | 理由 |
|---|---|---|
| EA の除外日リスト(JP・豪NZ) | **変更しない** | カレンダーと完全一致。2028 年分の追記は 2027-09 のキューに登録(「登録」後) |
| 11/2 の全口座スキップ | **変更しない**(仕様どおり) | docs/304 Q56 の事前登録規則「翌火曜 JP 祝日の月曜は建てない」。1 週分の機会損失は規則の一部。紙上の `MonExJpTue` で累積判定中(2027-03 末) |
| 研究系列への祝日除外の反映 | 変更しない(11 月改訂では触らない) | 候補セルの 6 か月累積(docs/229 §4)を待つ。採用なら deployed_book の Mon レッグに除外を入れ、MC と採点分布を作り直す(Q として登録) |
| 月次の装置 | **毎月 1 日のダイジェスト後に `python3 queue/q104_holiday_skip_parity.py` を実行**し、「カレンダー一致・除外日の違反なし」の 1 行を月次改正案に転記する | スクリプトは manifest の配備 EA から読むので、EA の版が変わっても追従する |

11 月の改訂への含意: 祝日機構は実口座で検証済み。新規口座(EA10S・EA11C6)も同じ入力リストを持つので追加作業なし。

## 5. 付記(本日の取り込みで判明・Q104 外): 3 口座の EA が有効期限 10/31 に到達し「新規停止」

`ea_log_extract` に `[EXPIRY] 有効期限到達 → 新規停止`(11/2 07:00 JST)が **ルビー 6104736(B案 v1.05)・パール 6071612(v1.11)・FN 14166201(v1.37)** の 3 本。いずれも `InpExpiry = 2026.10.31 23:59`(RecentFit 直近特化の賞味期限)。期限後は新規エントリーのみ停止で、建玉(14166201 の UK100 / USOIL Hold)は通常管理(時間切れ決済・ガード)のまま。影響: ルビー・パールは **11/9(月)の Mon から建たない**、14166201 は **11/4(水)の Roll と Hold の再建てが止まる**。10 月の月次改正(docs/389)で期限の確認が抜けていた。対処はユーザー判断(「切替」): (a) 期限だけ延長した版(v+0.01・`InpExpiry` を EA11 と同じ 2027.03.31)を用意して差し替える、(b) `recentfit_screen.py` を再実行して構成を更新してから差し替える。10 月の実口座採点(docs/389 §1: パール +2.66%・ルビー +2.6%・14166201 −0.31%)は分布内で、構成を変える根拠は出ていない。
