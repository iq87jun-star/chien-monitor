# 202.【事前登録】出金・寿命ポリシー — Instant口座の失格は「出口が無い」ことの帰結か

> 2026-09-02作成。費用ゼロの研究(docs/185 §5適合)。
> 本docのルールは`research/withdrawal_policy_mc.py`の実行**前**に凍結した。実行後の変更禁止。

## 1. 動機

docs/199 §8・docs/201 §9で、FN Instant 20k の失格率は悲観バウンドで **62.7〜77.8%** と出た。
これはシグナルの問題ではない。Instantは**目標が無く**、トレーリング−6%のフロアだけで
**地平の限り走り続ける**。出口の無いトレーリングストップは、時間を伸ばせば必ず当たる。

docs/177 §4は「+10%通知が出たら出金→スケールアップを検討」と書きつつ、
「出金後のフロア再計算」を**FNへの未回答事項**として残している(docs/161)。
つまり**いつ・いくら出金するか**は一度も設計されておらず、その設計に必要な規約情報も未回収である。

出金はシグナルを一切変えずに口座の寿命と実現利益を動かす変数であり、
資金化後の全口座(docs/194の長寿命トラックを含む)に共通する層である。

## 2. 対象と規則(実行前固定)

**対象**: FN Stellar Instant 20k(口座11988011・RecentFit Instant 4.0x・docs/177)。
系列は`deployed_book.py`の配備レッグ(Mon GBPJPY 0.374 / AUDJPY 0.322 / v4 USDJPY 0.304)×4.0。

**フロア規則(docs/177 §1・EA実装値)**:

```
floor_t = min( HWM_t − 6% × 初期残高 ,  初期残高 )        … 建値で止まるトレーリング
EA恒久停止 = equity ≤ floor + 1%                              … FNが殺す前にEAが止める
```

⚠ **docs/199・docs/201のMCはこの「建値で止まる」規則を実装しておらず、純粋なトレーリング
(フロアが上がり続ける)として計算していた。** それらのInstant失格率(77.8% / 62.7%)は
**過大**である可能性がある。本研究で両方を走らせ、差を記録する(§5-1)。

## 3. 出金後のフロアの扱い — FN未回答のため両方を走らせる

| 仮定 | 内容 | 意味 |
|---|---|---|
| `F_keep` | 出金してもHWM・フロアは**変わらない** | 出金分だけequityが下がり、フロアまでの距離が縮む。**出金がリスクを増やす**最悪解釈 |
| `F_reset` | 出金後、HWM:=新残高・フロア:=新残高−6% | 出金でフロアが**リセット**される。出金が安全弁になる最良解釈 |

真の規則はこの間のどこかにある。**両仮定で結論が変わるなら、FNへの質問(docs/161未解決)が
出金の前提条件になる**ことが本研究の帰結になる。

## 4. ポリシー(実行前固定)

| ポリシー | 内容 |
|---|---|
| `P0` | **出金しない**(現行) |
| `P1_10` | equity ≥ +10% で **+0%まで**(利益全額)出金 — docs/177 §4の「+10%通知」に対応 |
| `P2_10_5` | equity ≥ +10% で **+5%を残して**出金(バッファ保持型) |
| `P3_5` | equity ≥ +5% で +0%まで出金(高頻度型) |

- 出金は閾値到達時に即時可能とする(実際の出金サイクル制約は無視・簡略化を明示)。
- スケールアップ(docs/154)は評価しない。
- 分配率は評価に含めない(全ポリシーに同率で掛かるため順位を変えない)。

## 5. MC条件(実行前固定)

- 5日ブロックブートストラップ・シード7・1万パス・**地平500インデックス日**(出金サイクルを複数回含める)
- EA日次ガード −4%クリップ(docs/177の内部規律)
- サンプル: 直近12ヶ月(中間)/ 全期間(悲観)の2バウンド
- **§5-1 感度**: `P0` を「建値ロックあり(docs/177)」と「ロックなし(docs/199の実装)」の両方で走らせ、
  docs/199/201のInstant失格率がどれだけ過大だったかを記録する

## 6. 評価指標(実行前固定)

| 指標 | 定義 |
|---|---|
| `P_stop` | 500日以内にEA恒久停止(=収益源の喪失) |
| `E_withdrawn` | 累計出金額の期待値(初期残高比%) |
| `E_lifetime` | 寿命(停止日または地平)の期待値 |
| **`E_value`** | **累計出金 + 地平で生存していれば max(equity−初期, 0)**(未実現分は地平で出金可能とみなす) |

`E_value`が主指標。`P0`は累計出金ゼロだが未実現分が`E_value`に乗るため比較可能。

## 7. 解釈規則(実行前固定・後知恵の禁止)

| 結果 | 判定 |
|---|---|
| ある出金ポリシーが `F_keep`・`F_reset` の**両方**で `P0` より `E_value` が高い | そのポリシーを**推奨**(FNの回答に依らず成立) |
| `F_keep` と `F_reset` で `E_value` の順位が異なる | **FNへの質問(docs/161)を出金の前提条件とする**。回答前に出金しない |
| どのポリシーも `P0` を上回らない | 出金しない現行を維持。Instantの失格率は構造として受容する |

- 閾値(5%/10%)・バッファ(5%)は3点のみ評価する。グリッド探索はしない。
- 本結果を理由に稼働中口座の運用を変えない。適用は**次回の出金判断時**(docs/177 §4)からとする。

## 8. 承知している限界

1. FN Instantの出金には実際にはサイクル(隔週等)と最低額があり、閾値到達時の即時出金は簡略化である。
2. equity基準でHWMを追跡している(EAと同じ・FNのbalance基準より保守側)。
3. 出金後のスケールアップ(初期額加算)を評価しないため、`F_reset`側の利益は過小評価の可能性がある。
4. Yahoo日足近似・実口座成績ではない。

# 10.【結果 2026-09-02】どの出金ポリシーも「出金しない」を上回らない — 建値ロックが理由

> `research/results/withdrawal_policy_mc.json`・シード7・1万パス・地平500営業日(≈2年)。
> **判定(docs/202 §7): どのポリシーも `P0` を `E_value` で上回らない → 出金しない現行を維持。**

## 10.1 実行上の修正(結果を読む前に)

初回実行で `P0` の `E_value` が **+406%** という異常値が出た。原因は、Instant合成が
**活動日(月曜とv4シグナル日)だけを索引に持ち、12ヶ月で83本しか無い**ことだった。
「500本の地平」が暦で約6年になっていた。営業日カレンダーへ再索引(非活動日=0)して再実行した。
以下は修正後の値である(recent_12m の P0 +64% ≈ 12ヶ月+29.6%の2年複利で整合)。
docs/187 §6.1と同種の問題であり、**活動日索引の系列を単独でMCに掛けるときは必ず暦へ再索引する**。

## 10.3 なぜ出金すると死ぬのか — 建値ロックの含み益は「無料の保険」

Instantのフロアは `min(HWM − 6%, 初期残高)`、すなわち**建値で止まる**。
equity が +30% まで育てばフロアは初期残高のまま = **30%の余白**が生まれる。
出金はこの余白を取り崩す:

- **+0%まで全額出金(P1_10 / P3_5)は、フロアがロックされた建値へ equity を戻す行為**であり、
  `F_keep` では即死(停止率100%・寿命55〜97営業日)。
- `F_reset` でも、出金のたびに余白が6%へリセットされる。P0が余白を積み上げ続けるのに対し、
  出金ポリシーは毎回ゼロから6%の細い橋を渡り直す。悲観サンプルで停止率97〜100%になるのはこのため。
- `P2_10_5`(5%残す)は `F_keep` で唯一生き残る(23.5%)が、5%の余白は悲観側では足りない(97%)。

**「利益を出金する」と「口座を守る」が、この規則の下では正面から衝突する。**
docs/177 §4の「+10%通知が出たら出金」は、`F_keep` なら口座を殺す手順である。

## 10.4 FNへの質問(docs/161未解決)は依然として必要 — ただし優先度は下がる

順位は仮定で変わる(keep: P2_10_5 > P1_10 > P3_5 / reset: P1_10 > P3_5 > P2_10_5)。
しかし**どちらの仮定でも P0 が最上位**であるため、出金ポリシーの選択に先立って
「出金しない」が結論になる。FNへの質問は、将来「余白を大きく残した出金」を検討する際の前提として残す。

## 10.5 §5-1 建値ロックの感度 — docs/199 / docs/201 のInstant失格率は過大だった

| サンプル | 建値ロックあり(docs/177の規則) | ロックなし(docs/199/201の実装) |
|---|--:|--:|
| 直近12ヶ月 | **4.5%** | 57.5% |
| 全期間 | **63.2%** | 99.8% |

**docs/199 §8.2の「Instant 77.8%」、docs/201 §9.4の「62.7%」は、ロック未実装による過大値である。**
ブックMC(`book_circuit_breaker_mc.py`)の `sim_trail` にロックを実装し再計算した
(`results/book_circuit_breaker_mc_lockfix.json`・docs/199 §9に追記)。
docs/200の発火カウントはInstantを除外済みのため、**docs/200の結論(CB_new)は影響を受けない**。
影響を受けるのは旧定義 CB_old と E[失格口座数] である。

## 10.6 死んでいない仮説(将来の事前登録候補・本docでは採用しない)

`P2_10_5` が `F_keep` で唯一生き残ったことは、「**大きな余白を残して、それを超えた分だけ出金する**」
方向を示唆する(例: +20%を残す)。本docの3点(5%/10%/バッファ5%)の外にあるため、
**ここで追加評価はしない**(グリッド探索の禁止)。検討するなら新しい事前登録で。
そのとき同時に、docs/182 §6-4が触れた「業者の規約変更リスク」(出金せず口座に置いておくことのリスク)を
評価軸に入れる必要がある。本docの `E_value` はそれをゼロと置いている。

## 10.7 帰結

1. **Instantは出金しない**(現行維持)。docs/177 §4の「+10%で出金を検討」は、
   本docの結果を踏まえ「**出金しない。理由: 建値ロックの余白が生存を支配する**」へ読み替える。
2. Instantの失格率は、docs/199/201が示唆したほど高くない(悲観63.2%/2年・直近4.5%/2年)。
   docs/201 §9.6の「Instantに何を載せるかの再検討」は、その前提が半分崩れたため優先度を下げる。
3. 稼働中口座の運用は変更しない。適用は次回の出金判断時から。
