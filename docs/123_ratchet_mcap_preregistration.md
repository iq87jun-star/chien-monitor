# 123.【事前登録】利益ラチェット+月内損失キャップ(RATCHET+MCAP) — 攻めサイズの左尾切り

> 経緯: ユーザー問い「到達を維持し失格率を下げる方法」への現在地分析(2026-07-07・採点外)で、
> +5.04%起点・攻め5xにおいて「+2%への押し戻しで保守へ恒久降格 + 月内損失−4%で当月停止」が
> 失格5.8→2.5%(中央+4日)を示した。**ただしそれは4案からの事後選択**。本docは同じ数字での採用を
> 禁じ、**チャレンジ開始からの全生涯**での確証ランを、パラメータ・決定規則を固定した上で行う。
> 思想はdocs/60(G)「ガードで左尾を切る」の延長=エッジ変更なし・ガードを緩める方向の変更なし。
> ⚠ 本docは `research/policy_ratchet_confirm.py` の**実行前**にコミット。結果はdocs/124へ転記のみ。

## 1. ガード仕様(これで固定・変更は再登録)

状態変数 g = チャレンジ開始からのgain%(対初期残高)。

- **RATCHET(利益ラチェット)**: gの最高到達点が **ARM=+5%** 以上になった後、
  g ≤ **ARM−3% = +2%** に押し戻されたら、以後**全リスクを0.4倍に恒久降格**(再昇格なし)。
- **MCAP(月内損失キャップ)**: 暦月内の累積損益が **−4%**(対初期残高)に達したら
  全決済し当月中は新規停止(翌月月初に自動再開)。docs/60(G)の月内版。
- 両ガードは既存ガード(フロア/日次−4%/PASS_LOCK/MONTH_TRAIL)と独立に併走。

## 2. 確証ランの設計(固定)

- 系列・環境: docs/121と同一(PD日次1x・2016-2025・FN P1 = +8%/−10%/日次2バウンド・36M上限)。
- **開始点 g0=0(全生涯)を主判定**とする(+5%起点の再計算は参考表示のみ=事後選択の再confirmはしない)。
- m0グリッド: {3, 4, 5, 6}(攻め帯。保守帯m0≤2はdocs/122 §3の別件として扱わない)。
- 経路: 歴史120本(各月開始)+ブロックブートストラップ(3ヶ月×2000, seed=7)。
- 比較: A=ベース(現行) vs D=RATCHET+MCAP。分解のためB=MCAP単独/C=RATCHET単独も表示
  (採否判定はDのみ。B/Cの成績を見てDの構成を変えることはしない)。

## 3. 採否の決定規則(事前固定・全て必須)

1. **失格が全点で悪化しない**: 4つのm0全てで fail%(D) ≤ fail%(A)(楽観・悲観の両バウンド、歴史)
2. **実質的改善**: 楽観・歴史で 4点中3点以上 fail%(D) ≤ 0.75×fail%(A)(相対25%以上削減)
3. **速度維持**: 全点で 通過中央月(D) ≤ 1.4×通過中央月(A)
4. **ブート再現**: ブートでも4点中3点以上で相対25%以上削減
5. **開始年頑健性**: 歴史経路を開始年でグループ化し、失格数(D)≤失格数(A) が10年中8年以上

- 不成立なら**採用見送り**(手動運用ルールとしての紹介に留め、EAには入れない)。
- 合格時: `Chien_PortfolioD_Prop3` に**既定OFF**の入力群として実装(v1.40)。
  ARM/押し幅/降格倍率/キャップ値は本docの固定値を既定値とし、デモ並走→適用の順(docs/104 §4)。

## 4. 既知の限界(先に書く)

- 発案経緯が事後的(§0)。確証ランは開始点・グリッドを変えて独立性を高めたが、同一の10年系列上
  ではある(完全な独立確認はフォワード=docs/98系のみ)。
- 加算近似・日次解像度・Yahoo近似はdocs/121 §4と同じ。RATCHETの実装は日次更新(EAはtick追従可)。
- 降格後の再昇格は仕様に含めない(新フェーズ開始=`InpBaselineReset`で人手リセット)。
