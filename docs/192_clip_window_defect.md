# 192.【障害記録・型(c)】選抜スクリプトの窓truncateバグ — D案2026-09版が規則不適合の構成で稼働中

> 2026-09-01発見。docs/186の実験①を実装中に、2026-08のOOSが全アームで0.00%になる
> 不自然な挙動から発覚した。docs/185 §1の**型(c)(実装・運用欠陥)**に該当する。
> **口座喪失は発生していない**が、稼働中のFTMO #521100397 が事前登録規則(docs/180 §2)に
> 適合しない構成で走っている。

## 1. 原因(1行)

`research/recentfit_screen.py` の `clip()` が窓の終端を**既定引数**で受けていた:

```python
W_ALL0, W_ALL1 = pd.Timestamp("2016-01-01"), pd.Timestamp("2026-07-29")
def clip(s, a=W_ALL0, b=W_ALL1):      # ← 既定引数はモジュール定義時に一度だけ評価される
```

Pythonの既定引数は**関数定義時に1回だけ評価**される。したがって呼び出し側が

```python
base.W_ALL1 = pd.Timestamp("2026-08-31")   # 窓をロールしたつもり
```

としても、`clip()` の `b` は**2026-07-29 のまま**であり、全セル系列がそこで打ち切られていた。
`base.win()`(line 237)にも同じ既定引数の問題があった。

### 実測による確認

| | mon_cell("GBPJPY") の最終日 |
|---|---|
| `base.W_ALL1 = 2026-08-31` を再代入した状態(修正前) | **2026-07-27** |
| 同(修正後) | **2026-08-31** |
| キャッシュCSVの実データ最終行 | 2026-09-01(データは取得できていた) |

**データは正しく取得されており、切られていたのは構築段階である。** 取得(`fetch`)は
`P2_EPOCH`を見るため正しく2026-08-31まで拾っていた。ログにも警告は一切出ない。

## 4. 最も重要な帰結 — docs/184の警告は大半がバグの産物だった

docs/184 §3は配備決定時に次を警告として提示していた:

> **12ヶ月バウンドが旧構成配備時の62.2%→9.5%へ大幅劣化**。選抜窓(6〜8月)が極端に静かで、
> スコア1位のMon USDJPYは選抜窓+1.1%に対し12ヶ月−2.0% — docs/180が自ら警告していた
> 「短窓ほど選抜ノイズ増大」の顕在化と評価

**この解釈は誤りだった可能性が高い。** 規則通りの窓で再実行すると12ヶ月バウンドは
**59.3%**(旧構成配備時62.2%とほぼ同水準)であり、「レジーム劣化の顕在化」ではなく
**窓が2ヶ月に潰れていたことによる選抜ノイズの人為的増幅**だったと読むのが自然である。

- docs/184は「休止案(10月選抜まで温存)を推奨として提示したが、ユーザー決定は規則通りの配備」と
  記録している。**その推奨・その決定はいずれも欠陥のある数字の上で行われた。**
- 同時に、この事象は皮肉にも docs/180 §1 の
  「短窓ほど選抜ノイズは増大し賞味期限は短くなる」を**意図せず実験してしまった**ものであり、
  3ヶ月窓と2ヶ月窓で12ヶ月バウンドが 59.3% → 9.5% まで動くという、
  窓長の感度の実測値を残した(docs/186の実験①と整合する方向)。

## 5. 実施した修正

`recentfit_screen.py` の `clip()` と `win()` を、既定引数ではなく**呼び出し時にモジュール値を
読む**形に変更した:

```python
def clip(s, a=None, b=None):
    a = W_ALL0 if a is None else a
    b = W_ALL1 if b is None else b
    ...
```

- **W_ALL1を再代入しない全ての呼び出しでは挙動が完全に同一**であることを確認済み
  (修正後も既定窓では最終日 2026-07-27 のまま)。したがって docs/174-182 の
  過去の数値の再現性は保たれる。
- 配備時の一次値ファイルは改変していない。修正版は別ファイル
  `recentfit_short_rescreen_202609_fixed.json` に保存した。
