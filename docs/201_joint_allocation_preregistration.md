# 201.【事前登録】口座横断のセル割り付け — 8口座を1つのブックとして設計する

> 2026-09-02作成。費用ゼロの研究(docs/185 §5適合)。
> 本docのルールは`research/joint_allocation_mc.py`の実行**前**に凍結した。実行後の変更禁止。

## 1. 動機 — 今回見つかった問題の大半は「口座を独立に設計している」ことに根を持つ

| 発見 | 出典 | 独立設計との関係 |
|---|---|---|
| 完全重複2組(ρ=1.000) | docs/197 §9.2.1 | 別々の判断で同じ選抜規則を走らせた帰結 |
| Mon GBPJPY の5口座並走 | docs/193 §1 | 同上 |
| CB発火54%(悲観) | docs/199 §8 | 口座ごとの失格率を足し合わせた帰結 |
| 相関ペナルティが平時に効かない | docs/199 §8 | 1口座の相関だけ動かしても、ブックは動かない |

現状は各口座が**自分の規則で独立に選抜**し、業者制約への適合も口座ごとに手作業で確認している
(docs/182 §3の銘柄除外・docs/178 §2のJP225除外)。
「8口座を1つのブックとして、制約の下でセルを口座に**割り付ける**」問題は一度も解かれていない。

docs/187 §2.2は「分散はプロップにおいて倍率へ変換される」ことを単一口座で示した。
本研究は同じ機序が**口座間**でも成立するかを測る。

## 2. 帰無仮説

> **H0: 口座横断の割り付けは、各口座の独立選抜に対して、ブック全体の同時失格確率を下げない
> (または、下げる代わりに資金化の期待値を失う)。**

## 4. アーム(実行前固定)

| アーム | 内容 |
|---|---|
| `INDEP` | **現行**。各口座が独立に選抜する(ベースライン) |
| `JOINT_EXCL` | 順次選抜。**他口座に既に割り付けたセル(族×銘柄)を候補から除外**する |
| `JOINT_EXCL_SYM` | 順次選抜。**他口座に既に割り付けた銘柄(族を問わず)を候補から除外**する |
| `JOINT_PEN` | `JOINT_EXCL` + 既割付口座の合成に対して λ=1.0 のペナルティ(docs/193のLAM10の一般化) |

### 4.1 順次選抜の順序(実行前固定)

**資金×配備倍率(リスク寄与)の降順**: 速攻プロ(129×2.5) → C案(50×6.0) → D案(50×5.24) →
非FX(100×1.48) → パール(32×4.0) → Instant(20×4.0)。
リスク寄与の大きい口座が先に選び、小さい口座がそれを避ける。
順序は本研究の選択であり、他の順序は評価しない(順序の最適化は選抜ノイズの再生産)。

### 4.2 業者制約(全JOINTアームで強制・実行前固定)

| 制約 | 内容 | 出典 |
|---|---|---|
| FN同一取引禁止 | **InstantとFN100k非FXは同一銘柄を持たない** | docs/161 §4③・docs/182 §3 |
| Fintokei トレードグループ3% | パール・速攻プロは**Hold族を持たない** | docs/178 §2 |
| Fintokei 両建て禁止 | パール・速攻プロは同一銘柄で逆方向を持たない(Mon/v4はLONG基調のため実質非該当・記録のみ) | docs/176 §7.5 |
| FTMO | 自己口座間コピー可=制約なし | docs/181 §3.1 |

`INDEP`ではこれらを強制しない(現行=配備時に手作業で解消している)。
代わりに**違反件数を診断として出力**する。

## 5. 評価(実行前固定)

docs/199の同時失格MCを拡張し、**資金化も追跡**する:

- 全口座に同一のブートストラップ・ブロック(5日・シード7・1万パス)
- 口座別の業者規則はdocs/199 §3の表と同一
- 6基準日(docs/198と同じ)で各アームを実行し、平均で読む

| 指標 | 定義 |
|---|---|
| **`P_CB_new`** | docs/200の定義(発火カウントは通常口座5つ: A案・B案・C案・D案・非FX) |
| `P_CB_old` | docs/185旧定義(7口座全て)・参考 |
| **`E_funded`** | 資金化口座数の期待値 |
| `E_failed` | 失格口座数の期待値 |
| 口座別 資金化率・失格率 | 7口座 |
| 重複診断 | ρ>0.7の口座ペア数・完全一致ペア数・FN同一銘柄違反数 |

## 6. 解釈規則(実行前固定・後知恵の禁止)

| 結果 | 判定 |
|---|---|
| あるJOINTアームが `P_CB_new` を INDEP 比で**相対20%以上**下げ、かつ `E_funded` が下がらない | **採用候補**。次回以降の再スクリーニングを「順次・除外つき」に切り替える提案を出す |
| CBは下がるが `E_funded` も下がる | トレードオフとして併記し、ユーザー決定に付す |
| どちらも改善しない | H0棄却できず。独立選抜を維持する |

- **稼働中の8口座は本結果を理由に変更しない**(docs/174 §1・docs/179 §4)。
  適用先は期限到来時の再スクリーニングのみ。
- 順序・λ・閾値を本結果から最適化しない。

## 7. 承知している限界

1. 季節RG3($100k)が含まれない。実ブックより FX集中が強い方向に偏る(docs/199 §6と同じ)。
2. A案は再割付できないため固定。A案と他口座の重複(Mon GBPJPY)は本研究では解消されない。
3. 「順次選抜」は真の最適化ではない(組合せ最適化は探索空間が大きく、選抜ノイズの温床になる)。
   本研究が測るのは「**独立選抜をやめて、重複を避けるだけでどれだけ変わるか**」である。
4. 各口座の規則・窓を現行のまま保つため、6口座がそれぞれ別の窓で選抜する。
   窓を揃えれば重複はさらに減るはずだが、それは各トラックの事前登録規則の変更になるため行わない。

# 9.【結果 2026-09-02】H0棄却できず — 重複は消えるが、CBの低下は基準(−20%)に届かない

> `research/results/joint_allocation_mc.json`・シード7・1万パス・6基準日の平均。
> **判定(docs/201 §6): 全JOINTアームが採用候補の基準を満たさない。独立選抜を維持する。**

## 9.1 主結果(6基準日平均)

| アーム | **CB_new**(docs/200定義) | LAM0比 | CB_old(旧定義) | **E[資金化口座数]** | E[失格口座数] | ρ>0.7の組 | 同一構成の組 |
|---|--:|--:|--:|--:|--:|--:|--:|
| `INDEP`(現行) | **15.32%** | — | 45.01% | **3.594** | 2.502 | 4.17 | **0.83** |
| `JOINT_EXCL` | 13.74% | **−10.3%** | 39.59% | 3.632(+0.038) | 2.280 | 0.67 | 0 |
| `JOINT_EXCL_SYM` | 13.21% | −13.8% | 32.82% | 3.147(**−0.447**) | 1.971 | 0.67 | 0 |
| `JOINT_PEN` | 13.05% | −14.8% | 39.83% | 3.548(−0.046) | 2.291 | 0.83 | 0 |

- **重複は完全に消える**(同一構成の組 0.83→0)。ρ>0.7の組も 4.17→0.67。
- しかし **CB_new の低下は −10〜−15% で、事前登録の −20% に届かない**。
- `JOINT_EXCL_SYM`(銘柄レベル除外)は最後の口座(Instant)を **6日中4日で空にする**
  (選抜できるセルが残らない)。E[資金化]が−0.447落ちるのはそのため。制約として強すぎる。
- `JOINT_EXCL` は集計上は**全指標でINDEPを上回る**(CB↓・E[資金化]↑・E[失格]↓・重複0)が、
  基準に届かない上に、日別では不安定である(§9.3)。

## 9.2 シミュレーションは現ブックの重複を再現している(妥当性の確認)

2026-08-31基準のINDEPでは、**速攻プロ・C案・パールの3口座が完全に同一の構成**
(Mon AUDJPY/GBPJPY + v4 NZDUSD/USDJPY)を選び、Instantもほぼ同じ構成になった。
これは現に稼働中のブックに完全重複が2組ある(docs/197 §9.2.1)状況と整合する。
**独立選抜が重複を生む機序は、実験の中で再現されている。**

## 9.3 効果は「重複があるときだけ」出る — docs/197 §9と同じ結論

| 基準日 | INDEP同一構成 | INDEP CB_new | JOINT_EXCL CB_new | 差 |
|---|--:|--:|--:|--:|
| 2025-09-30 | 0 | 11.20% | **5.56%** | −5.6pt |
| 2025-12-31 | 1 | 10.66% | 9.48% | −1.2pt |
| 2026-03-31 | 0 | 11.83% | 10.11% | −1.7pt |
| 2026-05-29 | 0 | 18.47% | 19.78% | **+1.3pt** |
| 2026-06-30 | 1 | 18.41% | 21.78% | **+3.4pt** |
| 2026-08-31 | **3** | 21.35% | **15.75%** | −5.6pt |

**6日中2日でJOINT_EXCLはINDEPより悪い。** 重複が3組ある2026-08-31では大きく効き、
既に分散している日では、後順の口座を無理に別のセルへ押し出す分だけ悪化する。
docs/199 §8で「平時のペナルティは効かない」、docs/197 §9で「重複検知時のみ発動」と
した結論が、口座横断でも再現された。

## 9.4 口座別に何が起きているか(JOINT_EXCL vs INDEP・6日平均)

| 口座 | INDEP 資金化/失格 | JOINT_EXCL 資金化/失格 | 読み |
|---|---|---|---|
| **Instant**(順序最後) | 37.3% / **62.7%** | **58.3% / 41.7%** | FXクラスタから押し出され低ボラ構成(倍率0.92)へ。**失格が21pt減る** |
| D案(3番目) | 67.9% / 12.4% | 59.9% / 10.7% | 前順の速攻プロ・C案に良いセルを取られ資金化−8pt |
| パール(5番目) | 71.7% / 14.7% | 65.1% / 14.8% | 同上・−6.6pt |
| C案(2番目) | 70.3% / 11.6% | 70.4% / 13.0% | ほぼ不変 |
| 速攻プロ(1番目) | 7.3% / 92.6% | 6.8% / 93.2% | 先頭なので不変。短命設計そのもの |

**集計の改善は、ほぼInstantの失格減少1口座分で説明できる。** その分をD案・パールが払っている。
順序の後ろに置かれた口座が犠牲になる構造であり、順序を変えれば別の口座が犠牲になる
(順序の最適化は行わない・§6)。

## 9.5 結論と帰結

1. **H0は棄却できない。独立選抜(現行)を維持する。**
2. 口座横断の割り付けが効くのは**独立選抜が重複を生んでいる日だけ**である。
   その状況に限って発動する規則は **docs/197 §9(重複検知時のみλ=1.0)として既に事前登録済み**であり、
   本研究はそれを口座横断でも支持する追加証拠になった。**新しい規則は追加しない。**
3. **順次選抜の「後順の口座が犠牲になる」構造**は、本研究の設計そのものの限界である。
   真の同時最適化(組合せ)は探索空間が大きく、選抜ノイズの温床になるため行わない(§7-3)。
4. 稼働中8口座は変更しない(docs/174 §1・docs/179 §4)。

## 9.6 本研究で分かった、規則とは別の事実

- **Instantの失格率62.7%(INDEP)は、選抜の問題ではなく順序・構造の問題である。**
  FXクラスタと同じ構成を4.0x(本実験では校正値3.24)で走らせるとこうなる。
  JOINT_EXCLで低ボラ構成に変わると41.7%まで下がる。**Instantに何を載せるか**は
  docs/177の「B案をInstant用に複製」という判断の再検討に値する(期限10/31の再スクリーニング時)。
- docs/200で発火カウントから外した速攻プロ(失格92.6%)とInstant(62.7%)が、
  旧定義CB_old(45%)と新定義CB_new(15%)の差のほぼ全てである。docs/200の改訂の妥当性を裏付ける。
