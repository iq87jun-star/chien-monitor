# 201.【事前登録】口座横断のセル割り付け — 8口座を1つのブックとして設計する

> 2026-09-02作成。費用ゼロの研究(docs/185 §5適合)。
> 本docのルールは`research/joint_allocation_mc.py`の実行**前**に凍結した。実行後の変更禁止。

## 1. 動機 — 今回見つかった問題の大半は「口座を独立に設計している」ことに根を持つ

| 発見 | 出典 | 独立設計との関係 |
|---|---|---|
| 完全重複2組(ρ=1.000) | docs/197 §9.2.1 | 別々の判断で同じ選抜規則を走らせた帰結 |
| Mon GBPJPY の5口座並走 | docs/193 §1 | 同上 |
| CB発火54%(悲観) | docs/199 §8 | 口座ごとの失格率を足し合わせた帰結 |
| 相関ペナルティが平時に効かない | docs/199 §8 | 1口座の相関だけ動かしても、ブックは動かない |

現状は各口座が**自分の規則で独立に選抜**し、業者制約への適合も口座ごとに手作業で確認している
(docs/182 §3の銘柄除外・docs/178 §2のJP225除外)。
「8口座を1つのブックとして、制約の下でセルを口座に**割り付ける**」問題は一度も解かれていない。

docs/187 §2.2は「分散はプロップにおいて倍率へ変換される」ことを単一口座で示した。
本研究は同じ機序が**口座間**でも成立するかを測る。

## 2. 帰無仮説

> **H0: 口座横断の割り付けは、各口座の独立選抜に対して、ブック全体の同時失格確率を下げない
> (または、下げる代わりに資金化の期待値を失う)。**

## 4. アーム(実行前固定)

| アーム | 内容 |
|---|---|
| `INDEP` | **現行**。各口座が独立に選抜する(ベースライン) |
| `JOINT_EXCL` | 順次選抜。**他口座に既に割り付けたセル(族×銘柄)を候補から除外**する |
| `JOINT_EXCL_SYM` | 順次選抜。**他口座に既に割り付けた銘柄(族を問わず)を候補から除外**する |
| `JOINT_PEN` | `JOINT_EXCL` + 既割付口座の合成に対して λ=1.0 のペナルティ(docs/193のLAM10の一般化) |

### 4.1 順次選抜の順序(実行前固定)

**資金×配備倍率(リスク寄与)の降順**: 速攻プロ(129×2.5) → C案(50×6.0) → D案(50×5.24) →
非FX(100×1.48) → パール(32×4.0) → Instant(20×4.0)。
リスク寄与の大きい口座が先に選び、小さい口座がそれを避ける。
順序は本研究の選択であり、他の順序は評価しない(順序の最適化は選抜ノイズの再生産)。

### 4.2 業者制約(全JOINTアームで強制・実行前固定)

| 制約 | 内容 | 出典 |
|---|---|---|
| FN同一取引禁止 | **InstantとFN100k非FXは同一銘柄を持たない** | docs/161 §4③・docs/182 §3 |
| Fintokei トレードグループ3% | パール・速攻プロは**Hold族を持たない** | docs/178 §2 |
| Fintokei 両建て禁止 | パール・速攻プロは同一銘柄で逆方向を持たない(Mon/v4はLONG基調のため実質非該当・記録のみ) | docs/176 §7.5 |
| FTMO | 自己口座間コピー可=制約なし | docs/181 §3.1 |

`INDEP`ではこれらを強制しない(現行=配備時に手作業で解消している)。
代わりに**違反件数を診断として出力**する。

## 5. 評価(実行前固定)

docs/199の同時失格MCを拡張し、**資金化も追跡**する:

- 全口座に同一のブートストラップ・ブロック(5日・シード7・1万パス)
- 口座別の業者規則はdocs/199 §3の表と同一
- 6基準日(docs/198と同じ)で各アームを実行し、平均で読む

| 指標 | 定義 |
|---|---|
| **`P_CB_new`** | docs/200の定義(発火カウントは通常口座5つ: A案・B案・C案・D案・非FX) |
| `P_CB_old` | docs/185旧定義(7口座全て)・参考 |
| **`E_funded`** | 資金化口座数の期待値 |
| `E_failed` | 失格口座数の期待値 |
| 口座別 資金化率・失格率 | 7口座 |
| 重複診断 | ρ>0.7の口座ペア数・完全一致ペア数・FN同一銘柄違反数 |

## 6. 解釈規則(実行前固定・後知恵の禁止)

| 結果 | 判定 |
|---|---|
| あるJOINTアームが `P_CB_new` を INDEP 比で**相対20%以上**下げ、かつ `E_funded` が下がらない | **採用候補**。次回以降の再スクリーニングを「順次・除外つき」に切り替える提案を出す |
| CBは下がるが `E_funded` も下がる | トレードオフとして併記し、ユーザー決定に付す |
| どちらも改善しない | H0棄却できず。独立選抜を維持する |

- **稼働中の8口座は本結果を理由に変更しない**(docs/174 §1・docs/179 §4)。
  適用先は期限到来時の再スクリーニングのみ。
- 順序・λ・閾値を本結果から最適化しない。

## 7. 承知している限界

1. 季節RG3($100k)が含まれない。実ブックより FX集中が強い方向に偏る(docs/199 §6と同じ)。
2. A案は再割付できないため固定。A案と他口座の重複(Mon GBPJPY)は本研究では解消されない。
3. 「順次選抜」は真の最適化ではない(組合せ最適化は探索空間が大きく、選抜ノイズの温床になる)。
   本研究が測るのは「**独立選抜をやめて、重複を避けるだけでどれだけ変わるか**」である。
4. 各口座の規則・窓を現行のまま保つため、6口座がそれぞれ別の窓で選抜する。
   窓を揃えれば重複はさらに減るはずだが、それは各トラックの事前登録規則の変更になるため行わない。
