# 211.【事前登録】配備中レグの別ソース再現 — Yahoo で選抜した 13 レグ・7 口座を Dukascopy 日足で同一性確認

> 2026-09-04。docs/209(E5 の別ソース再現)と同じ手順を、**実際に資金が載っているレグ**に適用する(新境地「3」)。
> 目的は「Yahoo の日足で作った選抜と倍率が、別ソースでも同じ系列を指しているか」の確認。
> 数字は §4 で確定し、書き換えない。

## 1. 対象(`research/deployed_book.py` BOOK・7 口座・重複を除いて 13 レグ)

| ファミリー | 銘柄 | 使用口座 |
|---|---|---|
| Mon | GBPJPY / AUDJPY / USDJPY / EURJPY / GBPUSD / ETHUSD | Instant・パール・A案・C案・速攻プロ・D案・非FX |
| v4 | USDJPY / NZDUSD / AUDUSD / GBPJPY | Instant・パール・C案・速攻プロ・D案 |
| v4nfx | BTCUSD | 非FX |
| Hold | GER40 / UK100 / WTI | D案・非FX |
| MonThuS | USDCHF | A案 |
| RSI2a / RSI2b | GBPUSD / GBPJPY | A案 |

季節RG3(14074882)は再構築不可(docs/199)のため対象外。

## 2. データと手順

- Yahoo: 既存キャッシュ(`research/data/`、選抜に使ったもの)。Dukascopy: BID 日足 GMT(`tools/dukascopy_fetch.py`、2015-06〜2025-12)。
  Dukascopy は 2026 年分が無いため**窓は 2016-01-01〜2025-12-31**(120 ヶ月)。
- Dukascopy CSV → `data_duka_rf/<sym>_rf.csv` に変換し、`base.DATA` を差し替えて**同一のセル生成式**(`deployed_book.leg_series`)を走らせる。
  暗号資産は週末行を保持(base.load_daily の CRYPTO 扱いに合わせる)。祝日フラット行は除去。
- レグ毎: 日次相関・月次相関・累積(両ソース)・稼働日数。口座毎: 合成(倍率抜き)の月次相関・累積・maxDD。

## 3. 判定(レグ毎・固定)

| 判定 | 条件 |
|---|---|
| **再現** | 月次相関 ≥ 0.80 かつ累積の符号一致 |
| 部分再現 | 0.60 ≤ 月次相関 < 0.80(符号一致) |
| **不一致** | 月次相関 < 0.60 または累積の符号不一致 → **最優先の問題**として当該口座の倍率再校正を提案(実行はユーザー判断) |

口座合成は月次相関 ≥ 0.85 を「再現」とする。不一致が 1 レグでも出れば docs/185 §5(9 月は追加投資ゼロ)を維持したまま、
当該レグを含む口座を 9 月末の再スクリーニング(docs/184)の優先対象にする。
