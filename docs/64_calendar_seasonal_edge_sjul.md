## 0. 一行結論

> 未トライ土俵を N=164・Bonferroni で一括検定 → **Bonferroni生存=0件**(v7/E-Mon 自身と同じ天井)。
> プレ祝日・年末年始は**エッジ無し**。唯一クリーンに生き残った系統が **株価指数の「7月ロング」= S-Jul**。
> S-Jul(US500+NAS100) は **★年次ブロックp=0.0045・陽性年80%・最悪年−0.4%・maxDD−5.7%**、
> しかも **E-Mon(指数月曜)と相関 −0.31(負)** ＝ 既存の指数スリーブに対する**真の分散源**。
> 級は **SEASONAL-LEAD**(STRONG-LEADの亜種・サテライト限定)。**ADOPT ではない**(下記の限界)。

## 1. なぜ「曜日・月末以外」なのか — docs/14/50 が残した穴

| 既往探索 | 検定したカレンダー軸 | 生存 |
|---|---|---|
| docs/14 (FX, N=54) | 曜日 / 月末(TOM) | 円月曜(v7) のみ |
| docs/50 (指数/暗号/コモ/相対価値, N=130) | 曜日 / 指数TOM / 相対価値 | 指数月曜(E-Mon) のみ |

両者が触れたカレンダー軸は **曜日と月末の2つだけ**。古典的アノマリーには他にも系統がある:
- **プレ祝日効果**(Ariel 1990 / Lakonishok-Smidt 1988): 市場休場の直前営業日のリターンが異常に高い。
- **年末年始 / サンタクロース・ラリー**: 12月最終数日〜1月初の上昇。
- **月別シーズナリティ**(Sell-in-May / 11-4月=Best Six Months / 1月効果 / 夏枯れ): 暦月ごとのドリフト差。

これらは本プロジェクトで**一度も検定していない**(`grep` で docs/research 全体に "holiday/santa/sell-in-may/month-of-year" の語が皆無 ＝未トライを確認)。本書がその穴を埋める。

## 2. ハーネス設計(既存と同一・盛らない)

- データ: 指数 US500/NAS100/GER40/UK100/JP225 + 金 XAUUSD の **Yahoo日足10年**(`fetch_calendar.py`)。
- トレード定義(リポジトリ統一): trade_date の **open → 翌 trade_date の open**(o2o, 1営業日保有)。往復コスト bps 控除。
  プレ祝日は**休場をまたいで**翌寄付決済(プレ祝日+休場明けギャップを取る)。
- 候補(事前登録, N=164):
  - **H プレ祝日**: 各資産の自前カレンダーの「平日ギャップ」から休場を**自動検出**(ハードコード無し=再現性)。L/S。
  - **Y 年末年始**: 12月最終5営業日 + 1月最初2営業日。L/S。
  - **M 月別**: 各暦月を丸ごと保有(12ヶ月)＋ Best Six Months(11-4月)。L/S。
- 二次ハーネス: 順列検定 / IS-OOS(プール半割) / 全年ジャックナイフ / Bonferroni(α=0.05/164=**0.000305**) / コスト感応(1×/2×/3×) /
  **★既存エッジとの月次相関 = v7(円月曜) と E-Mon(指数月曜) の両方**(候補が指数系→E-Mon冗長性チェックが肝)。
- **★年次ブロック順列p**: 単月季節性の**実サンプルは年数(10)しかない**。日次解像度の順列pは
  月内ドリフトの自己相関で**有意性を過大評価**しうる。そこで「1年=1観測」に集約した符号反転順列p を併記し、
  **こちらを主たる採点**とする(数字を盛らない核心)。

## 4. S-Jul の v7基準9ゲート採点(docs/40 と同一ゲート)

**S-Jul = US500 + NAS100 の 7月 open→翌open LONG 等加重**(指数2つのバスケット)。

| # | ゲート | 合格条件 | **S-Jul 実測** | 判定 |

## 5. ★最重要の但し書き — 「数字を盛らない」(単月季節性の構造的弱点)

- **実サンプル = 年数(10)。** v7/E-Mon は週次の月曜が10年で約500サンプル。S-Jul は**7月が10回しか来ない**。
  年次ブロックp=0.0045 は良い数字だが、**10標本ベース**である事実は動かせない。
  → ∴ **ADOPT(確証)には絶対に上げられない**。級は **SEASONAL-LEAD**(STRONG-LEADの亜種・サテライト限定)。
- **日次pは過大評価しうる**(月内ドリフトの自己相関)。本書が年次ブロックpを主採点にしたのはこのため。
- **1ヶ月保有=スワップ累積が大きい**。指数CFDのロング1ヶ月保有はスワップ負け・配当調整の影響を受ける。
  Yahoo日足は**配当除く・bps単純化**＝**実CFDコストはこれより重い可能性**。→ デモで実スワップ/配当/スプレッドを実測必須。
- **レジーム依存の可能性**: 2016–2025 は概ね株式の強気相場。7月効果が**弱気相場でも続く保証はない**(E-Monの2020依存・v7のレジーム注記と同じ正直さ)。
- ∴ **S-Jul はサテライト(小サイズ)に限定**。主軸は引き続き v4(ADOPT)/v7/E-Mon。季節性は"足す"もので主軸にしない。

## 6. ポートフォリオへの組込み(銘柄＆手法の提案)

S-Jul は**通年では発火しない**(7月のみ)ので、リスク加重の常時配分(docs/54のP-A〜P-E)には乗らない。
正しい使い方は **「休眠リスク予算を使う季節性オーバーレイ(サテライト)」**:

| 提案 | 中身 | 狙い |
|---|---|---|
| **P-A+S(既存1口座に重畳)** | 既存 P-A(v7:v4:E5:E-Mon) に、**7月だけ** S-Jul を月次リスク **≤1%** で重畳 | 11ヶ月休眠の予算を7月に使う。E-Mon相関−0.31ゆえ7月の指数月曜が弱くても季節ドリフトで補完 |
| **並行B+S(並行口座に重畳)** | 並行 E-Mon+E5 口座に、7月だけ S-Jul を重畳 | 並行ポートの指数スリーブに、E-Mon と逆相関の季節脚を足す(同一資産クラス内の分散) |

- **サイズ**: 季節性=**月次リスク1%**(サテライト)。主軸ガード(equityフロア−8%/日次−4%)の内側で建てる。
  S-Jul の素 maxDD は−5.7%だが、サテライト小サイズなら合算DDへの寄与は僅少。
- **発火が他系統と重ならない**ため、合算の左尾(同時DD)を増やさず、7月だけ期待リターンを底上げする「ほぼ無料の分散」。
- **S-Nov は採らない**(E-Mon相関+0.55=冗長)。どうしても通年で季節性を厚くしたい場合のみ、冗長承知で任意。

### 8.3 読み解き（数字を盛らない）

- **効果は「速さ寄り」で小さめ**。中サイズ(月1+2.4pt)で **3ヶ月以内通過が 38.0%→40.6%(+2.6pt)・失格 6.1%→5.6%(−0.5pt)**。
  フル脚(+4.9pt)で 38.0%→43.4%(+5.4pt)・失格5.2%。**「中央値を縮める」より「早期通過の山を厚くする＋わずかに失格減」**。
- **サテライト(≤1%)はほぼ誤差**(3内+1.2pt・失格−0.2pt)。体感効果を出すには **7月だけ中サイズ(2〜3%相当)** が要る。
- **損益非対称は良好(イン・サンプル)**: S-Jul7月の最悪は−0.40%。フル脚でも月1の下振れ≈−0.6pt vs 上振れ+4.9pt。
  ∴ **7月開始の月1だけ厚くするのは"割が良い"**。ただし下記の限界つき。

### 8.4 限界と運用上の鉄則

- **中央3/4ヶ月狙いは p95DD −15〜−19%＝−10%枠の1.5〜2倍**で回す高失格運用(docs/63: 口座喪失前提)。
  **S-Julの月1上乗せはこの前提を変えない**。**失格を本気で下げるのはガード強化(docs/60)**で、S-Julは速度施策。
- **2016–2025の7月に大暴落が無い**=S-Julの薄い下振れは楽観。7月だけ厚くするなら **日次−4%・フロア−8%の
  ハードガード必須**(本EAは実装済み)。
- ∴ **推奨 = 既存P1を中央4ヶ月運用(×1.47・失格6.1%)で回し、来月7月だけ S-Jul を中サイズに自動増量**。
  3ヶ月以内通過を ~38%→~41% に底上げしつつ失格も僅減。EA側は `InpJulyBoostMult` で7月のみ自動増減(下記)。

### 8.5 EA対応（7月だけ中サイズへ自動増減）

- `mql5/Chien_Seasonal_Index_EA.mq5` に **`InpJulyBoostEnable` / `InpJulyRiskMult`** を追加。
  7月は `InpMonthRiskPct × InpJulyRiskMult` の実効リスクで建てる(既定 1.0% × 2.5 = 2.5% ≒ 中サイズ)。
  他の季節月(併用時の11月など)は素の `InpMonthRiskPct` のまま=7月だけ厚い運用が自動化される。
- プリセット `mql5/presets/seasonal_sjul_p1overlay.set` ＝ P1重畳・7月中サイズ既定(月1.0%×2.5)。
