> 方法: register_metrics と同じレグ DB(研究系列 2021-10〜2026-08・Yahoo 日足近似・ロールは Dukascopy H1)。帳簿全体を倍率で比例スケール(EA 内部の比率は現行のまま)。5 日ブロック・ブートストラップ MC 5,000 本 × 250 営業日。日次ガードは日次リターンの下限クリップ、床は初期残高比の静的線。年別サブサンプル(2022〜2026・各年の日だけからブートストラップ)の最悪年失格率を併記。
> 採用規則(事前指定・docs/322): **最悪年でも失格率 ≤ 10% の中で到達率最大**。

## 1. 読み方の注意

- 「失格」= 床到達。床 10% の行は**業者の失格そのもの**。床 8%・9% の行は EA が先に止める確率(口座は残る。#531343523 の −8% 停止と同じ状態)で、業者失格より大きく出る。業者失格だけを比べるなら床 10% の行を見る。
- 日次ガードのクリップは「その日の損失がガード値で止まる」仮定で楽観側(ギャップは抜ける)。倍率が高いほど差が大きい。
- Fintokei の EA が持つ残高ガード −2.8%(全決済)は格子に入れていない(別機構)。
