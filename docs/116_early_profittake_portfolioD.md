### なぜPDでだけ効くのか(機序・誠実な読み方)
- **T2は「月内で+1%以上乗った後にピークから1.5%押した」時だけ発動**する(発動率9.2%=約1年に1回)。
  PDの最悪月中DD(−7.28%)は「上がってから崩れる」形の月で起きており、T2がその経路を正確に切る
  → **最悪月中DDが半減(−7.28→−3.78%)し、校正倍率が0.88→1.16(+32%)に上がる**。
  平均月利の犠牲(0.398→0.361%)を倍率上昇が上回り、校正後期待月利+19.7%。
- 季節EA(R4)は月別に集中配分するため、テール月は「最初から落ちる」形が多くトレーリングが切れない
  (docs/115: mult不変)。**同じルールでも土台の分布形状で価値が変わる**という教科書的な例。
- パラメータはフォールド間で安定(押し幅1.5%が10フォールド中9・2022のみ1.0%)。
- T1(固定閾値)はPDでは**逆効果**(0.311 < 0.350)= 「利益が出たら閉じる」単純ルールはPDでも損。
  効くのは**トレーリング(利益を守る)**であって**利確(利益で逃げる)ではない**。

## 4. 実装(事前登録 §4 の手順どおり)

`Chien_PortfolioD_Prop3.mq5` **v1.30** に **月内トレーリング・ロック(MONTH_TRAIL)** を新設。
**既定OFF・既存動作は完全不変**。ONにすると:

- 月初来リターン MTD = (equity − 月初equity) / 基準残高 ×100 を監視(端末GVで再アタッチ耐性)
- 月内ピークMTD ≥ **アーム 1.0×k %**後、**ピーク−1.5×k %**まで押したら**全決済+当月新規停止**
  (翌月月初に自動解除・プッシュ通知 `MONTH_TRAIL` あり)
- 入力: `InpMTrailEnable`(既定false) / `InpMTrailArm1x=1.0` / `InpMTrailGiveback1x=1.5`
  (**検証済みの研究1x単位=変更しない**) / `InpMTrailScale=k`(既定1.1)
- **k = 口座の月次PnLスケール ÷ 研究1x**。docs/87式のガード校正口座(フロア−8%逆算)なら
  k≈8/7.28≈1.1=既定値。サイズを上げた運用では比例して上げる(例: 2倍サイズなら k=2.2)。
- フロア/PASS_LOCK/日次ガードは従来どおり独立に先行評価(状態機械の優先順は不変)

**運用順序(docs/114 §4)**: ①この版を**デモのPD口座でON**にして並走 → ②発動挙動・通知を確認
→ ③実口座は次フェーズ開始時からON(走行中フェーズの設定は変えない)。

## 5. 既知の限界

- Yahoo日足終値解像度: 実運用はティックでピーク/押しを見るため**発動はやや早まる**(保守側=押し幅を
  深めに取る現行1.5%設定が無難)。
- E-Mon[RG3]ゲートなしのプロキシ(docs/114 §6)。ゲートは risk-off 月の露出を減らす方向で、
  T2の価値(上げ→崩れ経路の遮断)と同方向のため**過大評価の懸念は限定的**だが、デモ並走で確認する。
- 発動は10年で11回相当(9.2%)= フォワードでの統計的確認には時間がかかる。デモで見るのは
  「発動が仕様どおりか」であり「エッジの再確認」ではない(それは月次採点 docs/98/103 の仕事)。
