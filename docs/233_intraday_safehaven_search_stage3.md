## 6.【追補】1 時間刻みの分解 — 窓の細分化は bid 建て H1 では不可能(第 4 弾の制約)

月〜木・1h SHORT の平均(bps/回・コスト無し)。左 = 2016-01〜2021-09 / 右 = 2021-10〜2026-08。

| 銘柄 | 20 UTC | 21 | 22 | 23 | 00 | 16-19 |
|---|---|---|---|---|---|---|
| USDCHF | +1.0 / +2.4 | +1.0 / +1.4 | **−0.8 / −1.3** | **−0.5 / −1.2** | −0.5 / +0.3 | ≈0 |
| NZDUSD | +2.3 / +2.4 | −0.4 / +0.2 | −0.7 / −1.1 | −1.0 / −1.4 | +0.5 / +0.2 | ≈0 |
| AUDUSD | +1.4 / +1.7 | −0.4 / −0.0 | +0.4 / −1.4 | −1.1 / −0.8 | +0.8 / +0.8 | ≈0 |
| AUDJPY | +1.5 / +4.1 | −0.3 / 0.0 | +0.6 / −2.6 | −1.0 / −0.7 | +1.3 / +1.3 | ≈0 |

- 動きは **20→21 UTC に集中し、22〜23 UTC で半分戻る**。
- **21〜23 UTC の bar open は bid のみで、この時間はスプレッドが 3〜13 pip に開く(docs/216)ため bid が押し下げられる**。1h 刻みの「20→21 で儲かり 22→23 で戻す」は、その大半が bid の一時的な沈み込みと回復で、**約定可能な値ではない**(SHORT の決済は ask で行うため)。
- 4h 窓(20→00)は両端がスプレッド正常時刻なので**このアーティファクトを含まない**。§2〜4 の結論は変わらない。
- ただし **窓を 1h 単位で最適化することはできない**(21〜23 UTC を端点にする窓は全て汚染される)。窓の細分化には bid/ask 両方のティックデータが要る。
