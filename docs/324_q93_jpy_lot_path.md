# 324. Q93 円建て口座のロット計算経路 — 偽 SIZE SANITY の原因は業者の tick 値が損益通貨建てなこと。損益経路を正にした v+0.01 を 3 本用意

> docs/322 Q93(工学・セル 0)。2026-10-05 実行。配備(`ops/config/deploy_manifest.json`)と台帳(docs/241)は変更しない。差し替えはユーザーの「切替」後。

## 1. 症状と原因

- トパーズ #6104739(JPY 口座)の EA11 v1.10 は起動のたびに `⚠[SIZE SANITY UK100p] tick値経路 $1.00 vs 損益経路 $208.15 (乖離208.2倍)`・`USOILp $1000 vs $157,555 (157.6倍)` を出していた(docs/241 §1u・ダイジェスト既知警告)。
- `MoneyPerUnit()`(v1.32・docs/153)は 2 経路を比べて大きい方を採る: (a) `SYMBOL_TRADE_TICK_VALUE / TICK_SIZE`、(b) `OrderCalcProfit` から逆算。
- 原因: AXSE(Fintokei)は **tick 値を損益通貨建て(UK100p = 1.00 GBP・USOILp = 1,000 USD)で返し、口座通貨(JPY)に換算していない**。(b) は換算済み(GBPJPY 208.15・USDJPY 157.56 がそのまま乗っている)。乖離倍率 = 為替レートそのもの。
- 実害: 円口座では `max(a,b)` が (b) を選ぶので**ロットは正しかった**(検算: UK100p 名目 ¥861 万 ÷ (208.15 × 10,650.82) = 3.88 ロット = 実建玉、USOILp 0.17 = 実建玉)。もし (a) を使っていれば 808 / 28 ロット(208 / 165 倍)で即失格だった。逆に**口座通貨が損益通貨より強い場合(EUR 口座 × USD 銘柄など)は未換算の (a) が大きくなり max が (a) を選んで過小ロット**になる。警告が毎回出ることで本当の異常が埋もれる点も問題。

新 `MoneyPerUnit`: (b) 損益経路を**正**とする。(a) は `SYMBOL_CURRENCY_PROFIT → 口座通貨` の相場(`ResolveSymbol(pc+ac)` または逆数。接尾辞 p は全銘柄走査で解決)で換算してから比較し、換算後も 1.5 倍以上ずれる時だけ `[SIZE SANITY]` を出す。(b) が取れない時だけ換算後の (a) を予備として使う(その場合も 1 回ログ)。他の 3 本(FN / FTMO の EA)は USD 口座 × USD 建て銘柄が主で乖離は出ていないが、同じ関数を持つので 11 月の include 化(Q95)で共通化する。

検算(10/1 のログ値): 旧 max 経路 = 新経路 = 実建玉(UK100p 3.88 / USOILp 0.17)。**ロット値は変わらない。変わるのは警告と、強通貨口座での過小ロットの余地**。
