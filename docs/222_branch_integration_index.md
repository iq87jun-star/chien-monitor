# 222.【統合記録 2026-09-12】2 ブランチの doc 体系を 1 本に統合した

## 1. 何が起きていたか

2 つのブランチが **共通の祖先を持たない独立した履歴**で並走し、同じ doc 番号に別の内容を割り当てていた。

| ブランチ | 性格 | doc 範囲 |
|---|---|---|
| `claude/prop-trading-new-methods-a8y3l1`(本ブランチ) | 研究・新手法の探索 | 176〜218 |
| `claude/ea-code-review-integration-p8p06z` | 運用・配備・書面回収 | 176〜188 |

`git merge-base` は空を返す(=共通祖先なし)。docs/176〜178・180・182 は両者同一だったが、
**179・181・183・184・185 は内容が食い違い**、**186・187・188 は同じ番号に全く別の文書**が置かれていた。

この分散が実害を出した: 2026-09-12 に「D案 EA は未差し替え」「次口座の候補は…」と回答した際、
レビュー側ブランチにある **D案 v2 の訂正再配備(9/02)** と **4社目の横断調査(§7〜10)** を参照できていなかった。

## 2. 統合の方針

- **本ブランチ(研究側)を正とし、レビュー側の内容を取り込む。** 研究側の doc 数が多く、番号の付け替えコストが小さいため。
- レビュー側が明確に新しい **179・181・183** はレビュー側の版で置換。
- **184** はレビュー側の訂正版(§6)を採用し、バグの技術的記録 docs/192 への参照を §7 として追記。
- **185** は両側の固有部分を統合(レビュー側 §1〜10 + 本ブランチの docs/200 上書き注記・§10b・§11)。
  §11 は §7〜9 を踏まえた改訂版に書き直した。
- 番号が衝突する 3 本は改番して取り込んだ。

| 旧(レビュー側) | 新(統合後) | 内容 |
|---|---|---|
| docs/186 | **docs/219** | 月次採点 2026-08(docs/179 ランブック初回実行) |
| docs/187 | **docs/220** | Fintokei サポート書面記録 全7回(2026-07-28〜09-02) |
| docs/188 | **docs/221** | 別名義フル配分の設計案(**思考実験・実行対象外**としてアーカイブ) |

取り込んだ 6 ファイル内の `docs/186-188` 参照は 219-221 に張り替え済み。
本ブランチ側の docs/186〜188(選抜価値の事前登録・結果・市場中立)は**番号も内容もそのまま**。

EA も 1 本取り込んだ: `mql5/【FTMO50k_口座521100397】RecentFit_D3m_202609v2_5.24倍.mq5`。

## 4. 今後の運用

- **doc 番号は本ブランチで一元採番する。** 新規は 223 から。
- レビュー側ブランチで作業する場合は、番号を取る前に本ブランチの最大番号を確認する。
- 運用系(配備カード・書面記録・月次採点)と研究系(事前登録・結果)が同じ連番に混在するが、
  分けると今回と同じ分散が再発するため**あえて 1 本の連番で運用する**。
