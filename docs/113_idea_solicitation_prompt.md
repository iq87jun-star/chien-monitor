### 依頼: 新しいEA/改善の**アイデアを最大20個**出し、下記の型でトリアージして提出

**受け付けるレーン(この4つのみ)**:
- **L1 器・実装系**: 検証済み5エッジの新しい載せ方(口座構成・ガード・執行・通知・業者最適化・
  資金化後モード等)。バックテスト不要のものは最速で採用可能。
- **L2 新データ源**: まだ検定していないデータが**現実に入手可能**な場合のみ(例: 限月別先物=基差/
  キャリー、オプションIV、個別株、センチメント/ポジショニング(COT等)、オーダーフロー)。
  「入手手順」まで書けないアイデアは不可。
- **L3 既存エッジの機序深掘り**: 5本の機序(フロー・カレンダー)から演繹される**隣接仮説**で、
  棄却済み領域(下記)に入らないもの。
- **L4 運用・資金系**: 口座数・業者分散・出金・スケーリング(docs/58/77/78の改善)。

**禁止(トリアージで自動却下)**:
- 棄却済み領域への回帰: FX日中H1・非JPY曜日効果・月末月初・リードラグ・FXキャリー・平均回帰単体・
  ハロウィーン/発表日・VIXゲート・商品/債券の日足TSMOM(docs/14〜93, 107)
- 同じ日足/H1宇宙(FX9・主要指数・金)の再探索、パラメータいじり直し
- 市販EA/ロジック非公開のものの導入
- 「p値が良い」だけの提案(F2の教訓: プラセボ=ベータの言い換え検査を常に想定すること)

**提出フォーマット(アイデア1件につき)**:
```
ID: 仮名(例: idea-L2-01)
レーン: L1〜L4
一行仮説: 何が・なぜ効くと考えるか(機序を1文で)
必要データ/インフラ: 具体的な入手手順(URL/API/MT5機能)。L1/L4は「不要」で可
棄却済み領域チェック: docs/14-93,107,109のどれと近いか・なぜ別物か(最重要欄)
事前分布: 高/中/低 + 根拠(文献 or 既存エッジとの機序連続性)
検証計画の骨子: 事前登録するならどのゲート(docs/80 §5標準)をどう通すか
期待効果の桁: 月+何bp級か(盛らない・不明なら不明と書く)
```

### 規律(このプロジェクトの憲法・違反禁止)
- 本セッションでは**バックテストを実行しない**(アイデア出しとトリアージのみ)。
  実行は生き残り案の事前登録(docs/114以降)がコミットされた後の別作業。
- 数字を盛らない。過去docsの数値は転記のみ・出典必須。
- 全20案のうち**自信のある上位3案**を選び、その3案だけ詳細化(却下17案も一覧は残す=
  「試して駄目だった/考えて却下した」の記録が将来の再発明を防ぐ)。

成果物: `docs/113a_idea_batch1.md`(全案一覧+上位3詳細)をコミット。実装・検証はしない。

## 本docの位置づけ(このセッション側の記録)

- アイデア募集は「探索再開」ではない。**実行の門番は事前登録**(docs/114以降)であり、
  募集セッションにはバックテスト実行権を与えない設計にしてある。
- 却下されたアイデアの一覧も保存させる(negative spaceの地図を太らせる)。
- 有望案が出た場合の流れ: docs/113a → ユーザー選択 → 事前登録(docs/114) → ハーネス実行 →
  結果doc → (合格時のみ)EA化 → デモ。
