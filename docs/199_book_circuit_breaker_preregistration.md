# 199.【事前登録】現ブック全体の同時失格MC — 相関ペナルティのポートフォリオ側の利益を測る

> 2026-09-01作成。費用ゼロの研究(docs/185 §5適合)。
> docs/198 §3が「判断に必要だが本docに無い情報」として明示した欠落を埋める。
> 本docのルールは`research/book_circuit_breaker_mc.py`の実行**前**に凍結した。実行後の変更禁止。

## 1. 動機 — 片側のコストだけが分かっている状態

現状の情報は非対称である:

| 測ったもの | 出典 | 内容 |
|---|---|---|
| ポートフォリオ側の**利益** | docs/193 §8 | CB発火 20.85%→2.82%。ただし**口座A=4セル1口座**という別構成 |
| 単体口座の**コスト** | docs/198 §2 | 全ブック基準・C案規則で資金化 64.3%→46.2%(λ=1.0) / →58.8%(λ=0.5) |

**同じ構成(全ブック基準・C案規則)で利益とコストを並べた表が存在しない。**
λ=0.5はその不確実性下での中間解として選ばれており(docs/197 §8.4)、最適値の主張ではない。
本研究はその表を作る。

## 2. 測る対象(実行前固定)

> **docs/185 §2のサーキットブレーカー発火確率**
> = P(30日以内に2口座以上が失格)

これはdocs/185が自ら「全トラックの再起・新規購入を凍結」する条件として定義した事象であり、
ポートフォリオ層の目的関数として最も直接的である。

## 3. 方法(実行前固定)

1. **口座集合**: `research/deployed_book.py` の7口座(§6の限界を参照)。
2. **操作する変数はC案口座のレッグのみ。** 他6口座の構成・倍率は固定する。
   C案を λ=0版 / λ=0.5版(docs/197 §8)の2通りで差し替えて比較する。
3. **同一のブートストラップ・ブロックを全口座に適用する**(docs/193 §4と同じ思想)。
   独立に引くとクロス相関が消え、測りたいものが消える。5日ブロック・シード7・1万パス。
4. **失格判定は口座ごとの業者規則で行う**:

| 口座 | 規則 | 失格条件 |
|---|---|---|
| FTMO 100k(A案) / 50k×2(C案・D案) | 2-Step P1+10%→P2+5% | フェーズ基準から**静的−10%** |
| FN 100k(非FX) | Stellar 2-Step P1+8%→P2+5% | 同**−10%** |
| Fintokei パール500万(B案) | P1+8%→**P2+6%** | 同**−10%** |
| FN Instant 20k | 目標なし(資金化済) | **トレーリング−6%**(HWM基準・口座喪失) |
| Fintokei 速攻プロ2000万 | +6%単段 | **静的−3%** または **60営業日で未達=時間切れ失格**(docs/183 §1) |

5. **EA日次ガード**: 全口座に日次クリップを適用する。**速攻プロのみ−1.5%**(docs/183 §3の
   balance−1.5%全決済)、**他は−4%**(v1.44系)。
6. **地平**: 250インデックス日。速攻プロのみ60営業日で打ち切り(時間切れ=失格)。
7. **基準日**: docs/198と同じ6日(2025-09-30 / 2025-12-31 / 2026-03-31 / 2026-05-29 /
   2026-06-30 / 2026-08-31)。各基準日でC案を選抜し直し、結果は6日の平均で読む。

## 4. 出力(実行前固定)

| 指標 | 定義 |
|---|---|
| **`P_circuit_breaker`** | 2口座以上が失格し、その失格日の**最大差が30日以内**の組が存在する確率 |
| `P_any_fail` | 1口座以上が失格 |
| `E_failed_accounts` | 失格口座数の期待値 |
| 口座別失格率 | 7口座それぞれ |
| `rho_C_vs_rest` | C案と「C案を除くブック合成」の相関(選抜窓) |

これらを **λ=0 と λ=0.5 の2通り**で出力し、docs/198 §2の単体コスト表と**同じdocに並べる**。

## 5. 解釈規則(実行前固定・後知恵の禁止)

| 結果 | 判定 |
|---|---|
| λ=0.5 が `P_circuit_breaker` を**相対20%以上**下げる | λ=0.5の採用を支持する証拠。docs/197 §8を維持 |
| 低下が相対20%未満 | **λ=0.5の根拠が弱いことを記録し、ユーザーへ再提示**する(当方で撤回しない) |
| `P_circuit_breaker` が上がる | 同上。ペナルティが逆効果である可能性を明示して再提示 |

- **どの結果でも稼働中8口座は変更しない**(docs/174 §1・docs/179 §4)。
- **λの値を本結果から最適化しない。** {0, 0.5, 1.0}の3点以外は評価しない(docs/197 §8.4の規律)。

## 6. ⚠ 承知している限界(実行前に明示)

1. **FN100k #14074882(季節RG3・$100k)が含まれない。** 生成式が再構築できないため(§6.1)。
   本研究のブックは実ブックより**FX集中が強い**方向に偏っており、
   **CB発火確率もペナルティの効果も過大に出る可能性がある。**
2. **速攻プロのFintokei「トレードグループ3%」警告(docs/176 §7.5.1)は実装しない。**
   失格ではなく警告であるため(docs/176 §7.5.2の書面)。
3. インデックス日には暗号セルの週末が含まれる(非FX口座を含むため)。
   「30日」はインデックス日換算であり暦日ではない。**λ間の比較には影響しない**(同一インデックス)。
4. ブロックブートストラップは系列相関を5日までしか保存しない。危機時の相関収斂は再現されない
   (docs/193 §6と同じ限界)。

### 6.1 季節RG3が再構築できない理由(調査結果の記録)

2026-09-01に他ブランチを調査した結果:

- **RG3ゲートの定義は特定できた**: `research/edge_regime_gate_10y.py`
  (ブランチ `claude/fundednext-portfolio-strategy-wuibur`)。
  「E-Monバスケット(NAS100/US500/GER40)の過半が前日終値<SMA200(D1) **かつ**
  20日実現ボラが直近252日の80分位超 の週だけ月曜建てを見送る」(docs/68 §1)。
- **配備の記述も特定できた**: docs/172 §1(ブランチ `claude/prop-trading-ea-short-term-8ta3be`)
  「FN100k #14074882 = 季節R4+G3(EMon/EMonXにRG3ゲート追加)・1.0x・Magic 940900」。
- **しかし「季節R4」スリーブ本体の定義と、そのイン・サンプル月次重みが得られない。**
  docs/172 §2は「季節の数字は**イン・サンプル月次重みを含む**(LOYO正直値≈2/3, docs/166)」と
  記しており、月別の重みテーブルが構成の中核である。これはdocs/166系に属し、
  本調査では所在を確定できなかった。

→ **推測で再構築すると ρ_book の基準が誤るため行わない。**
含めるには「季節R4の研究コードを本ブランチへ移植する」という独立したタスクが必要であり、
その工数と価値の判断はユーザーに委ねる(docs/199 §7)。
