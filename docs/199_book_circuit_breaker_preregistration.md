## 1. 動機 — 片側のコストだけが分かっている状態

現状の情報は非対称である:

| 測ったもの | 出典 | 内容 |
|---|---|---|
| ポートフォリオ側の**利益** | docs/193 §8 | CB発火 20.85%→2.82%。ただし**口座A=4セル1口座**という別構成 |
| 単体口座の**コスト** | docs/198 §2 | 全ブック基準・C案規則で資金化 64.3%→46.2%(λ=1.0) / →58.8%(λ=0.5) |

**同じ構成(全ブック基準・C案規則)で利益とコストを並べた表が存在しない。**
λ=0.5はその不確実性下での中間解として選ばれており(docs/197 §8.4)、最適値の主張ではない。
本研究はその表を作る。

## 2. 測る対象(実行前固定)

> **docs/185 §2のサーキットブレーカー発火確率**
> = P(30日以内に2口座以上が失格)

これはdocs/185が自ら「全トラックの再起・新規購入を凍結」する条件として定義した事象であり、
ポートフォリオ層の目的関数として最も直接的である。

## 3. 方法(実行前固定)

1. **口座集合**: `research/deployed_book.py` の7口座(§6の限界を参照)。
2. **操作する変数はC案口座のレッグのみ。** 他6口座の構成・倍率は固定する。
   C案を λ=0版 / λ=0.5版(docs/197 §8)の2通りで差し替えて比較する。
3. **同一のブートストラップ・ブロックを全口座に適用する**(docs/193 §4と同じ思想)。
   独立に引くとクロス相関が消え、測りたいものが消える。5日ブロック・シード7・1万パス。
4. **失格判定は口座ごとの業者規則で行う**:

| 口座 | 規則 | 失格条件 |
|---|---|---|
| FTMO 100k(A案) / 50k×2(C案・D案) | 2-Step P1+10%→P2+5% | フェーズ基準から**静的−10%** |
| FN 100k(非FX) | Stellar 2-Step P1+8%→P2+5% | 同**−10%** |
| Fintokei パール500万(B案) | P1+8%→**P2+6%** | 同**−10%** |
| FN Instant 20k | 目標なし(資金化済) | **トレーリング−6%**(HWM基準・口座喪失) |
| Fintokei 速攻プロ2000万 | +6%単段 | **静的−3%** または **60営業日で未達=時間切れ失格**(docs/183 §1) |

5. **EA日次ガード**: 全口座に日次クリップを適用する。**速攻プロのみ−1.5%**(docs/183 §3の
   balance−1.5%全決済)、**他は−4%**(v1.44系)。
6. **地平**: 250インデックス日。速攻プロのみ60営業日で打ち切り(時間切れ=失格)。
7. **基準日**: docs/198と同じ6日(2025-09-30 / 2025-12-31 / 2026-03-31 / 2026-05-29 /
   2026-06-30 / 2026-08-31)。各基準日でC案を選抜し直し、結果は6日の平均で読む。

## 6. ⚠ 承知している限界(実行前に明示)

1. **FN100k #14074882(季節RG3・$100k)が含まれない。** 生成式が再構築できないため(§6.1)。

   「30日」はインデックス日換算であり暦日ではない。**λ間の比較には影響しない**(同一インデックス)。

# 8.【結果 2026-09-01】λ=0.5 はブック全体のCB発火を下げなかった

> `research/results/book_circuit_breaker_mc.json`・シード7・1万パス・6基準日の平均。
> **判定(docs/199 §5): 低下は相対20%未満(実測は+1.2%=むしろ微増)。
> → λ=0.5の根拠が弱いことを記録し、ユーザーへ再提示する。当方では撤回しない。**

## 8.1 主結果

| | λ=0(従来規則) | **λ=0.5(採用値)** | 変化 |
|---|--:|--:|--:|
| ρ(C案 vs 残りブック) | 0.423 | **0.280** | −34%(狙い通り) |
| C案の倍率(平均) | 3.78 | 3.34 | −0.44 |
| **CB発火(30日以内に2口座以上失格)** | **54.33%** | **54.96%** | **+1.2%** |
| 2口座以上失格 | 83.8% | 84.1% | +0.3pt |
| いずれか失格 | 98.3% | 98.3% | ±0 |
| E[失格口座数] | 2.765 | 2.773 | +0.008 |

**相関は確かに下がったが、ブック全体の同時失格確率は動かなかった。**

## 8.2 なぜ効かないのか — 口座別の失格率

| 口座 | 失格率(λ=0) |
|---|--:|
| **Fintokei速攻プロ2000万** | **90.1%** |
| **FN Instant 20k** | **77.8%** |
| FN100k(非FX) | 36.5% |
| FTMO100k(A案) | 29.7% |
| FTMO50k(D案) | 19.9% |
| FTMO50k(C案) | 11.6% → 12.4% |
| Fintokeiパール(B案) | 11.0% |

**CB指標は上位2口座で飽和している。** 速攻プロ(静的−3%+60日時間切れ)と
Instant(トレーリング−6%・目標が無いため250日走り続ける)だけで
P(2件以上) ≈ 0.901 × 0.778 ≈ 70% に達する。C案の失格率を11.6%→12.4%動かしても、
この構造的な2件が支配する指標は動かない。

⚠ この90.1% / 77.8%は**バグではなく悲観バウンド(全期間サンプル)の帰結**である。
docs/183 §2は速攻プロの悲観側を「合格26.7%・プロ口座寿命中央44営業日」と記録しており、
250日地平で90%失格は整合する。Instantも docs/177 §2 が
「最悪=2018年型でトレーリング−6%接触=口座喪失」を承知の上での配備と記している。

## 8.3 感度分析(事後・判定には使わない)

飽和が原因かを切り分けるため、**チャレンジ型5口座のみ**(速攻プロ・Instantを除外)で再測定した
(`results/book_cb_sensitivity_challenge_only.json`):

| | λ=0 | λ=0.5 | 変化 |
|---|--:|--:|--:|
| CB発火 | 16.85% | 16.96% | **+0.6%** |
| 2口座以上失格 | 28.5% | 29.2% | +0.7pt |

**飽和を取り除いても効果は出ない。負の結果は頑健である。**

## 8.4 docs/193との違い — なぜあちらでは効いたのか

docs/193 §8.3で自ら記した通り、あの実験のベースラインは **ρ=1.000**
(口座Bが口座Aと完全に同一の構成)だった。**「同じ戦略を2口座に複製した状態を解消する」**
利益を測っていたのであり、それは巨大だった(CB 20.85%→2.82%)。

現ブックにその状態は存在しない。C案 vs 残りブックの相関は既に0.423であり、
これを0.280へ下げても、**7口座中1口座の相関を少し下げるだけ**では
ブック全体の同時失格は動かない。

**docs/193の結論は誤りではないが、その適用条件(完全な重複の解消)が現ブックには当てはまらない。**
docs/197 §3で私がその差を確認せずに全ブック基準を事前登録したことが、
docs/198 §2.1に続く2つ目の帰結である。

## 8.5 ⚠ 付随して判明した、より重要な問題 — docs/185のサーキットブレーカー設計

**現ブックでは、docs/185 §2のサーキットブレーカーが悲観バウンドで54%の確率で発火する。**

docs/185 §2はこの装置をこう定義していた:

> 30日以内に2口座以上が失格した場合、原因を問わず全トラックの再起・新規購入を凍結し、
> 全体postmortem(相関・レジーム・実装の3面)を完了するまで解除しない。
> 根拠: …複数同時失格は「個別の不運」ではなく共通要因の顕在化とみなすのが正しい事前確率

しかし §8.2 の通り、現ブックの同時失格は**共通要因の顕在化ではなく、
速攻プロとInstantという寿命の短い2口座が構造的にほぼ確実に失格すること**で生じる。
この2件が30日以内に重なれば、共通要因が何もなくても発火する。

**装置が検知したい事象(共通要因)と、実際に発火させる事象(短命口座の寿命到達)が一致していない。**
発火すれば「全トラックの再起・新規購入を凍結」が起動するため、実害がある。

これはdocs/185の改訂を要する論点であり、**本docの範囲外**として提起のみ行う。
考えられる方向(いずれも事前登録が必要):
- 短命設計と明記済みの口座(速攻プロ・Instant)を発火カウントから除外する
- 失格の**型判定**(docs/185 §1の型(a)/(b)/(c))を発火条件に組み込む
- 「2口座以上」を資金加重や口座数比率で定義し直す

## 8.6 ユーザーへの再提示(docs/199 §5の規定による)

λ=0.5には**測定されたコスト**があり、**測定された利益は無い**:

| | 出典 | 内容 |

選択肢(**ユーザー決定事項**・当方では撤回しない):

| 案 | 内容 |
|---|---|
| (a) λ=0.5維持 | 相関低下自体に価値を認める。ただし本docの範囲では利益を実証できていない |
| (b) **λ=0へ撤回**(TSMOM除外は維持) | 実証された利益が無い以上、−5.5ptのコストを払う根拠が無い。**TSMOM族の母集団除外(docs/197 §8.2)は実装可否による除外であり、λとは独立に維持する** |
| (c) 将来の重複時のみ発動 | 平時はλ=0とし、**新規口座が既存口座と高相関(例 ρ>0.7)になる場合に限り**ペナルティを適用する規則へ書き換える。docs/193が実証したのはまさにこの状況である |

**当方の見解は(c)** — docs/193が実証したのは「完全な重複の解消」であり、
それが起きるのは**同じ戦略を複数口座へ複製するとき**である。
現に Mon GBPJPY は最大5口座で並走しており(docs/193 §1)、
その状況にだけ効かせるのが実証範囲と一致する。ただし(c)は新しい規則であり、
採用するなら**発動条件を事前登録し直す必要がある**。
