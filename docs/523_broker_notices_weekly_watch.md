# 523.【登録・見張り】業者の告知を週 1 回確認する(FTMO・FundedNext・Fintokei)— 売買の合図ではなく、口座を守るための確認

2026-11-24 登録(ユーザー「Twitter系のアイデアは他にありますか」→ 業者の告知の見張りを提案 →「登録」)。記録は `research/forward/broker_notices_log.csv`。EA・マニフェスト・config は、この確認だけでは変えない(変更が要る場合は内容を報告し、ユーザーの「切替」の後に行う)。

## 1. ねらい
- 規約や取引条件の変更を、効き始める前に知る。これまでに、規約・条件が原因の警告や手戻りがあった(Instant のリスク警告、FTMO の出金時の口座変更、取引時間の扱い)。
- 売買の成績を良くするための検証ではないので、判定の期限は置かない。

## 2. 対象と確認する内容
| 業者 | 確認する場所 |
|---|---|
| FTMO | 公式サイトのお知らせ・取引条件の更新、公式の X の告知(報道・検索で拾える範囲) |
| FundedNext | 公式サイトのお知らせ・ヘルプの更新、公式の X の告知 |
| Fintokei | 公式サイト(日本語)のお知らせ、公式の X の告知 |

| 区分 | 例 |
|---|---|
| 規約の変更 | 損失の上限の数え方、利益の分配、出金の条件、EA・コピーの扱い、指標の前後の取引、同時保有のリスクの規則 |
| 取引時間・休場 | 祝日の取引時間、週末の扱い、指数・金の早じまい |
| 取引条件 | レバレッジ、スワップ、スプレッド、銘柄の追加・廃止・名前の変更、最小ロット |
| システム | サーバーの保守・移行、障害、取引ソフトの変更 |
| 料金・口座 | 料金、口座の種類の改廃、口座の移行 |

## 3. 手順(毎週・月曜 08:47 JST の確認に続けて行う)
1. 直前の 7 日間に出た告知を、公式サイトと報道の検索で探す(X そのものは読まない。有料の API を使わない)。
2. 見つけた告知ごとに、いまの口座と EA に関係があるかを判断する(関係あり / 関係なし / 判断できない)。
3. `research/forward/broker_notices_log.csv` に足す。該当なしの週は「該当なし」の 1 行。
4. 報告は「関係あり」と「判断できない」があるときだけ行い、何が変わるか・いつから・どの口座に関係するか・必要な対応を書く。
5. 公式の発表を確認できない話(噂・第三者の投稿だけ)は、記録に「未確認」と書き、対応の提案はしない。

## 4. CSV の欄
`checked_at_utc` / `firm` / `category` / `summary` / `effective_date` / `relevance`(関係あり・関係なし・判断できない・該当なし)/ `accounts`(関係する口座の呼び名)/ `action`(必要な対応の案)/ `sources` / `note`

## 5. 限界
- 検索で拾える範囲に限る。会員ページやメールだけで届く告知は拾えない(その場合は Gmail に届いた業者のメールを、ユーザーの指示があれば確認する)。
- 口座番号・残高・個人情報は書かない。本人確認(KYC)に関する問い合わせには答えない。
