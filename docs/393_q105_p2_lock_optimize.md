# 393.【Q105】P2 のロック値最適化 — 効くのは「ロック幅」ではなく「アーム幅」。Arm < Close の隙間(現行 0.15pp)は建玉なしで着地すると通過も再開もしない「滞留」を生み、到達率を 3.5〜12pt 下げる。**変更する(全 EA で `InpLockArmPct` = `InpLockClosePct`・入力のみ・v+0.01・「切替」後)**

> docs/322 Q105(診断・セル 0)。2026-11-03 朝 実行。スクリプト `research/queue/q105_p2_lock_optimize.py`、結果 `research/results/q105_p2_lock_grid.csv`(6 帳簿 × 25 格子 = 150 行)。
> 方法: Q85(docs/325)と同じ MC(研究系列 2021-10〜2026-08・5 日ブロック・5,000 本 × 250 営業日・日次ガードは下限クリップ・EA の全停止線で失格)。帳簿のレグを **イベント型**(Mon・Roll・ブレイク・v4: 建てて閉じる)と **連続型**(Hold: 常に建玉)に分け、EA の実装どおりに「gain ≥ Close → 全決済ロック(通過)」「gain ≥ Arm → 新規停止(毎 tick 再評価)」を日次で再現した。格子はロック幅 c = Close − 目標 ∈ {0.02, 0.05, 0.10, 0.20, 0.30}pp × アーム幅 g = Close − Arm ∈ {0, 0.05, 0.15, 0.30, 0.50}pp(現行 c 0.05 / g 0.15)。
> 保守性: 日次系列なので「建玉中に日中 equity が Close に触れて即ロック」は数えていない(実際の滞留確率は本表より小さい)。一方、滞留の定義「建玉なし・gain ∈ [Arm, Close)」は EA の実装そのもので、連続型レグの無い帳簿では解消する機構が無い。

## 1. 機構(EA の RecentFit 系・EA8/EA3/EA9/EA10/EA11 共通)

- `gain ≥ InpLockClosePct` → `CloseAllMine("PROFIT_LOCK")`・`g_passLocked`(通過)。
- `gain ≥ InpLockArmPct` → `blockNew`(新規停止)。Arm は毎 tick 再評価なので、建玉があって gain が Arm を割れば再開する。
- **建玉が無く gain ∈ [Arm, Close) に着地した場合**: 新規は建たず、equity も動かない → 通過も再開もしない。画面は `ARMED`、通知は `ARM +x% 新規停止` が 1 回。ダイジェストはこれを警告として拾っていない(docs/317 の alerts 語彙に ARM は無い)。
- イベント型だけの帳簿(トパーズ・ルビー・C6・FTMO 50k の Mon4)は月〜火以外は建玉なしなので、この着地が起きうる。連続型(Hold)を持つ帳簿(531343523・14074882・1-Step)は Hold の値動きで帯を抜けるので滞留しない。

読み:
- **滞留はアーム幅に比例**(帯の幅 ÷ 1 日の歩幅)。C6 ×3.0(1 週に Mon 2 本 + Roll で歩幅が小さい)が最大 12.4%、トパーズ 3.5%、ルビー 4.9%。Hold を持つ 531343523 は 0。

- **ロック幅 c は 0.02〜0.30pp で到達・失格とも動かない**(±0.1)。c は「全決済後の残高が目標を割らないための余白」で、スプレッド・手数料分(円クロス 0.02〜0.05pp・指数 0.02pp)があれば足りる。現行 0.05 のままでよい。

## 4. なぜ偽陽性でないと言えるか

- 結果は MC の揺らぎ(5,000 本で ±0.5pt)ではなく、EA のコード(§1)から直接導ける構造。滞留の大きさは帯幅 ÷ 歩幅という単純な量で、帳簿ごとの差(C6 > ルビー > トパーズ > Hold あり 0)も歩幅の順。
- 代替案(Arm = Close)は失格率を上げず、取引ロジック・倍率・ガードに触れない。逆方向(アーム幅を広げる)は単調に悪化する(g 0.5 で到達 −10〜−34pt)。
- 日中の Close 到達を数えていないため滞留の絶対値は上限側だが、符号と順序は変わらない。
