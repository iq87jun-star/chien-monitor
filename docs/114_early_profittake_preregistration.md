# 114.【事前登録】途中利確(手決済の体系化)— 月内アーリーエグジット規則族のLOYO比較

> ユーザー依頼「途中で利益が出ているタイミングで手決済をする、と条件を変えた場合の最適ロジックは作成可能か」
> → 作成する。ただし「手決済の勘」をそのまま写すのではなく、**決済ルール族を少数固定して
> LOYO(leave-one-year-out)のOOS成績のみで採点**する(docs/104の流儀)。
> ⚠ 本docは `research/early_profittake_loyo.py` の**実行前**にコミットする(docs/72/104の規律)。
> 結果は docs/115 に実出力JSONの転記のみで記載する。

## 0. 背景と位置づけ

- 現行エッジは**時間・カレンダー決済**(月曜o2o・月次リバランス・SL/TP/8日時間切れ)で検証済み。
  docs/112 §5 は「上振れ月の途中カットは検証済みエッジからの逸脱」と明記している。
- 一方でフォワード運用では手決済が実際に発生しており(docs/98 2026-06)、手決済混じり月は
  「manual-adjusted」扱いとなり採点が汚れる。**ルール化して自動化できれば運用規律も採点も改善**する。
- フェーズ単位の手決済相当(+7% ARM / +7.5% PASS_LOCK)は実装済み(docs/100 A-1)。
  本検証の対象はその手前、**「月内・建玉レベルの途中利確」**である。
- プロップ文脈での期待メカニズム: 途中利確は平均月利を下げ得るが、**最悪日・月中DDのテールを
  切れば校正倍率(docs/87: 最悪単日×0.8逆算)を上げられる**ため、「校正後の期待月利」では
  勝ち得る。これを主指標にする(下記§4)。

## 1. 何を最適化し、何を最適化しないか

- **最適化しない**: エントリーロジック・スリーブ構成・月別重み(docs/104-105で確定済み)。
  グリッドの事後拡張・ルール族の事後追加(追加は再登録)。
- **最適化する**: 月内の**全決済+当月新規停止**を発動する条件(下記T1〜T3)の族の選択と、
  そのパラメータ(**各フォールドの訓練9年のみ**で選ぶ)。

## 2. 候補ルール族(これで固定・追加は再登録)

発動=「その日の終値時点で判定→全決済・当月中は新規停止(翌月月初に自動再開)」。
判定水準はポートフォリオ**素サイズ1x換算の月初来リターン(MTD)**で定義する
(EA実装時は 口座月初来PnL% ÷ 倍率 で同じ量が得られる。v1.50利幅通知と同じ換算)。

| ID | ルール | パラメータ(グリッド固定) |
|---|---|---|
| **T0** | 現行(途中利確なし)= 対照 | なし |
| T1 | 固定閾値: MTD ≥ X% で発動 | X ∈ {1.0, 1.5, 2.0, 3.0} |
| T2 | トレーリング: 月内ピークMTD ≥ +1.0%(アーム固定)後、MTD ≤ ピーク−Y% で発動 | Y ∈ {0.5, 1.0, 1.5} |
| T3 | 時間切り: 月の第N営業日終値で発動(利益条件なし・対照的な「ただの早仕舞い」) | N ∈ {10, 15} |

- T3は「利益条件に価値があるか」を切り分けるための内部対照(プラセボと同旨)。
- パラメータ選択の目的関数(事前固定): 訓練9年系列の **校正後期待月利 = mult × 平均月利**
  (mult = docs/87 の 最悪単日−4%/月中DD−8% 逆算×0.8)。同点はCalmarで破る。

## 3. 手順(固定)

1. データ: Yahoo日足 固定窓 **2015-01-01〜2026-06-30**(E5の12ヶ月ルックバック確保)。
   `seasonal_optimize_loyo.fetch_all()` を流用し SHA-256 を記録。
2. 日次スリーブ再構築: `portfolio_daily_compare.py` の実装を**逐語流用**
   (v7/v7x=円月曜o2o・EMon/EMonX=指数月曜・E5=日次c2c×月次ポジション・SJul=c2c・v4=トレード日次時価)。
3. ベースライン合成(2本):
   - **主基準 R4**(現行稼働 Chien_Seasonal_R4G3_Prop に対応): 各フォールドの訓練9年で
     `weights_for("R4")` により月別重みを作る(docs/104と同一コード)。
   - 参考 M3(YEARROUND_05 固定テーブル・Chien_Seasonal_Top_EA)。
   - G3(FOMCオーバーレイ)は**対象外**(イベント建玉・保有~1日で月内利確の概念が合わない。
     docs/112 §5の利幅通知と同じ扱い)。
4. **LOYO**: テスト年Y∈{2016..2025}。各フォールドで(a)R4重み(b)T1/T2/T3のパラメータを
   訓練9年のみで決定→Yに適用。120ヶ月のOOS日次系列で採点。2026H1はLOYO外・参考表示のみ。
5. **プラセボ(ランダム打ち切り×200)**: 勝者ルールについて、月ごとの発動頻度を実測に合わせた
   **ランダム日発動**を200回生成。実OOSの主指標が置換分布の**上位5%に入らなければ
   「利益条件はノイズ(ただの露出削減)」と判定**しT0(またはT3)側を推す。
6. **コスト感応**: 全コスト2倍(近似: 月曜系は往復コスト2倍・v4は+0.04%/月・E5は+0.05%/月、
   docs/104と同じ近似)で上位ルールを再計測(順位逆転がないか)。
7. 付帯(判断材料・採点には使わない): 対照T0系列で「MTDが+X%に達した後の残月リターン」の
   条件付き分布(平均/中央/p25/p75)を出力する。**「手決済したくなる場面で持ち続けると
   統計的にどうなるか」への直接の答え**として docs/115 に記載する。

## 4. 採否の決定規則(事前固定・主基準R4のOOSで判定)

候補T(T1/T2/T3)をT0(現行)より優先するのは、以下**全て**を満たす時のみ:

1. **校正後期待月利(mult×平均月利) ≥ 1.1 × T0**
2. **最悪月がT0より悪化しない**(worst_month ≥ T0のworst_month)
3. **プラセボ合格**(ランダム打ち切り200回の上位5%以内)
4. **コスト2倍で順位維持**

- どの候補も満たさなければ**「現行の時間・カレンダー決済のまま(途中利確はしない)が結論」**
  (それも価値ある確認。docs/112 §5の設計思想が定量的に裏書きされる)。
- 合格ルールが出ても実装は: ユーザー承認 → EAへ**新入力パラメータとして追加(既定OFF・既存動作不変)**
  → **デモ並走**の後のみ実運用。走行中の実チャレンジ口座のEA設定は本検証の結果では変更しない。

## 5. 既知の限界(先に書く)

- Yahoo日足近似(配当除く・v4はSL/TP簡易再現)。**絶対値でなくルール間の相対比較**に使う。
- 判定は日足終値解像度: 実運用の「日中の含み益」は捉えない(intraday equityはtick/M1が必要。
  edge20の実データ検証は補助であり本検証の範囲外)。発動判定に使う値は当日終値=**先読みなし・
  実装可能**(EAはタイマーで同じ量を監視できる)。
- 月曜o2o建玉(v7/EMon系)の「途中決済」は日次granularityの近似(実装では発動時に成行決済)。
- スリーブ集合・ベースライン自体は全期間の知見で選ばれている(選択バイアスは消せない)。
  ゆえに合格でも級は上がらず、**デモ前進検証が最終判定**である事実は変わらない。
- ユーザーの実際の手決済水準は未聴取のためグリッドは常識的範囲で固定した。実際の水準が
  グリッド外なら**再登録の上で追加**する(事後のグリッド拡張はしない)。
