# 204.【事前登録・確認研究】VIX期間構造ゲート(VIX_TERM) — 口座別倍率のブックMCでの再検定

> 2026-09-02作成。費用ゼロ。docs/203 §9.5-2の帰結として、**LEADになった1候補だけ**を
> 正しい土俵で再検定する。本docのルールは`research/vix_term_confirm.py`の実行**前**に凍結した。
> ⚠ docs/203の欠陥(BOOKを単一口座として校正→失格率が退化)を修正した設計であり、
> 主判定の土俵を **docs/199 の口座別配備倍率のブックMC** に置く。

## 1. 候補(1つ・固定)

```
VIX_TERM: 前日終値で VIX > VIX3M(期間構造の逆転)なら、当日の新規建て(Mon・v4・A案の建て型レッグ)を見送る。
          Hold族(連続保有)には適用しない。VIX3M欠損日(2026-07-17以降)は fail-open。
```

docs/203 §9.2でperm_p=0.000、§9.4の補足で同率ランダム見送り20本全てに勝った。
**候補は1つ**なので Bonferroni は不要。α=0.05(片側)。ただし本候補は4候補スクリーンから
選ばれたものであり、本docは**確認研究**である(発見研究ではない)。

## 2. 土俵(実行前固定)

- 口座: `deployed_book.py` の7口座(季節RG3は再構築不可・docs/199 §6.1)。
- 各口座の**配備倍率・業者規則**は docs/199 §3-4 と同一(FTMO/FN 2-Step・Fintokei・Instant建値ロック・速攻60日)。
- 全口座に同一ブートストラップ・ブロック(5日・シード7)。地平250日。
- **窓ごとに独立にブートストラップ**: IS=2016-01..2021-12 / OOS=2022-01..2026-08 / FULL。
- パス数: 素版・ゲート版 1万 / プラセボ 3千(計算量のため・事前に宣言)。

## 3. プラセボ(実行前固定)

各窓で、VIX_TERMの**その窓での見送り率**と同率のランダム見送り(営業日単位・シード7)を**100本**生成し、
ゲートと同じ適用範囲(建て型レッグのみ・Holdは非適用)で掛ける。

## 4. 指標(実行前固定)

| 指標 | 定義 |
|---|---|
| **`E_failed`**(主) | 失格口座数の期待値(7口座) |
| `P_CB_new` | docs/200定義のCB発火(通常5口座で2件以上が30日以内) |
| `E_funded` | 資金化口座数の期待値(コスト確認用) |
| `perm_p` | 見送った日のBOOK合成リターン平均が、同数のランダム日1000組より低い割合(片側) |
| `placebo_pct` | ゲートの`E_failed`がプラセボ100本の何%点か |
| Δ年率 | BOOK合成(資金×倍率加重・倍率込み)の年率差 |

## 5. 判定(実行前固定・後知恵の禁止)

| 条件 | 内容 |
|---|---|
| (i) | `perm_p` < 0.05 を **IS・OOSの両方**で満たす |
| (ii) | OOSで `E_failed` がプラセボ100本の**下位5%以内** |
| (iii) | IS・OOSの両方で `E_failed`↓ かつ `P_CB_new` が悪化しない かつ `E_funded` ≥ 素版×0.98 |

- **ADOPT** = (i)(ii)(iii)全て。→ 期限到来時のEA更新で **fail-open のゲート**として実装候補
  (入力=前日終値のVIX・VIX3M。Yahooから日次取得可能・EA側は2値のフラグ1本)。
- **LEAD** = 一部のみ。→ 記録して閉じる。追加の条件緩和・閾値探索はしない。
- **REJECT** = いずれも通らない。
- 稼働中口座には適用しない(docs/174 §1)。

## 6. 承知している限界

1. 季節RG3口座を含まない。2. v4の当日ゼロ化は近似(docs/203 §2)。3. VIX3Mの2026-07-17以降欠損。
4. VIXは米国市場の指標であり、円クロス・欧州指数レッグへの効き方は本来非対称なはずだが、
   本docでは**全レッグ一律**に適用する(レッグ別適用は候補の増殖=別途事前登録)。

## 7. 実行物

# 8.【結果 2026-09-02】LEAD — 失格・CBは両窓で改善しプラセボにも勝つが、OOSの順列検定が通らない

> `research/results/vix_term_confirm.json`・シード7。
> **判定(§5): (i)✗ (ii)✅ (iii)✅ → LEAD。ADOPTではない。記録して閉じる(追加の条件緩和はしない)。**

## 8.1 主結果

| 窓 | 見送り率 | **perm_p** | E[失格] 素→ゲート | プラセボ100本中の位置 | CB_new 素→ゲート | E[資金化] | 年率(BOOK) |
|---|--:|--:|---|--:|---|---|---|
| IS(2016-21) | 9.2% | **0.002 ✅** | 3.285 → **3.022** | **4%点 ✅** | 28.78% → **22.34%** | 3.000 → 2.991 | −0.22 → +0.07 |
| OOS(2022-26) | 5.3% | **0.377 ✗** | 2.159 → **2.042** | **3%点 ✅** | 6.09% → **4.88%** | 4.319 → 4.366 | 3.55 → 3.47 |
| FULL | 7.5% | 0.001 | 2.745 → **2.551** | **1%点** | 17.58% → **13.50%** | 3.595 → 3.628 | 1.41 → 1.54 |

## 8.2 読み

1. **失格口座数とCB発火は、IS・OOSの両方で下がり、両方でプラセボの下位5%以内に入った。**
   FULLではCB_newが −23%(17.58→13.50)。これは本セッションで測った外部ゲートの中で最大の効果である。
   資金化期待値は落ちていない(OOSではむしろ増)。年率もほぼ不変。
2. **しかしOOSの順列検定が通らない(p=0.377)。** OOS(2022〜)ではVIXの逆転が稀(見送り5.3%)で、
   見送った日のBOOKリターン平均が、同数のランダム日と区別できない。
   つまりOOSでの失格率改善は「**平均が悪い日を外した**」のではなく「**分散が大きい日を外した**」ことによる
   可能性がある。失格は分散にも効くので改善自体は本物だが、§5(i)が要求した
   「平均リターンが有意に悪い日を選んでいる」証拠はOOSでは得られなかった。
3. ISでは(i)〜(iii)すべて通る。OOSで(i)だけ落ちる。**方向は一貫し、有意性が片側で足りない**という、
   docs/203 §9.3のCOT_JPY_SHORT(MON_JPY)と同型の状態である。

## 8.3 帰結(§5の事前登録に従う)

- **ADOPTではない。EAへの実装は行わない。稼働中口座には適用しない。**
- **LEADとして記録し、閉じる。** §5に「追加の条件緩和・閾値探索はしない」と定めた通り、
  (i)を「FULLのみ」に緩めれば通るが、それは後知恵である。
- 再検定の道はひとつ: **時間が経ってOOSが延びること**。VIX逆転はレジーム依存で頻度が低く
  (OOS 4.7年で5.3%≈62営業日)、順列検定の検出力が構造的に不足している。
  2027年以降にOOSを延長して同じ規則で再実行する(規則変更なし)。
- それまでの間、**VIX_TERMは「サーキットブレーカー(docs/200)を補う前向き指標」として
  監視のみ**に使う: VIX>VIX3Mの日はdocs/185 §1の型(b)(モデル外の事象)の事前確率が高い、という読み方。
  EAの動作は変えない。

## 8.4 本セッションの外部データ研究の総括

| 候補 | 判定 | 記録 |
|---|---|---|
| **VIX_TERM** | **LEAD**(2回) | 失格・CBは両窓で改善しプラセボに勝つ。OOSの順列検定のみ未達。OOS延長で再検定 |
| COT_JPY_SHORT | REJECT(BOOK)/参考(MON_JPY) | 円クロス月曜に限れば失格半減の方向。有意でない。レッグ限定で再事前登録すれば検討可 |
| VIX_HI | REJECT | 逆効果(高VIX日は円クロスの利益日を含む)。RG2と同じ |
| FOMC | REJECT | 効果なし |

**価格以外の情報で「悪い日を事前に選ぶ」ことは、少なくともVIX期間構造については実データで
片側の証拠が立った。** 採用に至らなかったのは効果の有無ではなく、OOSの検出力である。
