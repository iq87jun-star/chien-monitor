# 204.【事前登録・確認研究】VIX期間構造ゲート(VIX_TERM) — 口座別倍率のブックMCでの再検定

> 2026-09-02作成。費用ゼロ。docs/203 §9.5-2の帰結として、**LEADになった1候補だけ**を
> 正しい土俵で再検定する。本docのルールは`research/vix_term_confirm.py`の実行**前**に凍結した。
> ⚠ docs/203の欠陥(BOOKを単一口座として校正→失格率が退化)を修正した設計であり、
> 主判定の土俵を **docs/199 の口座別配備倍率のブックMC** に置く。

## 1. 候補(1つ・固定)

```
VIX_TERM: 前日終値で VIX > VIX3M(期間構造の逆転)なら、当日の新規建て(Mon・v4・A案の建て型レッグ)を見送る。
          Hold族(連続保有)には適用しない。VIX3M欠損日(2026-07-17以降)は fail-open。
```

docs/203 §9.2でperm_p=0.000、§9.4の補足で同率ランダム見送り20本全てに勝った。
**候補は1つ**なので Bonferroni は不要。α=0.05(片側)。ただし本候補は4候補スクリーンから
選ばれたものであり、本docは**確認研究**である(発見研究ではない)。

## 2. 土俵(実行前固定)

- 口座: `deployed_book.py` の7口座(季節RG3は再構築不可・docs/199 §6.1)。
- 各口座の**配備倍率・業者規則**は docs/199 §3-4 と同一(FTMO/FN 2-Step・Fintokei・Instant建値ロック・速攻60日)。
- 全口座に同一ブートストラップ・ブロック(5日・シード7)。地平250日。
- **窓ごとに独立にブートストラップ**: IS=2016-01..2021-12 / OOS=2022-01..2026-08 / FULL。
- パス数: 素版・ゲート版 1万 / プラセボ 3千(計算量のため・事前に宣言)。

## 3. プラセボ(実行前固定)

各窓で、VIX_TERMの**その窓での見送り率**と同率のランダム見送り(営業日単位・シード7)を**100本**生成し、
ゲートと同じ適用範囲(建て型レッグのみ・Holdは非適用)で掛ける。

## 4. 指標(実行前固定)

| 指標 | 定義 |
|---|---|
| **`E_failed`**(主) | 失格口座数の期待値(7口座) |
| `P_CB_new` | docs/200定義のCB発火(通常5口座で2件以上が30日以内) |
| `E_funded` | 資金化口座数の期待値(コスト確認用) |
| `perm_p` | 見送った日のBOOK合成リターン平均が、同数のランダム日1000組より低い割合(片側) |
| `placebo_pct` | ゲートの`E_failed`がプラセボ100本の何%点か |
| Δ年率 | BOOK合成(資金×倍率加重・倍率込み)の年率差 |

## 5. 判定(実行前固定・後知恵の禁止)

| 条件 | 内容 |
|---|---|
| (i) | `perm_p` < 0.05 を **IS・OOSの両方**で満たす |
| (ii) | OOSで `E_failed` がプラセボ100本の**下位5%以内** |
| (iii) | IS・OOSの両方で `E_failed`↓ かつ `P_CB_new` が悪化しない かつ `E_funded` ≥ 素版×0.98 |

- **ADOPT** = (i)(ii)(iii)全て。→ 期限到来時のEA更新で **fail-open のゲート**として実装候補
  (入力=前日終値のVIX・VIX3M。Yahooから日次取得可能・EA側は2値のフラグ1本)。
- **LEAD** = 一部のみ。→ 記録して閉じる。追加の条件緩和・閾値探索はしない。
- **REJECT** = いずれも通らない。
- 稼働中口座には適用しない(docs/174 §1)。

## 6. 承知している限界

1. 季節RG3口座を含まない。2. v4の当日ゼロ化は近似(docs/203 §2)。3. VIX3Mの2026-07-17以降欠損。
4. VIXは米国市場の指標であり、円クロス・欧州指数レッグへの効き方は本来非対称なはずだが、
   本docでは**全レッグ一律**に適用する(レッグ別適用は候補の増殖=別途事前登録)。
