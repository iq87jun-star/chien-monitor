## 2. 設計(`ops/futures/mffu_bot.py`)
- **判断と発注を分離**: 判断(月曜か・CME 休場か・HALT か・どの限月を何枚か・当日既建てか)はボットで完結し、発注は transport に委ねる。transport は `dry`(印字のみ)/ `webhook`(TradersPost 形式 JSON を POST)/ `tradovate`(REST・未検証)。
- **限月**: 四半期限月(H/M/U/Z)の第 3 金曜が取引日 + 8 日より後なら当該限月、そうでなければ次(出来高は満期 8 日前 = 前週木曜に移るため、満期週の月曜は次限月)。例: 2026-12-07 → MESZ2026、2026-12-14 → MESH2027。
- **3 つの実行**(VPS は JST・夏時間なしなので UTC 固定時刻をそのまま登録): `entry` 月 22:00 JST(13 UTC)、`exit` 火 05:00 JST(20 UTC)、`check` 火 05:30 JST(未決済が残っていれば決済を再送。16:10 ET の強制清算前の最後の保険)。
- **冪等**: `out/state.json` に日付ごとの {entered, open[], exited} を持ち、二重建て・二重決済・建てていない日の決済をしない。`HALT` という空ファイルを置くと建てなくなる(決済は続く)。
- **記録**: `mffu_log.csv`(UTC・action・限月・枚数・transport・応答)。config で Drive 同期フォルダ `chien_ops/futures/` に向ければ朝のダイジェストが読める(取り込みは稼働開始時に ops_ingest へ追加)。
- **秘密**: Webhook URL・API キーは `config.json`(git 管理外・`.gitignore` 済)にだけ置く。公開リポジトリには `config.example.json` のみ。
- **オフライン検証**: `test_mffu_bot.py` 5 本(第 3 金曜・限月ロール・スキップ条件・建て/決済の冪等・check の再送)を通過。`--dry` で全動作を印字確認済み。

## 3. 判明した制約(送信経路)— 購入前に決めること
| 経路 | 可否 | 費用 | 備考 |
|---|---|---|---|
| Tradovate REST を直接 | **現状不可** | API Access $25/月 | Tradovate の API キーは「本人名義の Live 口座・残高 $1,000 以上」でしか発行されず、プロップ・評価口座は対象外(Tradovate コミュニティ・PickMyTrade の 2026 年ガイド)。コードは残すが未検証 |

**推奨**: TradersPost Starter(資産クラス = 先物)。ボット側は `transport: "webhook"` に切り替えるだけ。

**規約上の注意(購入前に MFFU に書面で確認)**: docs/332 では「自前の自動化 可」としたが、TradersPost の MFFU ガイドは「人の監視なしの完全自律ボットは禁止・半自動(監視しながら)なら可」と書く。当方は週 1 回・2 発注で、毎朝のダイジェストと VPS の記録で監視する運用になる。これが「監視あり」に当たるかを、**口座購入前に MFFU サポートへ文面で確認し、回答を保存**しておく。回答が「不可」なら Q117 は中止(費用ゼロ)。

**当方の形との相性**
- 月曜 1 回の取引は週次リターンが ±0.8%(名目 $150k で ±$1,200)と粗いので、**評価の一貫性(最大日 ≤ 総利益の X%)が最大の壁**。$3,000 到達時に最大日 ≤ $1,500(50%)は数週かかれば満たせるが、30%(≤ $900)は週次の散らばりより小さく、Rapid EOD は実質不可。Builder は評価に一貫性がなく、1 日で通過もあり得る。
- Rapid の本口座は **日中トレーリング**: 7 時間保有中に +$1,500 まで行って戻ると、損失限度も $1,500 上がる。当方の保有形には不利。Rapid EOD / Pro / Builder は EOD。
- Pro はミクロ上限 5 枚(当方の 5 枚ちょうど)、80/20、14 日出金で、Rapid EOD に対する利点が「一貫性 30% でない」ことだけで $70 高い。
- Builder の $1,000 ソフト停止は、当方の最悪日(docs/333 の最悪月 −2〜3% ≒ 1 日 −0.7% × $150k ≈ −$1,050)で稀に当たるが、失格ではなく「その日停止」= 災害 SL として働く。出金は 1 サイクル $2,000 上限・5 回で Live 移行(その後は上限なし・80/20)。
- T1 ニュース: 当方の保有 13〜20 UTC(9:00〜16:00 EDT)に月曜の T1(CPI が月曜になる年に数回)が重なると Rapid / Pro の本口座では違反。Builder は無制限。ボットには `skip_dates`(T1 の月曜)を config で持たせる(v0.2)。

**結論**: **Builder 50k($2,000 MLL・$153、割引時 $92〜107)を第一候補**。評価通過の確率が最も高く(一貫性なし・1 日)、本口座も EOD DD・ニュース無制限で当方の形に合う。代償は 80/20 と出金のサイクル上限 $2,000(Live 移行まで)。次点は Rapid(90/10・毎日出金)だが、評価 50% 一貫性で通過に数週〜数か月、本口座の日中トレーリングが保有形に不利。Rapid EOD(30%)と Pro は当方には不向き。
自動売買は Fair Play で「自分の設定の自動戦略は可・自分で建て決済すること」と明記されており、自前ボットを自分の VPS で動かす形はこれに沿う(第三者が代わりに運用する形・コピーが不可)。TradersPost 経由の送信は「自分の発注を自分のツールで出す」範囲だが、念のため購入前に文面で確認する(§3)。

## 9.【2026-10-09 追記】口座サイズの選択(ユーザー「費用が変わらないなら大きいサイズを」)
Builder の価格(第三者レビューの 2026-10-04 検証値・定価 / 50% コード適用時): 25K $105 / $53、50K $153 / $77、100K $282 / $141、**150K $398 / $199**。リセットも同額。1k 当たりでは 150K が最安($2.65/k、50K は $3.06/k)。

**通過確率はサイズでほぼ変わらない**(docs/333 の週次リターン 2018〜 を名目比率で合成、2 万回ブートストラップ、EOD トレーリング MLL と日次ソフト停止を近似):
| サイズ | ×2 | ×3 | ×4 |
|---|---|---|---|
| 50K(MLL 4%) | 通過 69% / 失格 32% / 中央 11 週 | 73% / 27% / 7 週 | 76% / 24% / 5 週 |
| 100K(MLL 3%) | 64% / 36% / 10 週 | 70% / 30% / 7 週 | 73% / 27% / 5 週 |
| 150K(MLL 3%) | 67% / 33% / 10 週 | 72% / 28% / 7 週 | 75% / 25% / 5 週 |

目標 6% に対し MLL 3〜4% で、週次の正のドリフト(平均 10.9 bps・標準偏差 0.83%)が効くため、通過率は 7 割前後で一定。倍率を上げると速く通るが失格も増える(×3 が均衡)。失格 1 回当たりの費用だけがサイズで変わる: 期待審査費 = 価格 / 通過率 ≈ 50K $210、100K $400、150K $550(定価)。

**規模が買うもの(×3・週 10.9 bps・80/20)**: 期待利益 ≈ 50K $8.5k/年 → 手取り $6.8k、100K $17k → $13.6k、150K $25k → $20k。初回出金までのバッファ($2,100 / $3,100 / $4,600)はいずれも中央 10 週前後。150K の出金はサイクル $4,500 上限・最低 $1,500、Live 後は 4 ミニ / 40 ミクロ。

**結論**: 150K Builder(定価 $398・コード適用で ≈$199)を ×3(MES 6 / MNQ 3 / MYM 6 = 15 ミクロ・名目 ≈$460k)で。注意 2 点: (1) 日次ソフト停止 $2,500 は名目の 0.54% で、最悪日(0.7%)より手前で止まる = 災害 SL として月に 1 回程度発動し得る(失格ではない)。(2) 失格時に失う額が $398 で、2 回失格すると $800。許容できるなら 150K、審査費を抑えたいなら 100K($282)が中間。
`config.json` の枚数: 150K = MES 6 / MNQ 3 / MYM 6(`max_contracts_total` 15)、100K = 4 / 2 / 4(10)、50K = 2 / 1 / 2(5)。
