# 519.【登録・紙の上の記録】週末の要人の発言を月曜の建ての前に記録する — 対象・話題・判定の手順を固定(EA は変えない)

2026-11-24 登録(ユーザー「Twitterの投稿をトレードに反映させる様な事は出来ますか」→「どういう方が良いでしょうか」→ 要人・機関の公式の発言を、まず紙の上で記録する案を提示 →「登録」)。記録は `research/forward/weekend_statements_log.csv`。EA・マニフェスト・config は変えない。

## 1. ねらい
- 予告なしに出る要人の発言(X への投稿を含む)が、月曜の円クロスと月曜の指数の結果を悪くするかを、先に決めた規則で記録して確かめる。
- 過去の投稿をさかのぼって集めることはできないので、検証はこれからの記録で行う。記録は月曜の建ての前に付け、後から書き換えない。

## 2. 対象(役職で固定・個人名では持たない)
| 区分 | 対象 | 記録する話題 |
|---|---|---|
| A | 米国の大統領(現職) | 関税・輸出規制・制裁 / 軍事行動 / FRB への介入(議長の解任・利下げの要求の具体化)/ ドル政策 |
| B | 米国の財務長官 | ドル政策・為替(円安へのけん制)/ 関税 |
| C | 日本の財務大臣・財務官(通貨当局)、日銀総裁 | 為替介入の示唆・実施 / 予定外の発言での政策変更の示唆 |
| D | FRB 議長 | 予定外の発言・緊急の声明 |
| E(参考) | 要人の発言ではない週末の重大な出来事 | 主要国の軍事衝突の開始 / 主要な金融機関の破綻 / 米国債の格下げ / G7 の緊急声明 |

## 3. 記録の手順(毎週・月曜 08:47 JST)
1. 対象の時間: 金曜 21:00 UTC(NY の引け)から、確認の時点(月曜 08:47 JST ごろ = 日曜 23:47 UTC ごろ)まで。
2. 報道の検索で、区分 A〜E の発言・出来事を探す(当面は X の有料 API を使わない。主要な発言はすぐ報道される)。
3. 強さを付ける。該当が複数あれば一番強いものを採る。
   - S0 = 該当なし。
   - S1 = 話題への言及だけ(新しい具体策なし・これまでの方針の繰り返し)。
   - S2 = 具体的な措置の予告(税率・対象・日付のいずれかつき)、または介入の強い示唆(「断固たる措置」「あらゆる手段」など)。
   - S3 = 実施・発動の発表(関税の発動・制裁の実施・介入の実施・軍事行動の開始)。
4. S2・S3 は、独立した主要な報道機関 2 社以上(Reuters・Bloomberg・AP・WSJ・FT・日経・NHK など)が報じていることを条件にする。1 社だけなら S1 として、備考に書く。
5. 判定 = S2 以上を「見送り相当」、S0・S1 を「通常」とする。区分 E だけの週は「通常(E あり)」として別に数える。
6. 1 行を CSV に足し、月曜の建て(13:00 JST)の前にコミットする。コミットの時刻が「建ての前に付けた」ことの記録になる。
7. 記録を後から直す場合は、行を書き換えずに備考の追記か訂正の行を足す。

## 4. CSV の欄
`week_monday`(月曜の日付)/ `checked_at_utc` / `window_from_utc` / `window_to_utc` / `strength`(S0〜S3)/ `label`(見送り相当・通常・通常(E あり))/ `category`(A〜E)/ `topic` / `summary`(1〜2 文)/ `sources`(報道機関名と URL・`;` 区切り)/ `note`

## 5. 並べる数字(判定の時にまとめて計算する)
- 月曜の円クロス 4 本の結果(倍率 1 あたり・実口座の記録から)と、月曜の指数の結果。
- 週明けの始値の飛び(金曜の終値 → 月曜の始値・円クロス 4 本の平均)。大きな発言は週末の飛びに表れるので、過去 10 年を確かめられる代わりの物差しとして並べる。

## 6. 判定(先に固定)
- 中間 = 2027-03-01(約 14 週)、最終 = 2027-05-31(約 27 週)。
- 「見送り相当」の週が 5 週に満たない場合は「判断できない」とし、延長するか終了するかをユーザーに確認する。
- 5 週以上ある場合: 「見送り相当」の週の月曜の円クロスの平均がマイナスで、「通常」の週の平均がプラス、かつ「見送り相当」の週のうち負けた週が半分を超えるとき、「見送りの合図として EA に入れる検証」を登録の候補にする(ここで初めて EA の検証に進む。採用ではない)。
- それ以外は、記録を終了する。
- 週の数が少ないので、この記録だけで効き目を証明することはできない。判定は「次の検証に進むかどうか」を決めるためのもの。

## 7. 限界
- 報道の検索に頼るので、報じられなかった投稿は拾えない。
- 強さの区分(S1 と S2 の境目)に判断が入る。迷った場合は弱い方に付け、備考に理由を書く。
- 発言が出た時点で、相場はすでに動いていることがある(月曜の始値に織り込み済み)。
- 2026-11-23 の週までは記録が無い(さかのぼって付けると、結果を知ったうえでの後付けになるため付けない)。最初の記録は 2026-11-30 の週。

## 8.【追記・2026-11-24 登録】週末の BTC の騰落も同じ時刻に記録する
ユーザー「登録」(Q282・docs/524 の提案)。Q282 で、週末に BTC が大きく上げた週は月曜の円クロスが弱い傾向があった(z が +2 超の 19 週: 平均 −0.41%・負け 68%)。採用の線には僅差で届かなかったので、紙の上で続きを見る。EA は変えない。

- 定義(Q282 と同じ): 金曜の終値 → 日曜の終値(Yahoo 日足)の騰落を、直前 52 週の週末の騰落の標準偏差で割った z。
- 帯: z ≥ +2 =「見送り相当(BTC)」/ +1 ≤ z < +2 =「注意」/ z ≤ −2 =「下げた週」/ それ以外 =「通常」。
- 記録: 毎週 月曜 08:47 JST の確認で `cd research && python3 -W ignore forward/btc_weekend_signal.py` を実行する。`research/forward/btc_weekend_log.csv` に 1 行足される(同じ週は二重に足さない)。日曜の終値は確認時点(確定の約 13 分前)の値。
- 判定(§6 と同じ時期・先に固定): 中間 2027-03-01・最終 2027-05-31。「見送り相当(BTC)」と「注意」の週を合わせて 5 週に満たなければ「判断できない」。5 週以上あり、その週の月曜の円クロスの平均がマイナスで、ほかの週の平均がプラスなら、「週末の BTC が上げた週を見送る」形の検証を登録の候補にする(採用ではない)。
- 最初の記録は 2026-11-30 の週。2026-11-23 の週(z +1.79・注意)は、結果を知った後なので記録に入れない。
