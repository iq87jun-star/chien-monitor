## 1. 決定事項

1. **全プロップ口座をPD系に一本化**(季節R4G3は撤収。7月インシデント月としてdocs/98に記録)。
2. **プロップ構成からv4を除外(noV4)**: v4はポートフォリオ内で「平均への寄与は代替可能・
   危機日の集中テール(9ペア同方向一斉SL)は代替不能に悪い」ことがMC解剖で判明
   (3xの日次失格の100%がv4主犯・出所は2024/8・2016/7・2020/3・2025/4の4ヶ月に集中)。
   v4自体のエッジは否定しない(Dukascopy 6/6)— **自己資金(檻なし)向けに保存**。
3. EMonのRG3ゲートは**EA実装済み(docs/68)を確認**。研究系列が素EMonで計算されていた乖離を
   本docで是正(RG3込みが正: 2018年−3.5%→+0.5%・マイナス年ゼロ・2022/2/21はOFF週で不参加)。
4. **EA v1.44**: ガード基準をFN/FTMOの実計算式(日開始balance−現在equity)に一致させる。

## 4. EA v1.44 仕様(本docと同時に実装)

1. **balance基準日次ガード**: `equity ≤ 日開始balance×(1−3.5%)` で全建玉即時決済+当日新規停止。
   判定は**OnTick毎**(旧: 60秒タイマーのみ=7/24の執行遅れ要因の一つ)。
2. **翌サーバー日に自動再開**(E5はBAL_GUARD決済後の月内再建てを許可 — 従来は手決済のみ再建て)。
3. **月内発動上限2回**: 3回目で月末ロールまで新規停止(2020/3型の連鎖発動対策)。
4. 既存ガードは全て維持(静的フロア/利益ロック/旧equity日次ガード=二次防衛に降格)。
5. v4はリスク入力0+EntriesV4冒頭で無効化(コードは温存=自己資金版で再利用)。

## 5. 誠実な注記

- **v4関連の構成変更だがDukascopy最終ゲートは事後確認とする**: 本決定の根拠はリターン差でなく
  テール構造(危機日の相関SL集中)であり、データソースに依存しない。Dukascopyでの追試は
  次回Colab実行時に行い、noV4の平均リターン低下幅(Yahooでは−0.02pt/月)を実測で更新する。

  超えれば破られ得る(ガードは深さでなく速度の制御。フロア型・閉場ギャップは残余リスク)。

  イン・サンプル月次重みの産物だったことの帰結であり、後退ではなく正直化。
