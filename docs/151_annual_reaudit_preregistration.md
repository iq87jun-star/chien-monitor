# 151.【事前登録】年次再監査ラン — 最新世代の全ゲートを採用エッジに機械適用(初回2027-01)

> 背景(2026-07-11の対話): 検定基準はプロジェクト進行中に強化された(ドリフト保存プラセボは
> edge11で導入等)。「古い結論は現在の基準でも成立するか」を毎年、**機械的に**確認する仕組みを
> ここに固定する。これは探索ではなく監査 — 新パラメタ・新仮説なし・窓を1年延ばして再実行するだけ。

## 1. 対象と頻度

- 対象: **v4 / v7(2クロス化後の配備定義) / E-Mon[RG3] / E5(E5p) / G3 / (参考)S-Jul**
- 頻度: **毎年1月第1週**(初回2027-01)。データ窓を前年末まで延長。
- 実行: 本docの規則で `research/annual_reaudit.py` を組む(実装は既存関数の逐語再利用:
  edge13ローダ/stats/perm・edge11のドリフト保存プラセボ・edge20実測コスト・regime_monitor)。
  G3のみ日足プロキシが弱い(docs/86 H14b)ため**H1再測はユーザーColab任意**・日足は参考扱い。

## 3. 決定規則(機械適用・降格のみ。昇格はフォワードでしか起きない)

- **R2またはR3不合格**(=ベータの言い換えが新基準で判明) → 該当スリーブのサイズ50%降格。
  Dukascopy再確認(ユーザーColab)でも不合格が再現 → 新規停止(docs/102のRED手順に合流)。
- **R5がRED** → docs/102の既存規則どおり停止(本監査はそれを年次で追認するだけ)。
- **R6が2年連続で分布最小未満** → 停止(docs/98 §3の年次版)。
- R1/R4の劣化は単独では降格しない(記録して翌年比較・2年連続悪化でR2-R3精査を義務化)。
- **全合格 → 級維持**。結果は docs/15x に転記(数字を盛らない)。

## 4. 位置づけの明確化(誠実に)

- 本監査は「過去の結論を疑う」のではなく、**「過去の結論が現在の基準・現在のデータでも
  成立し続けることを、作者(モデルのバージョン)に依存しない形で毎年証明し直す」**装置。
- 探索の再開ではない: 不合格が出ても代替エッジを探しに行かない(再開条件はdocs/128 §4のまま)。
- 実行者は誰でもよい(将来のモデル・人間・別セッション)— それがこの設計の要点。
