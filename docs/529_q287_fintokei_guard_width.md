# 529.【Q287】Fintokei 3 口座の全決済ガードの幅を下げる(最大許容リスク 3% の注意への対応)— 2.4% にすると、到達が古い期間で 2〜4 ポイント下がる(失格は +0〜2)。事前の条件(悪化なし)を満たす幅は無く、順守のための費用として判断を仰ぐ(セル +30・累積 11,293)

2026-11-25 登録・実行(ユーザー「登録実行」: docs/241 §1bx で案内した計算)。スクリプト `research/queue/q287_fintokei_guard_width.py`・結果 `research/results/q287_fintokei_guard_width.csv`。EA・マニフェスト・config は変えていない(切り替えはユーザーの「切替」の後)。

## 1. 背景
- 11/24 のトパーズの決済(確定損 3,500 万円の 3.13%)に対して、Fintokei から「最大許容リスク 3% の超過」の注意が来た(1 通目)。3 回で最大リスクが 1% になり得る。
- いまのガードは 2.8%。基準が「日の開始残高」で、発動から約定までのすべりもあるので、3% を超えることがある。

## 2. 型・場面・選び方(docs/244 に先に固定)
- 幅: 2.8%(基準)に対して 2.6・2.5・2.4・2.2・2.0%。モデルのガードは基準残高に対する割合で、発動時の損失は従来どおり「幅 × 1.1」。
- 場面 6(トパーズ・ルビー・パール × いま・次)。ガードの組み合わせは 11/25 に切り替えた形(SKEW + 200 日線 + 縮小)。
- 判定: 2 つの期間とも 到達 ≥ 基準 − 1・失格 ≤ 基準 + 1 なら「影響なし」、それ以外は「悪化」。
- 選び方: すべりを 20% まで見込んで 3% 未満に収まる幅(2.4% 以下)の中で、口座の 2 場面とも悪化でない最も広い幅。無ければ 2.4% の悪化の幅を示して判断を仰ぐ。

## 3. 照合
- 2.8% の 6 行は、Q286 の「SKEW + 200 日線 + 縮小」の行とすべて一致。

## 6. 読み方
1. **幅を狭めると、ガードが早く動く分だけ到達が下がる。** 2.4% では、新しい期間(①)はほぼ変わらず(−2.2〜+1.1)、古い期間(②)で 2〜4 ポイント下がる。失格は +0〜2 ポイント。
2. **費用は、今日入れた 3 つのガードの効き目より小さい。** たとえばトパーズのいまの段階は、今朝までの形が 75 / 25・71 / 29、3 つのガードを入れて 78 / 11・81 / 7、そこから幅を 2.4% にして 76 / 12・77 / 9。
3. **2.6% は費用が小さいが、余裕も小さい。** 11/24 と同じすべり(+7%)なら 2.78% で収まるが、すべりが 15% を超えると 3% に届く。実測は 3 回しかなく、どこまですべるかは分かっていない。
4. **2.2% 以下は費用が大きい。** パールで到達が 3〜8 ポイント下がる。
5. **ガードが動く回数は増える。** トパーズのいまの段階で、満額の月曜の 10% → 14%。日次ガードは月内 3 回で月末まで止まるので、止まる月も少し増える。
6. Fintokei の規則を守るための変更なので、「2.8% のまま」は選ばない(あと 2 回の注意で最大リスクが 1% になり得る)。

## 7. 限界
- モデルは 1 時間足で、発動時のすべりは一律(幅 × 1.1)。実際のすべりは指数の建玉が大きいほど大きい。
- Fintokei がどの残高を基準に 3% を測るかは未確認(基準残高でも日の開始残高でも、11/16 と 11/24 の通知の有無と合う)。
- ロールは評価中の計算に入れていない。ロールの建玉中の損失も 3% の対象になる。
- 同じ 10 年のデータ。

## 8. 提案(採るなら「切替」)
- **Fintokei 3 口座の全決済ガードを 2.4% にする。** あわせて、円の額を「基準残高」と「日の開始残高」の小さい方で決める(残高が基準残高より多い日に、円の額が膨らまないようにする)。
- 費用を抑えたい場合の代案は 2.6%(「切替 2.6」)。すべりへの余裕は約 15% まで。
- 切り替えは、版を 1 つ上げた EA を作る → コンパイル確認 → 切り替え。11/30 の月曜に間に合わせるには金曜までに行う。
- 別に確かめる価値があるもの: トパーズの指数 2 本(口座の約 2 倍)がすべりの主因なので、指数の数量を減らす形との比較(進めるなら「登録して実行」)。
