## 3. 読み方
1. **スワップは Hold XAU の期待を 3〜5 割削る**(研究系列 +123 → +65%、1-Step 9.0 → 6.4 万/月)。docs/398 §2c の「月 −0.5%」は帳簿 MC でもそのまま効き、評価中(×3.0)は XAU 名目の 3 倍で年 −6% 相当の固定費になって到達率を 7pt 下げる。docs/349 §9 以降の帳簿 MC・docs/290 の Hold XAU 行はスワップ無しの数字だったので、FTMO/FN の Hold XAU はこの表に読み替える。
2. **config `a9` の過大評価**(§2d): 1-Step の現行帳簿は EA9 の実レグより XAU を 2.8 倍多く持っている前提だった。実レグで描き直すと現行でも到達 83%・失格 19%・Sharpe 0.87 で、docs/399 §5 の「到達 81%・失格 25%(スワップ無)」より良い。つまり **1-Step の Hold XAU 問題は config の記述の問題が大きく、EA9 の実配分では「半分」との差は 1pt 台**。逆に docs/399 の膝(a9 1.25 / Mon4 0.81)は XAU 過大の帳簿で決めたので、実レグで再探索すると膝は少し上(資金化後倍率が 1.25 より大きい)になる可能性がある。これは config の再記述(§4 候補 E)の後で見る。
3. **Hold XAU を落とすと期待は 1〜2 割落ち、失格は大きく下がる**(1-Step 現行 36% → 半分 20% → 0 で 10%・Sharpe 0.76 → 0.89)。docs/322 の方針(失格 ≤10% の中で最大)に照らすと config 合成の帳簿では「0」か「Mon 置換」、実レグ帳簿では現行(19%)でも「半分」(14%)でも ≤10% には届かず、評価段階の倍率(×3.0)側の問題と分かる。評価段階は docs/399 の対象外だったので、§4 候補 E の後に Q 候補として扱う。
4. **宝くじ 531343523**: Hold XAU の有無で到達 30 → 36%・期待 11.9 → 10.9 で、どちらも「宝くじ」の性格(0 率 80%)は変わらない。Mon 置換(Mon4 10 → 10.9)は期待 14.6 と最大だが docs/318 §2(Mon 族の比率は上げない)と衝突し、判定はユーザー。
5. **FN 14074882**(−76 bps・2026-12-31 期限): Hold XAU 0.4 は期待 +0.3 万/月に対して失格 +8pt。ユーザーが 10/27 に「ギャンブル枠」として残した口座なので、本稿は数字を出すだけで判定は 12 月改定に送る。
6. なぜ偽陽性でないか: 同じ乱数・同じ帳簿でスワップ項だけを加えた差分(swap 無の行は docs/399 §5 と完全一致)。研究系列も `hold_cell` の式に日割り定数を足しただけで、スワップ 0 の行は docs/290 と同じ。実レグの差は EA9 のソース入力(`mql5/【FTMO100k_1Step_口座531466484】EA9_…_v1.06.mq5` 131〜134 行)から直接計算。
