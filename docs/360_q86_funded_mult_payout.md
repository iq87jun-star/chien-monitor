# docs/360 Q86: 資金化後の倍率逓減と出金最大化(12 か月 MC)— 逓減は不利、InpFundedMult は不要(診断・セル 0)

2026-10-14(水)朝の定例。docs/322 Q86(order 9)。スクリプト `research/queue/q86_funded_mult_payout.py`、結果 `research/results/q86_funded_mult_payout.csv`。

## 1. 仮説と設定
- 問い: 資金化後に倍率を維持するか逓減するか(Mon4 ×3.3 維持 vs 最初の出金後に ×2.0 / ×1.5)、出金は 2 週か 4 週か、出金後の残高扱いで 12 か月の期待出金額と失格率がどう変わるか。EA に `InpFundedMult`(資金化後倍率)を足すべきか。
- 帳簿: 10.6 年(2016-01〜2026-07)の日足レグ・5 日ブロック・2 万本(Q131 と同じ)。静的床 = 初期残高 × 0.90、EA 日次ガード(FTMO 4%・Fintokei 2.8%)。
- 出金: {10, 21} 営業日ごとに「初期残高 × (1 + 保持率)」を超えた分 × 0.8(80/20)。出金後の残高は初期 × (1 + 保持率)、床は動かない(FTMO の資金化口座の扱い)。
- 格子: 倍率 {1.5, 2.0, 3.3, 3.3→2.0, 3.3→1.5, 5.0, 6.0, 6.0→3.3, 8.0} × 保持 {0, 5, 10, 20}% × 頻度 {2 週, 月}、口座 2 型(FTMO 50k Mon4 = EA3、パール B 案)。比較対象として Q131 の余裕比例(採用設定 k=1.5 / 1.0・保持 20%・月次)。

## 3. 判定
1. **逓減は不利**: 失格は最初の出金より前に起きるものが大半なので、出金後に倍率を落としても失格は 0〜2pt しか減らず、出金は 3〜4 割減る。×6 → ×3.3 の逓減(7.8 / 6.4)は ×5 維持(7.0 / 7.6)に失格・出金の両方で劣る。「逓減」は「もっと低い固定倍率」の劣化版。
2. **出金頻度**: 2 週は月次より出金 +10〜15%。保持 ≥10% なら失格は同じ〜+0.3pt、保持 0〜5% では +2〜5pt。小さな改善で、規約(FTMO 14 日出金の可否)の確認が先(Q108)。
3. **保持率**: 全額出金は失格 3〜4 倍(Q134 と一致)。固定倍率では保持 10% が膝、Q131 併用では 20%(docs/349 §9c)。
4. **Q131 が優越**: 同じ失格(×6 で 9.8 vs 9.9%)で出金 3 倍(10.3 → 31.0%)。固定倍率の格子のどの点も Q131 の採用設定に届かない。

## 4. 提案(11 月改訂・新規口座への含意)
- **`InpFundedMult` は追加しない。** 理由: (a) 逓減が不利で、資金化後は一定倍率 + Q131 の余裕比例が最良。(b) FTMO・FundedNext とも資金化口座は別ログインなので、資金化 = manifest の別エントリ + `InpMult` の設定で足りる(docs/349 §9 の「完了」時の入力変更)。(c) 「余裕が増えたら上げる」方向は `InpDynK` が担う。
- 現行(docs/349 §9〜§9c)の資金化後倍率(EA3 / EA8 Mon4 ×6・パール ×8)と k・保持 20% はこの格子でも最良点。変更しない。
- Q108(規約の再確認)で 2 週出金の可否を確かめ、可なら 11/1 改正案の出金規則を「2 週・保持 20%」に(期待 +10〜15%・失格 +0.3pt 以内)。EA の `[PAYOUT]` 行は 21 日固定なので、変更する場合は `InpPayoutDays` を足す(別項目)。
