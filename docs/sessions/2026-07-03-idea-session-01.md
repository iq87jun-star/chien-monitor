### 詳細化 #1 — ポートフォリオレベルのボラティリティ・ターゲティング

- **レーン**: L1 器・実装系
- **提案セッション / 日付**: Claude 募集セッション / 2026-07-03

#### 仮説の要約

検証済み5本の**合成後**デイリーリターンに対し、実現ボラティリティ推定でポジション全体を
スケールして目標ボラ一定に保つと、シャープレシオが改善しテール(最大DD・尖度)が薄くなる。
個別戦略のシグナル生成には一切触れない。

#### 機序の説明

- **エッジが存在する理由**: ボラティリティ・クラスタリング(実現ボラの強い自己相関)は
  資産クラス横断で最も頑健なスタイライズド・ファクト。これは**リターン予測ではなくリスク
  予測**であり、探索自由度が小さい。
- **反対側で損をしているのは誰か**: 該当なし — これはアルファ創出ではなくリスク効率の改善。
  その旨を明示し、事前登録では「シャープ改善」のみを主要評価指標とし絶対リターン増を
  主張しない。
- **想定プラセボ(ベータの言い換え検査)**: 改善が「平均レバレッジが上がっただけ」の
  言い換えである可能性。→ **平均レバレッジを一致させた固定レバレッジ・ベンチマーク**との
  比較を事前登録の必須比較対象に指定する。

### 詳細化 #2 — CFTC COT ポジショニング極値(ヘッジ圧力)

- **レーン**: L2 新データ源
- **提案セッション / 日付**: Claude 募集セッション / 2026-07-03

#### 仮説の要約

CFTC COT レポートの大口投機筋(Non-Commercial)/当業者(Commercial)ネットポジションの
極値(長期パーセンタイル)が、先物リターンを条件付ける。まずは検証済み5本のフィルタ
(確信度の重み付け)として、独立戦略化はその後。

#### 機序の説明

- **エッジが存在する理由**: ヘッジ圧力理論 — 当業者は事業リスクのヘッジのために先物を
  使い、保険料としてプレミアムを支払う。投機筋はその反対側で流動性を提供し
  プレミアムを受け取る。ポジショニングの極値はこの保険料が厚い局面を示す。
- **反対側で損をしているのは誰か**: ヘッジャー(当業者)。ただし彼らにとっては事業リスク
  低減の対価であり、合理的な支払い。エッジが消えにくい構造的理由になる。
- **想定プラセボ(ベータの言い換え検査)**: **最重要**。ヘッジ圧力シグナルはキャリー
  (棄却済み領域)およびモメンタムと相関するとの文献報告がある。→ 事前登録で
  **キャリー・モメンタムに対する直交化後の残差効果**の検定を主要検定に指定。
  残差効果が消えるなら棄却済みキャリーの言い換えとして不採用。

#### データ入手手順(L2必須要件)

- **取得元**: CFTC 公式(cftc.gov)"Commitments of Traders"。Legacy / Disaggregated 両形式。
  Socrata Open Data API(publicreporting.cftc.gov)でプログラム取得可。
- **データ形式・粒度**: 週次(火曜時点)。CSV / API(JSON)。銘柄別ロング/ショート/
  スプレッド枚数、トレーダー分類別。
- **コスト**: 無料。
- **更新頻度・遅延**: 毎週金曜 15:30 ET 公表(火曜時点のデータ=**公表遅延3営業日**)。
  バックテストでは公表日ベースでのみ使用しルックアヘッドを排除(事前登録に明記)。
- **入手までの具体的手順**: ① Socrata API でヒストリカル一括取得(1986年〜)
  ② 銘柄コードを検証済み5本の対象市場にマッピング ③ 公表日カレンダーを付与
  ④ 週次→日次への保持展開。

### 詳細化 #3 — オプションIV(VIX/OVX/GVZ)によるレジーム条件付け

- **レーン**: L2 新データ源
- **提案セッション / 日付**: Claude 募集セッション / 2026-07-03

#### 仮説の要約

インプライド・ボラティリティ指数(VIX・OVX・GVZ 等)の水準/ランクが定義する
リスクレジームによって、検証済み5本のエッジの厚みが異なる。レジームを条件とした
配分の増減(オン/オフではなく重み調整)として5本に載せる。新戦略の探索は行わない。

#### 機序の説明

- **エッジが存在する理由**: リスクプレミアムの時変性 — IVが高い局面はリスク移転需要が
  高く、システマティックな流動性提供・リスクテイクへの期待報酬が変化する。
  検証済み機序の報酬がレジームで一様である必然性はない。
- **反対側で損をしているのは誰か**: 高IV局面で価格を問わず保険(オプション・ヘッジ)を
  買う制約付き投資家。
- **想定プラセボ(ベータの言い換え検査)**: レジーム条件付けの「改善」が単なる
  **ショートボラ・ベータまたは市場ベータのタイミング**の言い換えである可能性。
  → レジーム別のベータ暴露を計測し、ベータ調整後も条件付け効果が残ることを
  主要検定に指定。

#### データ入手手順(L2必須要件)

- **取得元**: FRED API(VIXCLS・OVXCLS・GVZCLS 等、無料APIキー)。原典は CBOE
  (公式サイトから日次ヒストリカルCSV無料DL可)。
- **データ形式・粒度**: 日次終値。CSV / JSON。
- **コスト**: 無料。
- **更新頻度・遅延**: 翌営業日更新。運用・バックテストとも**1営業日遅延**で使用
  (当日終値は翌日から有効)と事前登録に明記。
- **入手までの具体的手順**: ① FRED APIキー取得 ② 対象系列を検証済み5本の資産クラスに
  マッピング(株式系→VIX、原油系→OVX、金系→GVZ 等) ③ 日次系列を一括取得
  ④ ランク変換の基準期間を事前登録で固定。
