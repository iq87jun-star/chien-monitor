## 3. 読み方
1. **旧モデルの 1-Step は床の定義が違っていた**: 資金化後も静的床(額面 −10%)にしていたため、利益が乗るほど緩衝が増え、余裕比例 k=2 で倍率が最大 3 倍まで上がる経路が「月 108 万」を作っていた。規約(docs/396 §1)は EOD トレーリングで緩衝が常に ≤10%、k は効かず(余裕 ≤ mdd で f=1)、保持 20% も効かない(床が追随する)。正しい最適方針は「毎サイクル全額 Reward で床をリセット」(docs/396 §3a C/D)で、それでも ×3.125 では資金化後の失格 54%。
2. **docs/349 §9e〜§9f の「1-Step 資金化後 ×1.25」候補(10/22〜10/23 に 2 朝連続で出て切替)は旧モデルの産物**。規約床では逆方向で、失格 ≤10% の膝は a9 1.25 / Mon4 0.81(現行の 0.4 倍・10/23 以前の 2.0/1.3 の 0.63 倍)。docs/300 の「1-Step は ×1.5〜2.5(資金化後 250 日失格 ≤1%)」とも整合する(docs/300 は A 案 ×1.5 で 0.3%・本表は ×0.48 = a9 1.5 で 14.5%。差は docs/300 が Mon4 を含まず日次ガード 2.4% も違うため)。
3. 合計への影響は −22%(375 → 292 万)。1-Step を膝(×0.4)に戻すと 280 万(−25%)だが、1-Step の 0 率は 38 → 25%、資金化後失格は 54 → 8%。「期待 12 万/月の差」は失格 46pt 分の危険の対価で、docs/322 の方針(失格 ≤10% の中で最大)では膝を採る。
4. FTMO 2-Step はロール運用で旧モデルとほぼ同じ(+2 万/月は新規利益のみ分配・ロール分 100% の効果)。FN Instant は建値ロック + 70% で 1.2 万/月・失格 76%(docs/298 の「毎年 3 割で消える」より悪い。+5% 出金規則が床の頭打ち後に緩衝を削る)。
5. なぜ偽陽性でないか: 同じ乱数・同じ帳簿・同じ設定で床と出金の式だけを規約どおりに変えた差分。1-Step 以外の static 口座の数値は旧新で完全一致(実装の退行なし)。1-Step の 9% → 54% は床の定義そのもので、docs/396 §3a の単口座計算(40%・12 か月)とも整合(本表は窓が資金化から窓末までで長い経路を含む)。

## 4. 提案(11 月の EA 改訂・運用への含意。採用は「切替」)
- **config の 1-Step 資金化後倍率を a9 1.25 / Mon4 0.81 に戻す案**(docs/349 §9f 追記 2 の ×1.56 を撤回)。EA9 の資金化後入力(`InpMult`)は「完了」時に 3.0 → 1.25 相当。評価段階の倍率(×3.0)は本件の対象外(評価中の床は額面で頭打ちのトレーリングで、旧モデルと同じ)。
- **EA9 の `InpKeepPct`(1-Step)は資金化後 0 相当**: 保持は緩衝にならないので、毎サイクル全額 Reward を請求して新口座で再開する。docs/382 §4 の「1-Step は残し 20% を必ず守る」は撤回(docs/396 §4-3 のとおり)。`[PAYOUT]` 行の文言変更は Q159 の `InpPayoutMode` に含める。
- docs/349 §9c〜§9f の合計(375 万)は本稿の 292 万(膝採用なら 280 万)に読み替える。§9d の月別表も 1-Step 分(5〜27 万/月)を 1/5 に読み替え。11/6 朝からの `optimizer_daily` は新モデルで走るので、候補の再現性もそこから見直し。
- FN Instant の +5% 出金規則(docs/349 §9f 追記 4)は床の頭打ち後に緩衝を薄くする向きに働く。口座が小さいので規則は維持するが、Q157(スワップ)と合わせて 12 月改定で「Tier 2 到達まで出金しない」案を比較する候補。
- docs/382・docs/385(FTMO スケーリング)の FTMO 50k の数値はロール運用でほぼ不変(+2 万/月)。再計算は不要。
