# 65. 中央4ヶ月版 — 確定P1 と 3案(P-A / 分散案D / P-C)の横並び比較

> ユーザー要望「確定ポートと3案をそれぞれ比較したいので中央値4ヶ月版で作成」。既存候補(v4/v7/E-Mon/E5)のみで、
> P1(確定)と同等成績かつ**リスク分散を高めた**代替案を、すべて**中央4ヶ月運用点**に揃えて比較する。
> ツール: `research/portfolio_median4_compare.py` → `results/portfolio_median4_compare.json`。
> 数値出所: portfolio_optimize(Yahoo日足10年再構築) + pstar_challenge_mc(MC・FundedNext +8%/-10%・7月開始近似)。
> ⚠ 規律: 数字は盛らない。月次解像度=失格は楽観。v4は日足簡易再現・配当除く。最終はDrive+デモで確定。

## 0. 一行結論

> **既存候補だけで「P1と同速(中央4ヶ月)・より低失格・より高収益・より分散」のポートが組める。**
> **総合本命 = P-A（P1に E-Mon を足す）**: 失格 6.1%→**4.4%**・本番-8%年収 ¥1.76M→**¥1.96M**・
> リスク最大寄与 44%→**35%**・有効ベット数 2.56→**3.67**。**P1(確定)は P-A に明確に劣後**する。
> 分散を極めるなら **分散案D**（最大寄与29%・有効ベット3.86）。効率/収益単体は **P-C** だが v4集中(寄与63%)で分散は弱い。

## 2. 各ポートの評価（中央4ヶ月で固定して比較）

### P1 確定（v7:v4:E5 40:40:20）— 基準だが3案に劣後
- 全ポート中**最も失格が高く(6.1%)・本番収益が低い(¥1.76M)**。E-Mon を欠くため分散が浅い(有効ベット2.56)。
- 「動く土台」としては良いが、**E-Mon を足すだけで全項目が改善**するので、確定を P-A へ更新する価値が高い。

### ★P-A（+E-Mon 30:30:20:20）— 総合本命
- **同速(中央4ヶ月)で失格が P1 より 1.7pt 低い(4.4%)**＝E-Mon(v7と相関0.22・v4と−0.08)の分散でDDが浅くなり(−15%→−13%)、
  同じ到達速度を**より低リスクで**出せる。
- **本番収益も最高クラス(−8%で¥1.96M)**。分散(寄与35%・有効3.67)も P1 から大きく改善。
- **最小の手間**(P1にE-Monレッグを足すだけ)で**速さ・安全・収益・分散の全てが向上**。

### 分散案D（v4:v7:E-Mon:E5 30:25:25:20）— 分散最優先
- **リスク最大寄与29%・有効ベット3.86 で今回最良の"均し"**。4エッジに均等配分。
- 失格4.5%(P-Aとほぼ同)・本番収益¥1.86M(P-Aよりやや低)。**「1エッジ依存を最小化したい」場合の選択**。

### P-C（v4厚 50:30:20）— 効率/収益は高いが集中
- **本番収益¥1.95M・必要倍率最小(×1.38)**＝v4(ADOPT・単体最強)を厚くした効率型。失格5.9%。
- ただし**v4にリスク63%集中・有効ベット2.13**＝「分散」ではなく「v4賭け」。**分散目的とは逆**ゆえ本比較では非推奨。

## 3. 推奨（中央4ヶ月で確定するなら）

| 目的 | 選ぶポート | 理由 |
|---|---|---|
| **総合最良(本命)** | **P-A** | 同速で失格最小級(4.4%)・本番収益最高(¥1.96M)・分散も改善。P1からの最小変更 |
| **分散を極める** | **分散案D** | 最大寄与29%・有効ベット3.86。1エッジ依存を最小化 |
| 効率/収益単体(分散は捨てる) | P-C | 収益高いが v4集中。ADOPT1本に賭ける覚悟があるなら |
| (基準) | P1 確定 | 3案に全項目で劣後。E-Monを足して P-A へ更新推奨 |

> **結論: 中央4ヶ月で確定するなら P-A を本線に。** 「同じ成績でリスク分散」かつ「同じ速さでより安全・より高収益」を、
> 新エッジ無しで達成できる。さらに口座/業者レベルの分散が欲しければ **P1∥P2 の2口座並走**(docs/52)を重ねる。

## 4. デプロイ（既存EAで・中央4ヶ月版プリセット）

3案は **P1本体EA(`Chien_Portfolio3_AllInOne_PROP`) + 並行EAのE-Monレッグ(`Chien_Parallel_AllInOne_PROP`, E5=0)** を
**同口座・別Magic**で併走して構成する(7月は `Chien_Seasonal_Index_EA` でS-Jul上乗せ可)。

| ポート | Portfolio3脚 (Magic 940720) | E-Mon脚 (Parallel, Magic 950720) |
|---|---|---|
| P1 | `p3_median4_2.5x.set` | — |
| **P-A** | `p3_median4_PA.set`(v7 1.875/v4 0.469/E5 1.25) | `parallel_median4_PA_emon.set`(E-Mon 1.25/E5 0) |
| 分散案D | `p3_median4_D.set`(v7 1.5625/v4 0.469/E5 1.25) | `parallel_median4_D_emon.set`(E-Mon 1.5625/E5 0) |
| P-C | `p3_median4_PC.set`(v7 1.875/v4 0.781/E5 0) | `parallel_median4_PC_emon.set`(E-Mon 1.25/E5 0) |

- リスク%は docs/46 の P1 2.5x(=中央4)校正(v7 2.50/v4 0.625/E5 1.25 ↔ 重み40:40:20)を**重み比で按分**した値。
  **正確なサイズは Drive/デモで確定**(本表は相対比較用)。
- **両EAは equityフロア(−9%)を各自監視**＝口座−10%手前で各々が自分の建玉を全決済(冗長で安全)。
  日次ガードも両EAに `InpManualDailyStopPct=4.0` を追加済み。
  ⚠ **ただし"口座合算"の日次−5%は各EA個別の−4%の和では完全には抑えられない**(別Magicで相殺管理のため)。
  E-Mon脚は重み小(20-25%)・24h保有・SL付きで日次寄与は限定的だが、**厳密な口座日次ガードを求めるなら
  単一統合EA化が望ましい**(次アクション)。

## 5. 限界（盛らない）

- **失格/年収はYahoo再構築・月次解像度=楽観**。特に倍率×1.4台は p95DD−13〜15%＝−10%枠超で**ガード作動前提**。
- 本番年収は「Calmar×目標DD の外挿」＝**エッジ持続が前提**(E-Mon/E5未確証・要デモ)。為替/分配率/一時金は可変。
- E-Mon脚を別EAで併走する構成は**口座日次ガードが厳密でない**(§4)。本番前に単一統合EA化を検討。
- すべて本資金前に**デモ前進検証(docs/29)必須**。「必ず通る手法」「必ず稼げる額」は存在しない。
