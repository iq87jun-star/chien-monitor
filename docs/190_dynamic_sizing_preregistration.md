# 190.【事前登録】バッファ依存・動的サイジング — プロップ固有の非対称性を使い切る

> 2026-09-01作成。docs/185 §5に適合する**費用ゼロの研究**。既存EAへの横断改良の評価。
> 本docのルールは`research/dynamic_sizing_mc.py`の実行**前**に凍結した。実行後の変更禁止。
> ⚠ 本研究の結果を理由に**稼働中8口座のサイジングを途中変更しない**(docs/174 §1・
> docs/179 §4)。反映先は期限到来時のEA更新および新規トラックの設計のみ。

## 1. 動機 — 現行サイジングは2状態しかない

稼働中の全EAは「**固定倍率 + 利益ロック(目標到達で全決済・停止)**」であり、
口座の状態(バッファ)に応じたサイジングを持たない。しかしプロップ口座では:

1. **含み益はそのまま追加の損失許容枠である。** 静的−10%が初期残高基準なら、+5%地点では
   フロアまでの距離は実質15%ある。現行は+5%でも0%でも同じ倍率で張っており、
   **プロップ最大の非対称性を使い残している**。
2. 逆に損失側では、フロアが近いのに同じ倍率で張り続ける。docs/181のD案は
   「12ヶ月最悪日−3.19%」で走っており、フロア接近時の減速機構がない。
3. **倍率は焼き込みの静的値**である。docs/184でD案の選抜窓(6〜8月)が「極端に静か」だったため
   倍率5.0が校正されたが、その後の実現ボラが上がっても倍率は下がらない。
   これが「静かな窓で選んで荒れた窓で走る」事故の増幅器になっている。

docs/185が「丁半博打(マーチンゲール型)の定量却下」を既に記録している通り、
**負けで張り増す方向は却下済み**である。本研究が評価するのはその逆
(アンチマーチンゲール=バッファに比例して張る)であり、思想的に矛盾しない。

## 2. アーム定義(実行前固定)

初期倍率 `mult0` は各構成の配備値をそのまま用いる。日々のサイジングは:

```
mult_t = mult0 × scale_t          scale_t ∈ [0.5, 1.5](全アーム共通のクリップ)
```

| アーム | scale_t の定義 |
|---|---|
| `FIXED` | `1.0`(**現行=ベースライン**) |
| `BUFFER` | `(d_t / d_0)^γ`, γ=1.0。`d_t` = 現エクイティからフェーズ内フロア(−10%)までの距離、`d_0`=0.10 |
| `BUFFER_G05` | 同上・γ=0.5(緩やかな反応) |
| `VOLTGT` | `σ_target / σ_realized(20日)`。`σ_target` = 当該構成の全期間日次std |
| `BOTH` | `BUFFER × VOLTGT` の積を [0.5, 1.5] に再クリップ |

- クリップ [0.5, 1.5] は全アーム共通の事前固定値。上限1.5は「利益で走る」際の暴走防止、
  下限0.5は「減速しすぎて時間切れ失格になる」ことの防止。
- EAの日次ガード(−4%クリップ)は**全アームに従来通り適用**する。ガードを外した評価はしない。
- フェーズ移行(P1→P2)時は `d_0` をリセットする(現行EAの`BaselineReset`と同じ扱い)。

## 4. MC条件(実行前固定)

- FTMO 2-Step(P1+10%→P2+5%)と FN Stellar(P1+8%→P2+5%)の両土俵
- 静的−10%・EAガード−4%クリップ・5日ブロックブートストラップ・シード7・1万パス
- サンプルは **直近12ヶ月(中間)** と **全期間(悲観)** の2バウンド
  (選抜窓バウンドは docs/181 §2 の通り「無意味に近い」ため本研究では出さない)
- 主要評価軸: **失格率**・**資金化率**・**資金化所要日数中央値**の3点同時比較。
  1軸だけ良くなる案は採らない(速くなっても失格が増えるなら意味がない)

## 5. 採否の判定基準(実行前固定・後知恵の禁止)

| 結果 | 判定 |
|---|---|
| あるアームが**全4構成・両土俵・両バウンド**で FIXED に対し「失格率が下がり、かつ資金化率が下がらない」 | **採用候補**。次回EA更新で実装 |
| 一部でしか改善しない | **不採用**。構成依存の改良は選抜ノイズと同種の後知恵になる |
| 資金化率が上がるが失格率も上がる | **不採用**(掛金の回転を速めるだけでEVを改善しない) |

- 採用候補になった場合でも、実装は**次回再スクリーニング時のEA更新**に載せる。
  稼働中口座の途中差し替えはしない(docs/182 §8のPipOf対応と同じ扱い)。
- 実装時の追加検証: MT5テスターでのパリティ確認(docs/09方式)を配備前必須とする。

## 6. 承知している限界

- ブロックブートストラップはリターンの系列相関を5日ブロックでしか保存しない。
  バッファ依存サイジングは**トレンド継続性に敏感**であり、この近似は本研究に有利にも
  不利にも働き得る。結果は「MC上の差」であって実口座での差の保証ではない。
- 実現ボラの20日窓は事前固定であり最適化しない(窓長を探索すると本研究自体が
  docs/184で問題になった選抜ノイズを再生産するため)。
