# Chrome ウェブストア: 3つの拡張の提出(人が入力・Cowork は準備と動作確認)

**Chrome ウェブストアのページ(デベロッパーダッシュボードを含む)は、Chrome の仕様で拡張機能から読み取り・操作できない**
(Claude in Chrome では「The extensions gallery cannot be scripted.」と出る。Issue #64 で確認)。
そのため作業A〜Cの**ダッシュボードへの入力は人が行う**。Cowork は、貼る文章の準備(コピー用のページ作り)と、
作業D(サイトでの表示の確認)を行う。

| 作業 | 拡張 | 内容 | 誰が |
|---|---|---|---|
| 準備 | 3つとも | 貼る文章・ファイルをまとめたコピー用のページを作る | Cowork |
| A | トレカ海外相場チェッカー | 更新版(v0.3.1)の zip をアップロード | ★人 |
| B | 求人 年収チェッカー | 却下された説明文を貼り替え(キーワード スパム対策) | ★人 |
| C | 物件 単価・月額チェッカー | 新しいアイテムとして掲載情報をすべて入力 | ★人 |
| D(任意) | 求人・物件 | まだ確かめていないサイトで表示を確認 | Cowork(拡張の読み込みは★人) |

作業Aは、GitHub の Secrets に Chrome ウェブストア API の鍵を登録すると、タグを付けるだけで自動にできる
(`extension/store/` の自動公開の説明)。作業B・Cの掲載情報の入力は API ではできないので、人が行う。

## 守ること(Cowork 向け)

- Chrome ウェブストアのページは開いても操作できないので、**操作しようとしない**
- Google アカウントのパスワード・2段階認証コードを入力しない
- 求人サイト・不動産サイトでは**閲覧だけ**を行う。応募・問い合わせ・会員登録・ログイン・お気に入り登録はしない
- 文章はこの文書と各拡張の `store/listing.md` に書かれたものだけを使い、自分で文章を作らない。
  特に**説明文にサイト名(求人サイト・不動産サイトの名前)を書き足さない**(キーワード スパムで却下される)

## 事前準備(★人が行う)

1. Chrome で GitHub にログインしておく
2. Cowork に「https://github.com/iq87jun-star/chien-monitor/blob/main/extension/store/cowork-chrome-3.md の
   準備(と D)をして」と伝える

ファイルは GitHub から取る([cowork/README.md](../../cowork/README.md) の「ファイルの取り方」):

- `cowork-files` の `chrome/` にある zip(展開せずにそのままアップロードする)
  - `pokeca-kaigai-checker-0.3.1.zip`(トレカ)・`job-salary-checker-0.1.1.zip`(求人)・`realty-price-checker-0.1.0.zip`(物件)
  - バージョン番号は更新で変わることがある。`chrome/` にある最新のものを使う
- 掲載文・スクリーンショット・アイコンは、リポジトリ全体(「Code」→「Download ZIP」)の中

## 準備: コピー用のページを作る(Cowork)

次の文章を、1つずつ「コピー」ボタンで写せるページ(または文書)にまとめて人に渡す。
``` で囲まれた部分の中身だけを使い、``` の行自体は入れない。**文章は一字も変えない**。

- トレカ: `extension/store/listing.md` の「説明」
- 求人: `job-extension/store/listing.md` の「概要」「説明」
- 物件: `realty-extension/store/listing.md` の「概要」「説明」と「プライバシーへの取り組み」の各項目
  (単一用途の説明、storage 権限が必要な理由、コンテンツスクリプトが必要な理由、プライバシーポリシーURL)

求人・物件の「説明」には「■ 広告について」の節がある(「PR」と明記した紹介リンクの開示)。消さずにそのまま入れる。

## 作業A: トレカ海外相場チェッカーの更新版をアップロード(★人)

1. [デベロッパーダッシュボード](https://chrome.google.com/webstore/devconsole)で「トレカ海外相場チェッカー」を開く
2. 「パッケージ」タブ →「新しいパッケージをアップロード」で `chrome/pokeca-kaigai-checker-0.3.1.zip` を選ぶ
3. 「ストアの掲載情報」タブの「説明」が、コピー用のページのトレカの説明と違えば置き換える
4. 「審査に提出」(バージョンが 0.3.1 になっているか確かめてから)

## 作業B: 求人 年収チェッカーの説明文を貼り替え(★人)

1. ダッシュボードで「求人 年収チェッカー」を開く
2. 「パッケージ」タブ →「新しいパッケージをアップロード」で `chrome/job-salary-checker-0.1.1.zip` を選ぶ
   (Issue #66 の表示確認で見つかった読み取りの不具合を直した版)
3. 「ストアの掲載情報」タブの「説明」欄を**全部消してから**、コピー用のページの求人の説明を貼る。
   「■ 対応サイト」や求人サイトの名前が**残っていないか**確認する
4. 概要が違えば置き換える
5. バージョンが 0.1.1 になっているか確かめて「審査に提出」

## 作業C: 物件 単価・月額チェッカーを新しく登録(★人)

1. ダッシュボードで「新しいアイテム」を押し、`chrome/realty-price-checker-0.1.0.zip` をアップロードする
2. 「ストアの掲載情報」タブ:
   - 説明: コピー用のページの物件の説明
   - カテゴリ: 「仕事効率化」、言語: 「日本語」
   - アイコン: `realty-extension/icons/icon128.png`
   - スクリーンショット: `realty-extension/store/screenshots/` の `1-rent.png`・`2-sale.png`・`3-investment.png`(1280x800)
3. 「プライバシーへの取り組み」タブ: コピー用のページのとおりに入力する
   - リモートコードの使用: いいえ
   - データの使用: 収集するデータの種類はすべて「いいえ」、下部の3項目にチェック
4. 「配布」タブ(表示される場合): 公開、すべての地域(または日本)
5. 「審査に提出」

## 作業D(任意): まだ確かめていないサイトで表示を確認(Cowork・拡張の読み込みは★人が行う)

事前に(★人が)`chrome://extensions` でデベロッパーモードをオンにし、「パッケージ化されていない拡張機能を
読み込む」で、展開したフォルダの `job-extension` と `realty-extension` をそれぞれ選んでおく。

### 求人 年収チェッカー

次の各サイトで職種(例: 「営業」「エンジニア」「事務」)を検索し、**求人の詳細ページ**を各サイト2〜3件開いて、
画面右下に「💴 年収チェック」と書かれた白い枠が出るか確認する。検索結果の一覧ページには出ないのが正しい。

- doda、マイナビ転職、リクナビNEXT、Indeed、ハローワークインターネットサービス

| サイト | 求人のタイトル | 表示された? | 表示された年収の目安 | 給与欄に書かれていた内容(そのまま) | おかしい点 |
|---|---|---|---|---|---|

### 物件 単価・月額チェッカー

次の各サイトで賃貸・中古マンション・投資物件を検索し、**物件の詳細ページ**を各サイト2〜3件開いて、
画面右下に「🏠 家賃チェック」または「🏠 価格チェック」と書かれた白い枠が出るか確認する。検索結果の一覧ページには出ないのが正しい。

- LIFULL HOME'S、アットホーム、CHINTAI、Yahoo!不動産、楽待

| サイト | 物件名 | 種類(賃貸/売買/投資) | 表示された? | 表示された月額・単価 | ページの賃料・価格・面積(そのまま) | おかしい点 |
|---|---|---|---|---|---|---|

- 「おかしい点」には、表示が出ない・金額が違う・一覧ページで出てしまう、などを書く
- **表示が出ないページがあれば**、そのページの賃料(給与)欄の見出しの文字(例: 「賃料」「給与」)を書き添える
- この表は Issue の「報告の表」に書く(下の「報告」)

## 報告(Cowork)

作業が終わった時・止まった時は、人に知らせるのに加えて、[cowork/README.md](../../cowork/README.md) の
「報告の出し方」のとおり GitHub の Issue(「Cowork の作業報告」)に結果と報告の表を書き、Issue の番号を人に伝える。

## 修正が必要な時(★人が行う)

作業Dで直すところが見つかった場合は、Claude Code に「Issue #番号 に報告を出しました」と伝えて修正版を作ってもらう。
求人・物件は、作業Dを先に済ませてから作業B・Cで提出した方が、却下や低評価を避けられる。
