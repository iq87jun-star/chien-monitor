# 優待クロス(株主優待のつなぎ売り)判定と紙上フォワード

現物買いと同じ株数の信用売りを同時に建て、権利付最終日の翌営業日に**現渡し**で相殺する。
値動きの損益は打ち消し合うので、残るのは **優待価値 − 費用**。
費用のうち読めないのは**逆日歩**(制度信用の売り方が払う品貸料)だけで、これには日証金が公表する**最高料率**という上限がある。
このフォルダは「上限で計算してもプラスか」を毎営業日判定し、権利付最終日を過ぎたら実際の逆日歩で採点する。

## 毎日の流れ(GitHub Actions `yutai`・平日 JST 11:07)

1. `node fetch.js` … 日証金の品貸料率一覧(`shina.csv`)と貸借取引残高(`zandaka.csv`)を取得。
   品貸料率一覧は**その日の分しか公開されない**ので、`data/jsf/shina-<申込日>.csv` として毎日ためる(採点の元データ)。
2. `node report.js` … `candidates.csv` の候補を判定して `report.md` を更新。
   Secret `YUTAI_DISCORD_WEBHOOK` があれば、権利付最終日が 5 営業日以内の候補と、前営業日の採点を Discord に送る。

日証金の更新は JST 10:30 ごろ(前営業日の申込日分)。権利付最終日の 11:07 のレポートが、その日の発注前の最終判定になる。

## 自分でやること

- `candidates.csv` に候補を書く(1 行 1 銘柄)。

| 列 | 中身 |
|---|---|
| コード / 銘柄名 | 4 桁(英字入りも可) |
| 権利確定日 | `2026-11-30` 形式。会社の IR で確認 |
| 必要株数 | 優待をもらえる最小株数 |
| 優待価値円 | **実際に売れる値段**(メルカリ等の売れた値段)か、自分で使う場合の価値。額面ではない |
| 1株配当円 | 予想配当。課税口座ではクロスで配当の約 20% が費用になる |
| 一般在庫 | `あり` / `なし` / `不明`。証券会社の一般信用(短期・いちにち信用など)の在庫を見て書く |
| 一般で入る日 | 一般信用で先に建てる日(空なら権利付最終日) |
| 株価 | 空なら日証金データの値段を使う |

- `config.json` を自分の証券会社の条件(貸株料・手数料)に合わせる。
- 長期保有が条件の優待(「1 年以上継続保有」など)はクロスではもらえないので候補にしない。

## 判定の中身(`src/cost.js`)

- **制度信用**: 権利付最終日に入る。逆日歩の最悪 = 最高料率 × 品貸日数 × 株数。
  最高料率は日証金データにあればそれを、無ければ推定(貸借値段の 0.2% を 0.2 円単位に切り上げ・下限 1 円。2026-10-29 のデータでは 1,020 銘柄中 879 銘柄がこの式どおり、74 銘柄が 2 倍)。
  日証金が引き上げることがあるので、**最悪 × `maxRateStress`(既定 2)でもプラス**なら「制度信用で入る」。
- **一般信用**: 逆日歩なし。費用は貸株料 × 保有日数。在庫が `なし` 以外でプラスなら優先。
- 日証金の制限が `停止`(新規売り停止)なら制度信用は不可。`注意` と品貸日数 3 日以上(連休またぎ)は注記。

## 検証計画(事前登録)

実際にお金を入れる前に、紙の上で次を確かめる。条件と基準は**結果を見る前に**ここで固定する。

- **期間**: 2026-11 末権利 〜 2027-03 末権利(5 か月。12 月末の年末年始 5 日またぎと、権利が集中する 2・3 月を含む)。
- **見るもの**(`report.md` の「紙上フォワード」の集計):
  1. 実際の逆日歩が「引き上げ想定(最悪 × 2)」以内に収まった割合
  2. 「制度信用で入る」と判定した候補の、実際の損益の合計と赤字の件数
- **合格(少額で実際に始める)**: 判定件数 20 件以上 / 1 が 95% 以上 / 2 の合計がプラスで赤字が全体の 1 割以下。
- **不合格(見直す)**: 引き上げ想定を超えた件数が 2 件以上なら、`maxRateStress` を上げて**次の期間でやり直す**(同じ期間に当てはめ直して合格にはしない)。
- **実際に始めた後の停止基準**: 1 件で優待価値を超える赤字が出たら停止して原因を確認。月の損益が 2 か月続けてマイナスなら停止。
- 最初は**一般信用(逆日歩なし)の候補だけ**で始め、制度信用は紙上の成績が合格してから。

## 注意

- 発注は自動化しない(このツールは候補と判定まで)。現物買いと信用売りは**同じ寄付の成行**で同時に出す(値段がずれると、その分は相殺されない)。
- 現渡し・信用の手数料・貸株料の端数処理は証券会社で違うので、最初の数件は実際の明細と見比べる。
- 休業日カレンダー(`src/calendar.js`)は 2026〜2027 年分。年が変わる前に JPX の公表どおりに足す(範囲外の日付はエラーで止まる)。
- 日証金のデータは個人の研究用に 1 日 1 回だけ取得している。

## コマンド

```sh
cd yutai
npm test                 # 単体テスト
node fetch.js            # 日証金データの取得
node report.js           # report.md の作成
YUTAI_TODAY=2026-11-26 node report.js   # 基準日を変えて試す
YUTAI_KEEP_SAMPLE=1 node report.js      # candidates.csv のサンプル行(9999)も判定する
```
