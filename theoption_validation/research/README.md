# 毎日の改良検証(2026-11-27 開始・ユーザー指示)
ユーザー「毎日期待値があがるような工夫を、現在の手法や検証体験を抽象化、横展開の形で検証する様に仕組み作りをお願いします」。
毎朝 7 時(07:04 JST)の定期実行で、下の「原理」から 待ちの案をまとめて、先に型と合格条件を記録してから 10 年データで確かめ、結果を台帳に残す。

## 1. 決まり(毎回守る)
1. **待ち行列は溜めずに消化する**(2026-11-27 ユーザー指示「案が出たら、1日1本ではなく案を消化して下さい」)。1 回の実行で、待ちの案を時間の許すかぎり全部確かめる。先に `ideas.csv` へ全部の「仮説・型・合格条件」を書いてコミットし、その後に計算する。計算後に型やしきい値を変えない。
2. **発注は変えない。** 合格しても、やることは「紙上追跡に追加」か「ユーザーへの提案」まで。本番の変更はユーザーの「進めて」があってから。
3. **合格条件(既定)**: (a) 全期間・前半(〜2021-11)・後半で同じ向き、かつそれぞれ基準を満たす、(b) 年度別 10 年中 7 年以上で同じ向き、(c) 日単位にまとめた z ≥ 2.5(同じ日に同じ向きの本数は 1 回と数える)、(d) 直近 12 か月が損益分岐以上、(e) 配分に使う場合は `portfolio.py` で前半・後半とも月平均が現行以上かつ最大DD が 1.05 倍以内。新しい脚は合格線 = 損益分岐 + 3pt(23H 54.28 / 1H 55.63 / 15M 57.05)、既存の脚との月次相関 0.2 未満なら「連動しない脚」。「惜しい」= 向きの条件は満たすが z が 2.0〜2.5。
4. **多重検定の勘定**: 累計の検証本数を `ideas.csv` で数える。まとめて消化すると偶然の合格が増える(z 2.5 なら 160 本に 1 本)。だから合格 = 採用ではなく、紙上追跡(前向きの記録)を必ず挟む。z ≥ 3.0 を「強い合格」として区別する。
5. **データ**: 必ずミッド(bid だけの足は 06:00 JST の判定で数 pt ずれる)。既存脚の取引は `data/trades_*.json`(10 年・条件つき)。追加の分足は `fetch_fxcm.py`。判定時刻・建て時刻は商品の実際の時刻に合わせる。
6. **過去に棄却した案は繰り返さない**(`../README.md` の追補一覧と `ideas.csv` を先に見る)。同じ案の言い換え・しきい値違いも不可。
7. **結果を次の案に生かす**(ユーザー指示「採用になったり、非採用であっても惜しい案については、抽象化してアイデア出しに生かす」)。合格・惜しい案が出たら、その回のうちに (i) 何が効いたのかを 1 行に抽象化して「2. 原理」に足すか既存の原理を書き直し、(ii) そこから横展開した案を 1〜3 本、待ち行列に足す。不合格からも「この方向は効かない」という学びを原理の落とし穴(P7)に足す。足した案は次の回で消化する(同じ回で連鎖させない = 結果を見ながらの掘り下げを避ける)。
8. **報告**: 合格・惜しい結果・運用に関わる発見があった日は、結論から短く報告する。不合格だけの日は台帳に残して静かに終える(週次リサーチで週のまとめを出す)。ユーザーに頼まれて実行した回は必ず報告する。
9. 案が尽きたら無理に作らない。その日は「案なし」と記録し、原理の見直し(新しい抽象化)を 1 つ書く。

## 2. 原理(これまでの手法と検証体験の抽象化)
| 記号 | 原理 | 根拠になった結果 |
|---|---|---|
| P1 | **決まった時刻の実需の売買は、直前に片寄り、直後に戻る。** | 仲値後の反落(ゴトー日 09:55 LOW 64%)、月末の値決め前のドル売り(株高の月 63%) |
| P2 | **建てる直前に逆へ動いているほど、戻りが強い。** 見送りではなく賭け金の強弱に使う。 | 金曜下落 → 月曜 HIGH(+6.0pt・10/10 年)、仲値前の上げ → LOW(+8.3pt)。AUDJPY 02:00 × 当日下げは +4.9pt(z 2.26 で惜しい) |
| P3 | **商品の作りに合う形だけが残る。** 23H は遅く買っても 1.95 倍。1H・15M は時刻だけでは優位が無い。 | 23H 552 セル中 10(すべて深夜の円クロス HIGH)、1H 504 セル中 0 |
| P4 | **暦の状態で効き方が変わる。** | 日本の祝日の月曜 47.5%、25 日の仲値 70%、月末 58〜61%、米国の祝日は商品の満期が短縮(11/26) |
| P5 | **両側とも損益分岐を超えるなら配分、片側が下回るならフィルター。** | 強弱 2 つ(配分)、祝日の月曜・株安の月の月末脚(フィルター) |
| P6 | **向きを信号で決める脚は、向きが固定の脚と連動しにくい。** | 月末脚の月次相関 +0.03 |

## 3. 横展開の作り方(案の出し方)
- **原理 × まだ当てていない対象**: 例) P2 を EURGBP に別の窓で、P4 を米国の祝日に、P1 を別の値決め時刻に。
- **既存の条件の「量」への拡張**: 符号だけでなく大きさ(三分位)で強弱を変える。ただし 1 仮説 1 しきい値。
- **運用の実測からの案**: 拒否(213)の出方、判定レートの偏り、満期の短縮など、記録から見つかったこと。
- **落とし穴の逆利用**: 既存脚の弱い状態(年・月・曜日)を事後に切るのは不可(P7)。仕組みの説明がつく状態だけ。

## 4. ファイル
- `ideas.csv`: 台帳(id, 登録日, 原理, 仮説と型, 合格条件, 状態, 結果, 追補番号)。
- `portfolio.py`: 配分・条件・新しい脚を足した場合の月平均 / 最大DD / 最悪月(現行 v1.19 = 強弱オン・月末脚込み・×1.67)。
- `data/trades_night_10y.json`・`trades_nakane_10y.json`: 既存 10 脚の 10 年の取引(条件つき)。`trades_newlegs_10y.json`: 窓埋め(G)・月末脚(M)。
- `legs_night.py`・`legs_nakane.py`: 上の取引を作り直すスクリプト(引数 = to_live.py のある場所、価格データの場所)。`cond_report.py`: 条件あり / なしの比較。`example_newlegs.py`: 新しい脚の検証例。
- `fetch_fxcm.py`: 1 分足の取得。`data/duka_ticks.tar.gz`: FXCM に無い時刻のティック(取り直しに時間がかかるため保存)。
