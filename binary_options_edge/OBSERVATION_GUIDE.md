# 気配観察実験ガイド（H2/H3のキル条件を最小コストで判定する）

THEORY.md の結論: 各仮説の生死は**少数のスナップショット観察**で決まる。
本ガイドはその記録手順。記録したCSVを

```bash
python -m binary_options_edge.observation observations.csv
```

に通すと、スナップショットごとに「生存/棄却/判定不能」と根拠が機械判定される。
テンプレート: `observations_template.csv`（例3行を実測値で置き換える）。

---

## 1. 観察スケジュール（直近の機会, JST）

| 日時 (JST) | イベント | 仮説 | 想定ジャンプ σ_J |
|---|---|---|---|
| **7/30(木) 3:00** | FOMC政策金利+パウエル会見(3:30) | H3 | 0.002–0.004 |
| **8/7(金) 21:30** | 米雇用統計(NFP) | H3 | 0.003 |
| **8/12(水) 21:30** | 米CPI | H3 | 0.001–0.002 |
| 平日 13:00 / 15:55 / 27:00(=翌3:00) | セッション境界(東京昼/ロンドン直前/NY遅番) | H2 | — |

H3は**発表60分前・30分前・10分前**の3回記録が理想（1回でも可）。
H2は同じ3時点を2–3営業日繰り返すと判定が安定する。

## 2. 何を記録するか（H3: 指標発表前）

対象: 発表時刻を**満期までの窓に含む**2時間物（例: 21:30発表なら22:00判定の回号）。

1. **銘柄選択**: 現値から **25–40pips 離れた**上側ラダー（finish above）とワンタッチ。
   （残存1時間・σ=10%なら1σ≈16pips。25–40pipsが理論感度の高い d≈1.5–2.5 帯）
2. 記録項目（CSV列）:
   - `timestamp` 記録時刻 / `expiry` 判定時刻（いずれもJST, `2026-08-07 21:20` 形式）
   - `spot` 現値 / `level` ストライクまたはバリア
   - `bid`, `ask` 提示ポイント。**提示が消えていたら空欄にして `halted=1`**
   - `hypothesis=H3`, `jump_std_log` 上表のσ_J
3. スクリーンショットも保存しておく（後から入力誤りを検証できる唯一の証拠）。

**判定ロジック（自動）**: 提示停止 or スプレッド>15pt → 棄却（取れない）。
mid がジャンプ込みFVより半スプレッド超割安 → **生存**。ジャンプ込みFV近傍 → 棄却（織り込み済み）。

## 3. 何を記録するか（H2: セッション境界）

対象: 各記録時点で残存1–2時間の回号。現値から1σ（15–25pips）離れた上側ラダー。

追加で必要な2列（境界効果の判定に使う）:
- `sigma_trailing_ann`: 直近1時間の実現ボラ（年率）。
  簡易式: **σ ≈ 直近1時間の高値安値レンジ(%) × 58**（例: レンジ15pips/150円=0.10% → σ≈0.058=5.8%）
- `sigma_seasonal_ann`: 満期窓の季節ボラ。日平均ボラ×時間帯係数:

| 時間帯(JST) | 係数 |
|---|---|
| 東京昼 12–15時 | 0.6 |
| ロンドン序盤 16–18時 | 1.6 |
| NY重複 21–24時 | 1.5 |
| NY遅番 2–5時 | 0.7 |

**判定ロジック（自動）**: mid が季節FV±2pt以内 → 棄却（IGはカレンダー実装済み）。
mid がトレーリングFV寄りで季節FVと半スプレッド超乖離 → **生存**。

## 4. 判定の運用原則

- 「生存」1件では結論しない（入力誤差・ボラ推定誤差でも出る）。
  **独立した複数記録（別日・別イベント）で再現して初めて「エッジ候補」**。
- 「棄却」はそのまま棄却として記録し、README §7 の事前結論を維持する。
- 生存が再現した場合の次段階のみ、`data.py` の `IGQuoteSource` を実装した
  本格収集＋`backtest.py` での検証に進む（証明書ゲートはその先にある）。

## 5. 想定される最頻の結末（正直な事前分布）

1. H3: 発表前に提示停止 or スプレッド20pt超 → **棄却**（最も可能性が高い）
2. H2: mid が季節FVと一致 → **棄却**
3. どちらかで「生存」→ それ自体が発見。記録を増やして再現性を確認する。
