# 戦略探索エンジン

毎朝、仮説を事前固定プロトコルで検定し、結果を台帳に積む仕組み。

## なぜ「毎朝最良を探す」形にしなかったのか

探索空間を広げるほど偽陽性が増える。この会話で実測した通り:

- DOW族290セルの全数走査で、基準通過は1件(期待誤検出 0.4件)
- 販売ページ基準では 3年窓で18本「合格」するが、翌年運用すると PF 0.96
- 72構成の入れ替え戦略のうち40構成が PF<1.00

**毎朝「今日の最良戦略」を出す仕組みは、毎朝ノイズを報告する。**
そこで、見つけたものを報告するのではなく、**検定した回数を数え続ける**設計にした。

## 必要t値は累積検定数で決まる

| 累積検定数 | 必要t値 |
|---:|---:|
| 1 | 1.64 |
| 10 | 2.58 |
| 100 | 3.29 |
| 1,000 | 3.89 |
| 10,000 | 4.42 |
| 100,000 | 4.89 |

参考: この会話で最も強かった NAS100 月曜L は **t=3.42**。
つまり **1,000回検定した後では通らない**。探索を続けるほど基準が上がる。
これは仕様であって不具合ではない。

## 使い方

### 1. 仮説を追加する

`hypotheses.json` の `queue` に追記する:

```json
{
  "id": "zrev-idx-w10-t15-h2",
  "note": "指数 z(10) 1.5SD 逆張り 2日保有",
  "family": "zrev",
  "params": {"symbols": ["US500","NAS100","GER40"],
             "win": 10, "thr": 1.5, "hold": 2, "direction": 1},
  "space_size": 90,
  "status": "pending"
}
```

**`space_size` は「この仮説にたどり着くまでに裏で何通り検討したか」**を書く。
銘柄3 × 窓5通り × 閾値3通り × 保有2通り を眺めて1つ選んだなら 90。
ここを正直に書かないと必要t値が甘くなり、仕組み全体が意味を失う。

### 2. 実行

```
python3 run.py            # pending をすべて検定し、台帳に記録
python3 run.py --report   # 検定せず、台帳の要約だけ出す
```

結果は `REPORT.md`、履歴は `ledger.json`。

### 3. 台帳は消さない

同じ仮説を条件だけ変えて再投入すると累積検定数が増え、必要t値が上がる。
**こっそりチェリーピックできない**のが台帳の目的。

## 判定プロトコル v2(事前固定)

| 基準 | 内容 |
|---|---|
| 最低取引数 | 100(未満は「検証不能」) |
| **補正t値** | **t / √hold** が累積検定数に応じた Bonferroni 閾値以上 |
| IS/OOS | 前半60%・後半40% の**双方**でプラス |
| ウォークフォワード | 各年、それ以前のデータだけで平均プラスだった年のみ採用し、その合計がプラス |
| **対ベンチマーク** | **同一銘柄・同一保有日数の「常時買い持ち」を上回ること** |

5つすべてを満たして初めて「通過」。

### なぜ補正t値とベンチマークを入れたか(2026-08-27 v2)

初回の拡張検定で `volregime-idx`(指数8銘柄・高ボラ局面のみロング・5日保有)が
**生t=8.03 で通過**した。検証したところ偽の発見だった:

| 構成 | n | 平均 | t |
|---|--:|--:|--:|
| 高ボラのみロング | 10,995 | 21.96bp | 8.03 |
| **常時ロング(フィルタなし)** | 29,997 | 12.71bp | **8.98** |
| 高ボラのみ**ショート** | 10,995 | −39.96bp | **−14.62** |

フィルタなしの方が t が高く、ショートでは大きく負ける。
**局面効果ではなく単なる指数ロング**だった。

原因は2つ:

1. **建玉の重複**。日次シグナル × 5日保有では隣り合う取引が4/5重なり、
   独立でなくなって t 値が過大になる。→ `t/√hold` で補正
2. **方向性エクスポージャーとエッジの混同**。上昇バイアスのある資産を
   買い持ちすれば、どんなフィルタを噛ませても数字は出る。
   → 同一銘柄の常時買い持ちを上回ることを必須にした

補正後: 生t 8.03 → **補正t 3.59** < 必要4.25 で棄却。台帳も再判定済み。

## 実装済みの族(18)

### 価格・カレンダー系
| family | 内容 | 主なパラメータ |
|---|---|---|
| `dow` | 曜日 open-to-open | `dow`(0=月) `direction` `hold` |
| `dom` | 月内の第N営業日 | `day` `direction` `hold` |
| `tom` | 月末効果 | `before` `after` `direction` |
| `zrev` | z-score 逆張り | `win` `thr` `hold` `direction` |
| `mom` | モメンタム順張り | `look` `hold` `direction` |

### オシレーター系
| family | 内容 | 主なパラメータ |
|---|---|---|
| `rsi` | RSI しきい値割れ/超え | `n` `low` `high` `mode`(fade/follow) `hold` |
| `stoch` | ストキャス %K×%D 交差 | `n` `smooth` `low` `high` `hold` |
| `cci` | CCI ±しきい値 | `n` `thr` `mode` `hold` |
| `bb` | ボリンジャーバンド | `n` `k` `mode`(fade/break) `hold` |

### トレンド系
| family | 内容 | 主なパラメータ |
|---|---|---|
| `macd` | MACD シグナル交差 | `fast` `slow` `signal` `hold` |
| `macross` | 移動平均クロス | `fast` `slow` `kind`(sma/ema) `hold` |
| `ichimoku` | 一目均衡表 雲抜け | `tenkan` `kijun` `senkou` `hold` |
| `donchian` | ドンチャンチャネル | `n` `mode`(break/fade) `hold` |
| `adx` | ADX 閾値超え + DI交差 | `n` `thr` `hold` |

### 価格構造系
| family | 内容 | 主なパラメータ |
|---|---|---|
| `atrbreak` | ATR倍率超の急変 | `n` `k` `mode` `hold` |
| `gap` | 窓開けの埋め/追随 | `k` `n` `mode` `hold` |
| `rangebreak` | 前日高安ブレイク | `mode` `hold` |
| `streak` | N日連続の後 | `run` `mode` `hold` |
| `inout` | はらみ足/包み足 | `kind`(inside/outside) `direction` `hold` |
| `volregime` | ボラ局面フィルタ | `n` `ref` `high_vol` `direction` `hold` |

### 複数銘柄系
| family | 内容 | 主なパラメータ |
|---|---|---|
| `xsect` | 断面ランク 上位買い下位売り | `symbols` `look` `hold` `n_side` |
| `pairs` | 2銘柄スプレッドの平均回帰 | `a` `b` `win` `thr` `hold` |

`params` に `symbols`(リスト)を渡すと合成、`sym`(単体)を渡すと単一銘柄。
指標は `indicators.py`、族の実装は `families.py`。

## コスト前提

往復(名目比%): FX 0.020 / 指数 0.030 / 貴金属 0.050 / エネルギー 0.060
1泊追加保有ごとに FX +0.004 / 指数・貴金属 +0.015 / エネルギー +0.018

## データの限界(重要)

データは **Yahoo Finance の日足**。以下は測れない:

- **日中の時刻依存**(定石壱の「サーバー時間月曜4時」など)。日足の始値は
  FXでは 00:00 UTC、指数では現物の寄りであり、MT5の日足始値とは別物
- **実スプレッドの時間変動**(ロールオーバー時間帯の拡大など)
- **業者ごとのスワップ**

したがって `dow-jpy-mon`(円クロス月曜)がこのエンジンで棄却されても、
**定石壱が否定されたわけではない**。壱はMT5のH1実データ・サーバー時刻基準で
別途検証済み(1,636取引 / PF 1.304)。
このエンジンは**日足で表現できる仮説の一次スクリーニング**であり、
通過したものはMT5で再検証する必要がある。
