## 1. これは何か

販売用FX EAの種を探すための、日足ベースの一次スクリーニング。
毎朝22:00 UTC(7:00 JST)に自動実行される(Routine `trig_01CrkDfGNuauXDZd2mP9h4Ak`)。

**目的は「毎朝いい戦略を見つけること」ではない。**
探索空間を広げるほど偽陽性が増えるため、この仕組みは
**検定した回数を数え続け、それに応じて基準を上げる**ように作られている。

## 2. 棄却が正常な結果である

現状: 検定済み59件 / 累積検定数 8,447 / 必要t値 4.38。

**指標トラック(インジケーター用)は8件中4件通過。** — 中身は2.6節。

詳細は `../multi/RESULTS.md`。

**通過しなかったことを問題として報告しないこと。
基準を緩めないこと。通るまで条件を変えて再実行しないこと。**

> 台帳には「通過3件」と出るが、**3件とも指標トラック(変動幅の予測)**であって、
> 売買トラック(翌日の方向)は依然として**46件中0件**。混同しないこと。2.6節。

### 最も惜しかった棄却と、その潰し方(2026-08-27)

`breadth-idx-washout`(指数7銘柄のうち50日平均超が3割以下の局面だけロング・5日保有)が
**5基準のうち4つを満たし、補正t 4.288 対 必要 4.334 の 0.05 差で落ちた**。

記録上の数字だけ見ると強い(平均45.1bp / 常時買い持ち超過+30.9bp / OOS +59.5bp /
WF +34.6bp / PF 1.43 / 負け年 2/16)。**通過扱いで潰しにかかった結果、偽物だった。**

`python3 attack.py breadth-idx-washout` の出力より:

| 検査 | 結果 |
|---|---|
| 同一日を1観測に集約 | n 5,327 → **772日**、補正t 4.29 → **1.89** |
| 連続する成立日を1局面に集約 | **73局面**、勝ち62/73 |
| 寄与最大の2局面 | 2018-10〜12(50日)**−91bp**、2020-02〜04(43日)**−81bp** |

n=5,327 の実体は **772日 × 相関の高い7指数**であり、独立な観測はその7分の1しかない。
さらに勝ちは6〜9日の短い切り返し、負けは40〜50日続く下落局面に集中している。
**小さく何度も勝ち、たまに大きく負ける**形で、販売した瞬間に大損する典型。

## 2.5 t/√hold では足りない — 日次t診断(2026-08-27 追加)

上の検査で分かったのは `breadth-idx-washout` 単体の話ではない。

**`t/√hold` は保有期間の重複しか補正していない。同じ日に相関の高い複数銘柄を
建てている分は補正されていない。** 多銘柄合成の仮説はすべて t が過大に出る。

v2導入のきっかけになった `volregime-idx` を同じ検査にかけると:

| | 記録上 | 同一日集約後 |
|---|--:|--:|
| n | 10,995 | 2,850日 |
| 補正t | 3.59 | **1.18** |

そこで、全エントリに **`n_dates`(独立な日数)と `t_date`(日次集約後の補正t)**を
診断値として記録するようにした(既存41件にも遡って追記済み)。

**これは6番目の基準ではない。5基準は変更していない。** ただし運用ルールとして:

> **`t_date` が必要t値を下回る仮説は、v2の5基準を通過しても「見つけた」と報告しない。**
> 必ず `attack.py` にかけ、その出力を添えること。

台帳全41件のうち、記録上の補正t と `t_date` の差が大きいのは
`volregime-idx`(+2.41)と `breadth-idx-washout`(+2.39)、つまり
**通過に近づいた2件だけ**。差は「強く見えた仮説ほど大きい」。

`dom-idx-first` も示唆的で、補正t 1.38 に対し `t_date` は **−0.32**
(月1日 × 7指数 = 実質206観測)。

## 2.6 インジケーターも探索対象(2026-08-28 追加)

`fx-ea/indicator/` でインジケーター2本(定石零 環境計・定石弐 待ち伏せ)を
出品する。**EAとインジケーターは商品の性質が違うので、探索も2トラックにした。**

| | 売買トラック(EA) | **指標トラック(インジケーター)** |
|---|---|---|
| 当てにいくもの | 翌日の**方向** | 翌日の**変動幅**・いまの**局面** |
| 判定 | プロトコル v2(5基準) | **指標プロトコル v1**(5基準) |
| 対照 | 同一銘柄の常時買い持ち | **素朴な基準**(その銘柄の過去平均) |
| 結果 | 46件中 **通過0** | 5件中 **通過3** |

### なぜ分けたか

**46仮説すべてが「翌日の方向」を当てにいって、ひとつも通らなかった。**
インジケーターは方向を当てる必要がない。「いまどれくらい動きそうか」
「いまは荒れているか」を素朴な想定より正確に示せれば商品になる。
そして**変動幅は実際に予測できる**。方向と違って、これは測ると出る。

累積検定数は両トラックで**共有**する。見た回数は同じ台帳で数える。

### 指標プロトコル v1(事前固定)

| 基準 | 内容 |
|---|---|
| 最低観測数 | 100 |
| 補正t値 | 改善の t/√hold が累積検定数のBonferroni閾値以上 |
| IS/OOS | 前半60%・後半40%の**双方**で改善プラス |
| 年別一貫性 | 改善が正の年が**全年の80%以上** |
| 実用水準 | 平均改善 ÷ 平均素朴基準が**5%以上** |

「常時買い持ちを上回る」に相当する対照は、**改善 = 素朴基準の誤差 − 予測の誤差**
という定義に織り込み済み。

### 通過した4件

| id | n | 補正t | 日次t | 改善率 | 改善年 |
|---|--:|--:|--:|--:|--:|
| `i-rangefc-fx-sma` | 50,003 | 46.48 | **24.72** | +17.5% | **16/16** |
| `i-rangefc-idx-sma` | 25,835 | 38.32 | **21.82** | +19.3% | **16/16** |
| `i-rangefc-idx`(ATR版) | 25,835 | 20.33 | 11.00 | +11.2% | 13/16 |
| `i-interval-fx`(2026-08-30) | 47,546 | 31.59 | **15.42** | +9.7% | **15/15** |

`i-interval-fx` は点ではなく**区間**の予測。直近60本の分位で作った値幅の範囲が、
全履歴の分位で作った範囲より良いか(狭くて外さないか)を interval score で測った。
全13ペアで改善。**値幅計 v1.01 に取り込み済み。**

**ただし名目8割の区間に実際に入るのは8割ではない。**
実測は FX 77.3% / 指数 76.2%(最低 75.4%)。
販売資料には名目ではなく実測を書くこと。

上2件は `attack.py` を通した。**全20銘柄・全16年で改善**し、日次集約後も
必要t値を大きく上回る。合成が個別の失敗を隠していない。

> **これは「方向を当てられる」という意味ではない。**
> 「その銘柄の過去平均をそのまま想定するより、直近14日の平均のほうが
> 翌日の値幅をよく言い当てる」という意味しかない。売買の優位性は別の話。

### ATR を「翌日の高安幅の予測」に使うと外す

最初 `kind="atr"` で組んだところ FX が **生t −21** と大きくマイナスになった。
原因は私の予測子の選び方で、**ATRは真の値幅(ギャップ込み)なのに
予測対象は高安幅**という定義のずれ。ギャップの大きい銘柄ほど上振れする:

| | ATR14(真の値幅) | SMA14(高安幅) |
|---|--:|--:|
| USDJPY | −16.4% | +13.9% |
| JP225 | −11.4% | +13.4% |
| US500 | +10.4% | +18.4% |

予測子を対象と同じ高安幅で組み直すと**20銘柄すべてプラス**になった。

**ただしこれは 定石零 環境計 の欠陥を意味しない。** 環境計の ATR は
チャート時間足の「いまどれだけ動くか ÷ スプレッド」であって、
翌バーの高安幅の点予測ではない。用途が違う。日中足ではギャップも小さい。
**今後「翌日の想定変動幅」を日足で表示する商品を作る場合の注意点**として残す。

## 2.62 トレンド判定表示には中身がない(2026-08-28)

指標トラックで測った中で、商品設計に最も効く否定結果。

「いまトレンドが出ている」の表示に中身があるかを、効率比
(= |n本の正味の値動き| ÷ |1本ごとの値動きの合計|、1に近いほど一方向)で測った。
直近20本の効率比が、**次の20本**の効率比を、その銘柄の平年並みより
正確に言い当てられるか。

| id | n | 生t | 日次t | 改善率 | 改善年 |
|---|--:|--:|--:|--:|--:|
| `i-effratio-fx-r2` | 46,779 | **−82.99** | −56.18 | **−38.1%** | **0/15** |
| `i-effratio-idx-r2` | 24,099 | **−59.80** | −43.81 | **−38.9%** | **0/15** |

**中身がないどころか、平年並みをそのまま言うより明確に悪い。全15年で一度も改善しない。**

裏付け(重ならない連続窓どうしの相関):

| | 効率比の持続性 | 値幅の持続性 |
|---|--:|--:|
| EURUSD | **−0.117** | +0.079 |
| USDJPY | **+0.043** | +0.339 |

**値幅は持続する。トレンドらしさは持続しない。**
`i-rangefc-*-sma` が +17〜19% で通過したのと同じ物差しで測って −38%。

> **市場で最もよく売られているインジケーターの主張(トレンド判定)を
> 商品にしてはいけない。** 日足では測ると出ない。値幅は出る。

初回 `i-effratio-fx` は素朴基準の拡大平均が目的変数の窓と重なり、
**素朴基準側だけが未来を少し覗いていた**。実現値の積み上げを n 本遅らせて
再検定したが、−38.9% → −38.1% でほぼ変わらなかった。
(`i_rangefc` `i_gapsize` `i_volpersist` は目的変数が翌1本なので同じ問題はない)

### 実用水準の基準が効いた例

`i-gapsize-idx`(指数の翌日の窓の大きさ)は
**生t 9.13 / 日次t 6.17(必要4.37)/ 改善年 12/15** と統計的には確実に改善するが、
**改善率 4.9% で実用水準5%に届かず棄却**。
統計的に確実であることと、商品になる大きさであることは別。

## 3. 判定プロトコル v2(変更禁止)

| 基準 | 内容 |
|---|---|
| 最低取引数 | 100 |
| **補正t値** | **t / √hold** が累積検定数のBonferroni閾値以上 |
| IS/OOS | 前半60%・後半40%の**双方**プラス |
| ウォークフォワード | 各年、それ以前のデータのみで判断して採用した年の合計がプラス |
| **対ベンチマーク** | 同一銘柄・同一保有日数の**常時買い持ちを上回る** |

### 後半2基準が入った経緯(重要)

初回の拡張検定で `volregime-idx`(指数8銘柄・高ボラ局面のみロング・5日保有)が
**生t=8.03** で通過した。検証したら偽物だった:

| 構成 | n | 平均 | t |
|---|--:|--:|--:|
| 高ボラのみロング | 10,995 | 21.96bp | 8.03 |
| **常時ロング(フィルタなし)** | 29,997 | 12.71bp | **8.98** |
| 高ボラのみ**ショート** | 10,995 | −39.96bp | **−14.62** |

フィルタなしの方がtが高く、ショートでは大きく負ける。**単なる指数ロング**だった。

原因は2つ:
1. **建玉の重複** — 日次シグナル×5日保有では隣接取引が4/5重なり、独立でないのに
   独立として t を計算していた → `t/√hold` で補正(8.03 → 3.59 で棄却)
2. **方向性エクスポージャーとエッジの混同** — 上昇バイアスのある資産を買い持ちすれば
   どんなフィルタでも数字は出る → 常時買い持ち超過を必須化

**通過した仮説が出たら、報告する前に必ず潰しにかかること。**
このチェックは `attack.py` に機械化してある:

```
python3 attack.py <hypothesis-id>
```

1. 逆方向でも成立するか(ロングだけ勝つなら方向性エクスポージャー)
2. フィルタを外した対照(常時買い持ち)より本当に良いか
3. 特定の1〜2年に依存していないか(年別・最大寄与年を除いた再計算)
4. **同一日を1観測に集約したt値**(銘柄間の相関を潰す。2.5節)
5. **連続する成立日を1局面に集約したt値**(局面数・寄与の大きい局面)

4と5は `breadth-idx-washout` の検査で追加した。**4が効かない仮説は報告しない。**

## 4. 台帳のルール

`ledger.json` は**消さない。累積検定数を減らさない。**

同じ仮説を条件だけ変えて再投入すると累積が増えて必要t値が上がる。
**こっそりチェリーピックできないことが台帳の存在理由。**

各仮説の `space_size` には「その仮説にたどり着くまでに裏で何通り検討したか」を
正直に書く。銘柄数 × パラメータ通り数の実数。小さく申告すると仕組みが無意味になる。

## 5. 探索方針 — 横に広げる

同じ族のパラメータを少し変えて再投入するのではなく、
**まだ試していない仕組み・まだ試していない銘柄クラスの組み合わせ**を狙う。

実装済み24族は `README.md` の表にある。
足りなければ `families.py` に族を追加してよい。ただし:
- 決済は「翌日寄り建て → hold営業日後の寄り決済」に統一する
  (日足では経路依存を正しく評価できないため、トレーリング等は入れない)
- 判定プロトコルは変更しない

## 7. データの限界

**Yahoo Finance の日足のみ。**測れないもの:

- **日中の時刻依存** — 日足の始値はFXでは00:00 UTC、指数では現物の寄り。
  MT5の日足始値(サーバー0時)とは別物
- 実スプレッドの時間変動(ロールオーバー時間帯の拡大など)
- 業者ごとのスワップ

**定石零 環境計の中核主張(時間帯別スプレッドの割高度)は、このエンジンでは
一切検証できない。** Yahooの日足にスプレッドは入っていない。
この主張は既にユーザーが実機で裏付け済み(GBPJPY 有効143件/23時間帯、
0時台が他の時間帯の8〜10倍。`indicator/READY.md`)。
**実機のMT5実測が唯一の検証手段であり、それが正しいやり方。**

したがって **`dow-jpy-mon`(円クロス月曜)がこのエンジンで棄却されても、
販売中の「定石 壱」が否定されたわけではない。**
壱はMT5のH1実データ・サーバー時刻基準で別途検証済み(1,636取引 / PF 1.304)。

このエンジンは一次スクリーニングであり、**通過したものはMT5で再検証する**必要がある。
