## A. 起動前に直すべき不備

### A-1. `SpreadCapFor()` が SPX500 に一致せず、最大重みレッグが既定値3.0pipで判定される 【最重要】

`InpDowSpreadCaps = "US500:10.0,HK50:60.0,..."` のキーは **解決後の銘柄名**と
突き合わされる(mq5:334 `StringFind(S,k)>=0`、S=解決後シンボル)。
FN の表記は **SPX500** であり、EA自身のヘッダーにも「US500はFN表記SPX500
(ResolveSymbol別名で自動解決)」と書かれている。つまり:

```
S = "SPX500", k = "US500" → StringFind = -1 → 不一致
→ 以降のキーもすべて不一致 → return InpMaxSpreadPips = 3.0
```

`ParseDowLegs()` は解決後の名前しか保持しない(mq5:245 `g_dowSym[k]=r`)ため、
元名 "US500" は失われる。結果、**w=0.309(構成の31%)の US500 レッグだけが
意図の 10.0 pip ではなく 3.0 pip で判定される。**

pip = point×10 なので影響は桁数依存:
- SPX500 が digits=1 (point 0.1 → pip 1.0) → 実効キャップ 3.0 指数ポイント(意図より厳しい)
- SPX500 が digits=2 (point 0.01 → pip 0.1) → 実効キャップ **0.3 指数ポイント**
  → アジア時間帯(4-10 UTC)の通常スプレッドで恒常的に弾かれ、**このレッグは一度も建たない**

同じ問題は `JP225 → JPN225` に解決された場合にも起きる(キー "JP225" が
"JPN225" に部分一致しないため)。

**対処**: `InpDowSpreadCaps` に `SPX500:10.0` を追加するのが最小修正。
恒久的には `g_dowReq[]` に解決前の名前を保持し、`SpreadCapFor()` を
解決前・解決後の両方で照合させる。

### A-2. XAGUSD レッグが最小ロットに届かず、無音で消える可能性

1ショットの想定元本 = `100000 × 0.060 × 1.0 ÷ 4 = $1,500`。
銀の現値は $65/oz。契約サイズが 5,000oz なら最小ロット 0.01 = **$3,250** で、
$1,500 では届かない。`LotsForNotional()` は 0 を返し、
`if(lots<InpMinLot){ g_lastShotDow[key]=hourBar; continue; }` (mq5:591) で
**ショット枠だけ消費して発注しない** — ログにも警告が出ない。

契約 1,000oz なら $650 で通る。**FN のデモで契約サイズを確認するまで、
このレッグが機能するかは不明。** XPTUSD も 1ショット $1,800 に対し
100oz契約なら最小取引額 $1,750 とほぼ同値で、ロットは 0.01 に量子化される
(白金が $1,800 を超えた時点で建たなくなる)。

なお `MathFloor` による切り捨て(mq5:291)は常に過小方向なので、
**実効倍率は名目の mult より一貫して小さくなる**。安全側ではあるが、
研究とのパリティは崩れる。

### A-3. 「災害SL」が災害用になっていない — 接触率が5割を超え、研究と別物になる

`InpCatastropheATR = 2.5` × `iATR(PERIOD_H1, 24)`。ATR(H1,24) は
**直近24本の時間足TRの平均 = 平均"時間"レンジ**であって日次レンジではない。
時間レンジの合計は日次レンジの4〜6倍になるため、
`2.5 × ATR(H1,24) ≒ 日次レンジ × 0.5` 程度にしかならない。

日足OHLCによる近似(`verify_nonfx_config.py` [6]):

| SL距離 = 日次レンジ×0.5 | 接触率 | 12M合成 | 窓外/年 |
|---|--:|--:|--:|
| SLなし(研究セル定義) | — | +20.8% | +2.9% |
| SLあり | 42〜59% | **+12.2%** | +2.1% |

**24時間保有に対して 2〜3回に1回はSLに触る。** 研究セル(o2o、SLなし)とは
別の戦略になっており、選抜時のtスタットも合成DDもそのままでは適用できない。

対処は二択:
- SLを本当に「災害用」にする(`InpCatastropheATR` を 8〜10 に、または
  `iATR(PERIOD_D1,·)` ベースに変更)→ 研究とのパリティを回復
- 現状のSLを仕様として受け入れる → **SL込みで再スクリーニングし直す**

### A-4. `InpInitialBalance = 0.0` のまま

EA のヘッダー自身が「規約基準残高(通常100000)の明示指定を推奨」
「0=自動は現在残高を基準にしてしまい静的-10%とズレる」と書いている(mq5:28-29, 67)。
既定値がその推奨に従っていない。

`g_initBal` は静的フロアの基準であると同時に**発注サイズの基準**でもある
(mq5:590 `notional = g_initBal*w*mult/nh`)ため、ここがズレると
ガードとサイズの両方が同時にズレる。**`100000` を明示すること。**

### A-5. 日次-4%停止と-4%全決済が同値で、段階的防御が働かない

- `InpDailyStopPct = 4.0` — 新規停止。基準は `g_initBal`(mq5:523)
- `InpBalGuardPct = 4.0` — **全決済**+当日停止。基準は `max(日開始bal, 日開始eq)`(mq5:457-460)

口座が 100k 近傍にある初期は両者がほぼ同時に発火するため、
「まず新規を止め、それでも悪化したら全決済」という段階が存在せず、
いきなり全決済になる。FN の日次規約 −5% に対し −4% で一気に畳む設計。

**対処**: `InpDailyStopPct = 3.0` / `InpBalGuardPct = 4.0` に分離する。
`InpNotifyDayWarnPct = 3.0` も 2.5 程度へ。

(なお基準の取り方が2つの間で不揃いな点も要注意 — 口座が成長すると
DailyStop(initBal基準・絶対額固定)が先に、縮小すると BalGuard が先に効く。)

## B. 設定値として最適でない点

### B-1. `InpMult = 1.0` は EA自身の校正規則に反しており、フロアに届く

校正規則は「最悪日 ≥ −4% かつ maxDD ≥ −8% を満たす最大倍率 × 0.8」。
これを窓外(悲観)系列に当てると **0.68**。1.0 はどの規則からも出てこない中間値である。

| 倍率 | 窓外maxDD | フロア−8%との関係 |
|--:|--:|---|
| 0.68 | −6.34% | 余裕あり |
| **1.00(既定)** | **−9.32%** | **フロアを突破 → 恒久停止で終わる** |
| 2.92 | −27.2% | 論外 |

EA のヘッダーも「mult 1.0でも全期間DDはフロア-8%に到達し得る=停止で終わる設計」と
明記している。**資金化済み(funded)口座で、失うのが口座そのものであるなら、
自分の規則が出した 0.68 を採るのが一貫している。**

### B-2. `InpDowHoursUTC = "4,6,8,10"` が全レッグ共通 — US500 で窓が9.5時間ずれる

研究セルは「対象曜日の**寄り** → 翌営業日の**寄り**」。各銘柄の寄りは UTC で:

| 銘柄 | 寄り(UTC) | EA建玉窓 | 研究窓との重なり |
|---|---|---|--:|
| US500 (^GSPC) | 13:30 | 火 04:00 → 水 04:00 | 14.5/24h = **60%** |
| HK50 (^HSI) | 01:30 | 月 04:00 → 火 04:00 | 21.5/24h = 90% |
| JP225 (^N225) | 00:00 | 水 04:00 → 木 04:00 | 20/24h = 83% |
| XPT/XAG (CME) | 前日23:00 | 火 04:00 → 水 04:00 | 19/24h = 79% |

**最大重みの US500 が最悪**で、建玉窓の4割は前日(月曜)セルの領域にある。
`4,6,8,10` は FX の Mon レッグ(東京〜ロンドン)から引き継いだ値で、
指数レッグ用に選び直されていない。

このズレが致命的かどうかは、エッジの時間感応度で決まる。実測すると:

| 窓 | 12M合成 | 窓外/年 |
|---|--:|--:|
| o2o(研究定義) | +20.8% | +2.8% |
| c2c(数時間ずらす) | **+8.8%** | +3.1% |
| o2c(日中のみ) | +10.2% | +0.3% |
| c2o(夜間のみ) | +0.7% | +0.8% |

**窓を数時間ずらすだけで選抜窓の成績が 6割落ちる。** HK50_Mon_L に至っては
+22.0% → −3.7% と符号が反転する。選抜されたエッジは「その時刻ちょうど」に
強く依存しており、EA の建玉時刻ではそのまま再現できない。

対処: レッグ毎の建玉時刻を指定できるようにする
(`SYM:w:曜日:方向:時刻` へ拡張)。最低でも US500 は 14/16/18/20 UTC に寄せる。
それが難しければ、**研究側を EA の建玉時刻に合わせて選抜し直す**のが筋。

### B-3. XPTUSD レッグは落とすべき — 3つの理由が重なっている

1. **選抜の弱さ**: t=1.66(6セル中最弱)。単独p=0.097。上位が相関除外された
   結果として6枠目に滑り込んだだけで、それ自体は有意でない。
2. **コストに負ける**: 窓外の寄与は年 +0.150%。損益分岐スプレッドは **$0.70**。
   CFD の白金スプレッドは通常 $1.5〜$3.0 で、**恒常的に赤字**になる。
3. **データが使えない**: 元系列 `PL=F` は **O=H=L=C の退化バーが 66.7%**、
   当該Tueセルが使う518取引のうち **79%(選抜窓内でも75%)** が退化バーを含む。
   Yahoo が気配ではなく清算値1点しか返しておらず、
   **「寄り→翌寄り」を測れていない。** +32.78% という12M成績自体が信用できない。

XAGUSD も退化バー 17%(セル内28%、窓内13%)で完全に清浄ではないが、
XPT ほどではない。US500/HK50/JP225 は 0%(問題なし)。

## D. 「現状最適か」— 否

### D-1. 窓外の期待値がコストとほぼ同じ

選抜窓を除いた約9年で、同じ6セル・同じ重み・mult 1.0 を回すと:

```
選抜窓12M   合計 +20.79%   年率 +20.86%   maxDD -2.16%   最悪日 -0.84%   t=5.05
窓外 約9年   合計 +25.92%   年率  +2.88%   maxDD -9.32%   最悪日 -1.47%   t=2.15
```

各レッグの「10年累計に占める選抜窓12ヶ月の比率」は 27〜64%(中央値 ≈ 51%)。
**10年分の累積の半分が、選抜に使った直近1年から出ている** — 窓で選んだ結果であり、
持続的エッジの形ではない。

窓外年率 **+2.88%** に対し、往復スプレッドだけの概算コスト(年52往復):

| レッグ | 窓外寄与/年 | 損益分岐スプレッド | 典型的なCFDスプレッド | 判定 |
|---|--:|--:|---|---|
| US500_Tue_L | +0.485% | 2.35 pt | 0.4〜1.5 pt | 通る |
| HK50_Mon_L | +0.700% | 16.2 pt | 15〜30 pt | **際どい〜負け** |
| HK50_Thu_S | +0.974% | 22.5 pt | 15〜30 pt | 際どい |
| JP225_Wed_L | +0.178% | 16.8 pt | 8〜20 pt | 際どい |
| XPTUSD_Tue_L | +0.150% | **0.70 $** | 1.5〜3.0 $ | **負け** |
| XAGUSD_Tue_L | +0.398% | 0.08 $ | 0.02〜0.04 $ | 通る |

さらに指数CFDの**オーバーナイト金利が毎回1泊分**発生する(o2o のため必ず1泊する)。
概算で年 0.6〜0.8% 相当。

**合計すると、窓外ベースでは執行コストが期待値を食い切る水準にある。**
デモ実測のスプレッドを上表の損益分岐値と突き合わせるのが、配備可否の最短の判断材料。

### D-2. 多重検定を通すと、最上位セル以外は雑音の範囲

DOW族の検定数は 140(14銘柄×5曜日×2方向)。帰無仮説下での最大|t|期待値は **2.69**。

| レッグ | t | 素p | 期待偽陽性件数 | Bonferroni p |
|---|--:|--:|--:|--:|
| HK50_Mon_L | 3.57 | 0.0004 | 0.05 | **0.050** |
| XAGUSD_Tue_L | 2.56 | 0.0105 | 1.47 | 1.000 |
| US500_Tue_L | 2.47 | 0.0135 | 1.89 | 1.000 |
| JP225_Wed_L | 2.02 | 0.0434 | 6.07 | 1.000 |
| HK50_Thu_S | 1.93 | 0.0536 | 7.50 | 1.000 |
| XPTUSD_Tue_L | 1.66 | 0.0969 | 13.57 | 1.000 |

**補正後に生き残るのは HK50_Mon_L 1本のみ**(それも p=0.05 ちょうど)。
残り5本、重みにして 0.79 は統計的裏付けを持たない。
docs/174 流の「EVベット」として承知の上なら成立するが、
`nonfx_screen_results.md` が総検定数を 560 と過大に書いていた点も含め、
規模の記録は正確にしておくべき。

### D-3. 相関フィルタは DOW セル同士にはほぼ効かない

`corr()` は日付の和集合をとり欠損日を 0 で埋める(nonfx_screen.py:255-266)。
DOW セルは週1日しか非ゼロを持たないため:

- **曜日が異なるセル同士は、構造的に必ず ρ≈0** になる。
  US500火L と HK50月L の ρ=0.00 は「独立」ではなく「重ならない」の意味しかない。
- 日次系列である現行 Hold レッグとの相関も約 1/√5 に希釈される。
  真の ρ=0.8 でも実測 ≈0.36 で、閾値 0.4 を通過してしまう。
  ユニバースに残した **UKOIL(Brent)** が選抜されていたら、
  #14166201 の Hold WTI とほぼ同一の建玉になっていた(今回は選抜されず助かっただけ)。

実際に効いた除外は同一曜日ペアのみで、ログ上も
`DOW_NAS100_Tue_L` / `DOW_US30_Tue_L` の2件だけである。
**「現行ブック10レッグと|ρ|≤0.23 → 分散追加として機能する見込み」という
md の結論は、この方法では支持されない。**

方向性で見ると: LONG 側 w=0.790 / SHORT 側 w=0.209、
株価指数のネットロング ≈ 0.449 + 貴金属 0.132。実質は**曜日タイミング付きの
指数ロングブック**であり、分散資産ではない。

### D-4. 2ヶ月枠での期待値が薄い

有効期限は 2026-10-15 = 約9週間。1レッグ週1回で総取引数は 50〜55 程度。

| 前提 | mult 1.0 の2ヶ月期待 | 対する下振れ |
|---|--:|---|
| 選抜窓が続く | +3.5% | |
| 窓外並み(コスト前) | +0.5% | maxDD −9.3%(フロア−8%で恒久停止) |
| 窓外・コスト後 | ≈ 0〜−1% | 同上 |

mult 0.68 なら下振れは −6.3% に収まるが、上振れも +2.4% / +0.3% に縮む。
**資金化口座に対して、この非対称性は割に合わない。**
