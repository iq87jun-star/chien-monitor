# Stellar EA (MT5 / MQL5)

レジーム適応型のマルチ戦略 Expert Advisor。**FundedNext 等のプロップファーム・チャレンジ**を想定した、ドローダウン厳守のリスク管理を組み込んでいます。

> ⚠️ **免責**: いかなる EA も「勝てる優位性」を保証できません。過去のバックテスト成績は将来の利益を保証しません。必ずデモ口座でフォワードテストしてから使用してください。本コードは教育・検証目的の出発点です。

---

## 「優位性」の設計思想

魔法の指標に頼るのではなく、リテール自動売買で現実的に効きやすい3点に置いています。

1. **相場環境（レジーム）への適応** — 単一戦略を全相場に当てるのではなく、今の地合いに合った戦略を選ぶ
   - **TREND**（`ADX ≥ InpAdxTrendLevel`）: 上位足 EMA バイアス方向への **押し目・戻り順張り**
   - **RANGE**（`ADX < InpAdxRangeLevel`）: **ボリンジャーバンド + RSI の逆張り**
   - **NEUTRAL**（両者の中間）: 見送り（無理に張らない）
2. **プロップ厳守のリスク管理** — チャレンジ突破は「破産しないこと」が最優先
   - 日次損失リミット / 最大ドローダウンの自動ガード（到達で自動停止・全決済）
   - 損失額が一定になる **%リスク・ロット計算**（SL 距離と tick value から逆算 → 銘柄非依存）
3. **悪条件の回避** — スプレッド上限・取引時間帯フィルター・1バー1判定でノイズとコストを抑制

---

## 取引ロジック

- 判定は**確定足（1本前のバー）**で行い、ヒゲによるダマシ・リペイントを回避。
- ポジション管理（ブレイクイーブン / ATR トレーリング）は毎ティック実行。

| 状態 | 条件 | エントリー |
|------|------|-----------|
| TREND ロング | `Close[1] > HTF_EMA` かつ `FastEMA > SlowEMA`、押し目（`Low[1] ≤ PullEMA` かつ `Close[1] > PullEMA`） | 買い |
| TREND ショート | `Close[1] < HTF_EMA` かつ `FastEMA < SlowEMA`、戻り（`High[1] ≥ PullEMA` かつ `Close[1] < PullEMA`） | 売り |
| RANGE ロング | `Close[1] ≤ 下バンド` かつ `RSI < 売られすぎ` | 買い |
| RANGE ショート | `Close[1] ≥ 上バンド` かつ `RSI > 買われすぎ` | 売り |

- **SL** = `ATR × InpSlAtrMult`、**TP** = `SL距離 × RR`（トレンド/レンジで別々の RR）。
- **ブレイクイーブン**: 含み益が `ATR × InpBeTriggerAtr` に達したら建値＋ロックへ。
- **トレーリング**: `ATR × InpTrailAtrMult` で利益方向のみ追従。

## インストール

1. MetaTrader 5 を起動 → メニュー **ツール → MetaQuotes言語エディタ**（MetaEditor）を開く。
2. `StellarEA.mq5` を `MQL5/Experts/` 配下にコピー（MetaEditor のナビゲータに表示）。
3. ファイルを開き **F7（コンパイル）**。エラー 0 を確認。
4. MT5 のナビゲータ → エキスパートアドバイザ → `StellarEA` をチャートにドラッグ。
5. **自動売買を許可**（チャート設定 & ツールバーの「アルゴ取引」ON）。

## バックテスト（ストラテジーテスター）

1. MT5 → **表示 → ストラテジーテスター**。
2. エキスパート = `StellarEA`、銘柄・期間を選択。
3. モデルは **「全ティック」**（ティックベース）を推奨。
4. まず**少なくとも1〜2年**で挙動を確認し、その後アウトオブサンプル期間で再検証。
5. 過剰最適化（カーブフィット）に注意。パラメータは少数だけ動かす。

## 主要パラメータ

| 入力 | 既定 | 説明 |
|------|------|------|
| `InpTradeTF` / `InpHtfTF` | M15 / H4 | 執行足 / 上位バイアス足 |
| `InpAdxTrendLevel` / `InpAdxRangeLevel` | 25 / 20 | レジーム判定の閾値（間は見送り） |
| `InpSlAtrMult` | 2.0 | SL の ATR 倍率 |
| `InpTrendRR` / `InpRangeRR` | 2.0 / 1.2 | リワード:リスク |
| `InpRiskPercent` | 0.75 | 1トレードのリスク（%・エクイティ） |
| `InpInitialBalance` | 0（自動） | 最大DD計算の基準残高 |
| `InpDailyLossPct` | 4.0 | 日次損失リミット（%・日初エクイティ） |
| `InpMaxDrawdownPct` | 8.0 | 最大DD（%・初期残高）到達で永久停止 |
| `InpMaxPositions` / `InpMaxTradesPerDay` | 1 / 6 | 同時保有数 / 日次トレード上限 |
| `InpMaxSpreadPoints` | 50 | スプレッド上限（0で無効） |
| `InpUseSessionFilter` 他 | ON 7–20時 | 取引時間帯（サーバー時間） |
| `InpUseNewsFilter` | ON | ニュース回避フィルター |
| `InpNewsMinImp` | High | 回避する最小重要度（Low/Moderate/High） |
| `InpNewsMinBefore` / `InpNewsMinAfter` | 15 / 15 | 指標の前後何分エントリー停止するか |
| `InpNewsManualList` | "" | バックテスト用の手動指標日時 |
| `InpPrintAnalysis` | ON | 終了時に時間帯/曜日別成績を出力 |
| `InpAnalysisToCSV` | OFF | CSVにも書き出す |

## ニュース回避フィルター

重要な経済指標の発表前後は値が荒れ、スプレッドも拡大しやすいため、その時間帯のエントリーを停止します。

- **ライブ/デモ（MT5内蔵カレンダー）** — `InpNewsUseCalendar = true`。EA は対象銘柄の**通貨（base / profit）**に関連する指標を MT5 の経済指標カレンダーから取得し、`InpNewsMinImp` 以上の重要度のイベントの **前 `InpNewsMinBefore` 分 〜 後 `InpNewsMinAfter` 分**はエントリーを見送ります。
  - ターミナルの設定でカレンダーが有効である必要があります（ツール → オプション → サーバー / コミュニティ）。
- **バックテスト（手動リスト）** — ⚠️ **ストラテジーテスターでは内蔵カレンダーが取得できません**（常に空を返す）。検証時に指標回避を再現したい場合は、`InpNewsManualList` に日時をセミコロン区切りで入力します。

  ```
  2026.06.06 12:30; 2026.06.06 21:00; 2026.06.10 14:00
  ```
  （サーバー時間で `YYYY.MM.DD HH:MM`。各日時の前後 `Before/After` 分を停止）

> 注意: カレンダーの国・通貨コードはブローカー/地域設定に依存します。意図通り止まっているか、ログ（`StellarEA: ...`）で確認してください。

## 曜日・時間帯別の成績分析

EA を**チャートから外したとき**、または**ストラテジーテスト終了時**に、その銘柄＋マジック番号の約定履歴を集計して「エキスパート」ログへ出力します（`InpPrintAnalysis = true`）。

- **エントリー時刻**を基準に、**曜日別**と**時間帯（0–23時, サーバー時間）別**で、**トレード数 / 勝率 / 純損益**を表示。
- 損益は `利益 + スワップ + 手数料` の合算（建値側に手数料が計上される口座では概算になります）。
- `InpAnalysisToCSV = true` で、`MQL5/Files/StellarEA_stats_<銘柄>_<マジック>.csv` にも書き出します（Excel 等で分析可能）。

出力例（ログ）:

```
===== StellarEA Performance Analysis =====
Symbol=EURUSD  Magic=870124  Trades=142  NetP/L=1830.50 USD
--- By day of week ---
Day | Trades |  Win% |     Net P/L
Mon |     28 |  53.6 |      420.10
Tue |     31 |  48.4 |      -85.30
...
--- By hour of day (entry, server time) ---
Hr | Trades |  Win% |     Net P/L
08 |     19 |  57.9 |      610.40
13 |     22 |  40.9 |     -240.10
...
```

**使い方のヒント**: 勝率・損益が一貫して悪い曜日/時間帯が見つかれば、`InpSessionStartHour/EndHour` を絞る、あるいは将来的に曜日フィルターを足す判断材料になります（カーブフィットには注意）。

### FundedNext 想定のチューニング指針

- 既定の `DailyLoss 4% / MaxDD 8%` は、よくある **日次5% / 最大10%** に対して**バッファを取った保守設定**です。
- お使いのプランの正確な規則（日次・最大DDの%、トレーリング方式か静的か、整合性ルール）に合わせて値を調整してください。
- 規則は変わり得ます。導入前に必ず最新の公式規約をご確認ください。

## 注意・既知の制約

- ニュース回避フィルターはライブで内蔵カレンダーを使用。**バックテストではカレンダー不可**のため `InpNewsManualList` で代替（上記参照）。
- ヘッジ/ネッティングは口座設定に依存。ネッティング口座では同銘柄の同時両建ては合算されます（既定 `MaxPositions=1` 推奨）。
- ブローカーの最小ロット・ストップレベル・フィリングモードにより、極小口座では「リスク額がminロット未満」で見送りになる場合があります（過剰リスク回避のため意図的）。
