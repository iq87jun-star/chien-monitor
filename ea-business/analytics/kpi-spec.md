# Phase 4 — 計測・KPI設計

> 販売開始後のデータが前提。ここでは「何を・どこで・どう見るか」を定義。

## 見るべきKPI
| 段階 | 指標 | 取得元 | 目安/用途 |
|---|---|---|---|
| 集客 | LP流入数 / 流入元 | LP解析（Plausible/GA4） | チャネル別の効き |
| 集客 | 記事→LPのCTR | 解析 | コンテンツの導線評価 |
| 転換 | LP→購入 CVR | LP解析＋決済 | LP/価格の改善対象 |
| 売上 | 販売数 / 売上 / 返金率 | MQL5 / Gumroad / Stripe | 主力指標 |
| 売上 | チャネル別手取り | 手数料控除後 | Market20% vs 自前13% |
| 製品 | ライセンス有効化数 / 失敗率 | `issued-keys.log` / verifyログ | サポート負荷の先行指標 |
| サポート | 問い合わせ数 / 種別 | サポート受信 | FAQ自動化の効果 |
| 評価 | MQL5レビュー数・星 | MQL5 Market | 検索順位・信頼 |

## データソースと取り込み
- 決済：Gumroad/Stripe のCSVエクスポート → `analytics/sales/*.csv`
- 発行：`licensing/issued-keys.log`
- LP：解析ツール（クッキーレスのPlausible推奨：開示が簡便）

## 改善ループ（月次）
1. 売上・CVR・返金率・レビューを集計（`analyze_sales.py`）。
2. ボトルネック特定（流入�‐CVR↓ ならLP/価格、流入↓ なら集客）。
3. 仮説を1つだけA/B（LP見出し or 価格 or コピー）。
4. 2週間で評価 → 採否。

## A/B候補（初期）
- LP見出し（機能訴求 vs 時短訴求）
- 価格 $49 vs $39（買い切り）
- CTA文言（「購入する」 vs 「デモで試す→購入」）

## コンプラ
- 成績の断定・利益予測はKPIにも資料にも載せない（社内分析のみ）。
- 顧客データは最小限・安全に扱う（メール等はログに平文で長期保持しない）。
