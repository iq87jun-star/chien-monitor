# 業務の部品づくり(1つの計算 → 複数の売り場)

事務・経理・人事の担当者が毎回手でやっている「決まった処理」を、ふだん使っている道具(Excel・スプレッドシート・
kintone・自動化ツール)の中で1回で済ませられる**部品**にして売る。

**計算の本体は `calc-api/src/` に1つだけ書き**、売り場ごとに薄い包みを付けて出す。拡張の自動づくり
([extension-factory](../extension-factory/README.md))の「1つの案から複数の商品」を、ブラウザ拡張を伴わない計算にも広げたもの。

```
calc-api/src/*.js(計算の本体・テスト)
   ├─ 計算API(RapidAPI)                    calc-api/       … 公開済みの仕組みあり
   ├─ Google スプレッドシートの JP_ 関数        sheets-addon/   … 公開準備中
   ├─ Excel の JP. 関数(AppSource)          excel-addin/    … 作成済み・公開準備中
   ├─ kintone プラグイン                     (予定)
   └─ n8n・Zapier・Make の連携部品            (予定。計算API の入口)
```

進み具合と次の案は [ledger.md](ledger.md)。

## 決まり

- **日本だけの処理に絞る**: 祝日・和暦・社会保険・源泉徴収・全銀フォーマット・住所・カナなど。海外の業者が作らないもの
- **決まった規則で答えが出るものだけ**: 計算・変換・検査。文章を生成するもの、情報を集めて転載するものは作らない
- **入力を外部に送らない**: Excel・スプレッドシート・kintone の中で計算を完結させる(審査が軽く、会社でも入れてもらいやすい)。
  外部の API が要る処理(例: 国税庁のインボイス照会)は、検査数字のチェックのように外部と通信しない形にできる部分だけ作る
- **公的で再配布自由なデータだけ使う**: 内閣府の祝日、協会けんぽの料率、日本郵便の郵便番号データなど
- **関数の名前は公開後に変えない**: 変えると利用者のブックやシートが壊れる。足すのは自由
- **毎年の更新を止めない**: 率・税制の更新は [calc-api/README.md の「毎年の更新」](../calc-api/README.md)。
  1か所直せば全部の売り場に入る
- **量より質**: 似た部品を大量に出さない(ストアのスパムの規定に触れる)。新しい部品は**30日で3つまで**

## 新しい部品を足す手順(作成係)

1. `ledger.md` の「次の案」から、持ち主が選んだものを1つ取る
2. **計算の本体**: `calc-api/src/` に純粋関数を書き、`calc-api/test/` に実際の表記を使ったテストを足す
   (例: 全銀フォーマットなら、銀行の仕様書にある例の行と1文字ずつ一致すること)
3. **計算API**: `worker.js` の `ROUTES`・`openapi.json`・`listing/marketplace.md`(新しい出品名の時だけ)
4. **スプレッドシート**: `sheets-addon/src/lib-entry.js` と `functions.js` に `JP_<名前>`、テスト・`Help.html`・`listing/store.md`
5. **Excel**: `excel-addin/src/functions.js` の `FUNCTIONS` に `<名前>` を1つ足す、テスト・`listing/store.md`
6. 各フォルダの `npm test` を通し、PR を作って CI がすべて緑になったらマージする
7. `ledger.md` の部品の表に1行足す

公開について:
- 計算API・Excel はマージで自動的に届く(Excel はマージで `toreca-auto-update` が自動で走って配信)
- スプレッドシートは、Marketplace に公開済みなら人が Apps Script で新しい版を作る

## これからの順番

| 順 | やること | 状態 |
|---|---|---|
| 1 | Excel 版の JP 関数(当初の17関数) | 作成済み(`excel-addin/`)。人の作業は [excel-addin/README.md の公開手順](../excel-addin/README.md#公開手順) |
| 2 | 経理の部品: 支払日・源泉徴収・登録番号の検査(作成済み)→ 全銀フォーマット | 途中 |
| 3 | kintone プラグイン(`kintone-plugin/`)。まず支払日・営業日・和暦の自動入力 | 2 の後 |
| 4 | n8n のノード(npm で公開)・Zapier・Make の連携部品。中身は計算API を呼ぶだけ | 計算API の出品が済んでから |
| 5 | 有料化: 経理の部品を有料の関数にし、ライセンスキーを全売り場で共通にする(`notify/` の Stripe 連携を流用) | 利用者と評価がついてから |

## 人がすること

- 各売り場の最初の登録(Partner Center・Google Cloud・kintone の開発者・npm)と、審査への提出
- `ledger.md` の「次の案」で、作ってほしいものに印を付ける
- 止めたい時は、この README の先頭に「停止中」と書く
